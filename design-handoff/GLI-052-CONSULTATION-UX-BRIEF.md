# Claude Design 작업지시: GLI-052 자연스러운 AI 상담 흐름

작성: 2026-09-18 / Codex PM. **A1 착수 및 A4 상담 UX 범위 승인. A2·A3 정책은 아키텍처 논의 후 결정**.

갱신: 같은 날 BuildBlock 실제 상담 벤치마크 후 사용자 "핸드오프 만들고, 네가 해야할 AI 상담 강화 계속해" 승인. 아래 B1~B5가 이번 추가 작업지시다. 기존 D1~D5는 유지하며, 충돌하면 새 B 항목을 우선한다. **이 문서는 디자인 제작 지시이며, 시안의 시각 결과와 신규 문구에 대한 최종 승인은 아니다.**

전체 분업과 승인표: [GLI-052 작업지시서](../docs/implementation/GLI-052-AI-CONSULTATION-WORK-ORDER.md). 최신 사용자 지시에 따라 [상담 아키텍처 검토안](../docs/implementation/GLI-052-CONVERSATIONAL-ARCHITECTURE.md)을 먼저 고려한다. 고정 추천 범위·최대 3개 후보·예산 선질문은 미승인이다. A4 범위는 승인됐지만 실제 시각안과 새 문구는 승인 전이다.

## 목적

사용자가 투자 조건을 자연스럽게 말하고, AI 답변을 읽고, 후보를 확인하고, 같은 맥락에서 다음 질문을 할 수 있도록 상담 흐름을 개선한다. 랜딩/소개/멤버십/뉴스를 다시 디자인하는 작업은 아니다.

기준은 전달 시점의 최신 승인 `source/gli-demo.dc.html` 및 관련 CSS/JS다. 과거 ZIP 전체를 덮어쓰지 않는다. 새 시안은 별도 작업본으로 제공하며 현재 승인본을 교체하지 않는다.

## 사용자와 합의해야 하는 범위

| 승인 ID | 권고 방향 | 승인 전 처리 |
|---|---|---|
| A2 | 맥락에 따라 추천 범위를 판단하는 구조 검토 | 고정 제외/포함 정책은 보류 |
| A3 | 설명/질문/조회/비교의 동적 상담 구조 검토 | 항상 3개 또는 예산 필수 입력을 고정하지 않음 |
| A4 | 답변 아래 입력창+후보별 상담+답변/결과 연결 | 범위 승인 완료, 실제 시각안/문구 별도 승인 |

후보 수는 미확정이며 전체 결과를 삭제하거나 상한을 3개로 줄이지 않는다. 자산의 실제 정보와 정확한 후보 수는 Codex API가 제공한다. 설명만 있는 답변, 질문이 필요한 답변, 후보 비교 등 여러 상담 상태를 수용하되 사용자가 고정 설문을 진행하는 느낌이 들지 않도록 제안한다.

## 현재 확인된 UX 결함

1. 현재 순서는 안내 → 후속 입력창 → 내 질문 → AI 답변이다. 마지막 질문을 읽고 위로 돌아가 입력해야 한다.
2. 상담 결과와 매물 목록이 분리되어 답변이 가리키는 후보를 사용자가 다시 찾아야 한다.
3. 예산 안에서 19개, 결과 18건, 전체 20건의 범위가 불명확하다.
4. 투자자에게 필요한 매입가·임대수입 근거·추천 이유가 연결되지 않는다.

동일 ID의 매매 데이터와 임대 시안 카드 충돌은 Codex가 고칠 데이터 연결 결함이다. Claude가 가격·거래유형을 수동으로 바꿔 숨기지 않는다. 사용자가 승인한 데모 데이터와 외부 수집 데이터를 혼동하지 않는다.

## D1. 대화 배치

- 기본 제안 순서는 대화 이력 → 최신 답변/확인 질문 → 후속 입력창이다. 마지막 답변과 입력창이 인접해야 한다.
- 신규 탐색과 이어서 상담의 목적을 구분한다. 상단 최초 입력 영역이 후속 입력을 대체하거나 대화 맥락을 지우지 않도록 한다.
- 최초 탐색 이후 상단 히어로를 줄이거나 접는 안이 필요하면 별도 옵션으로 제안한다. 임의로 삭제·축소하거나 랜딩 기능을 복제하지 않는다.
- 사용자가 과거 내용을 읽는 동안 강제 스크롤로 최신 메시지로 끌고 가지 않는다. 새 답변 도착·전송·복귀 시 초점/스크롤 규칙을 납품 문서에 적는다.
- 화면 고정 입력창, 별도 채팅 사이드바, 신규 팝업은 기본 요구사항이 아니다. 필요하면 장단점을 제시하고 따로 승인받는다.

## D2. 답변과 후보 연결

- 답변에서 관련 후보를 이해하고 전체 결과로 이동할 수 있게 한다. A3의 고정 후보 수는 미승인이므로 임의로 3개로 제한하지 않는다. 같은 카드 전체를 여러 영역에 반복해 페이지를 불필요하게 늘리지 않는다.
- 후보를 지정해서 이어 묻는 동작을 설계한다. 선택 대상과 선택 해제를 보여주되 질문 전송을 자동으로 실행하지 않는다.
- 특정 물건에 대한 상담은 이름이나 카드 순번이 아닌 Codex가 제공한 안정 assetId로 연결한다.
- 매입 후보, 임대 비교 근거, 사업 참여 기회를 같은 가격으로 비교하는 화면을 만들지 않는다. 임대 호가를 매입자의 확정 수입으로 표시하지 않는다.
- 새로운 액션 문구(예: "이 자산에 대해 묻기")는 납품 시 미승인 문구 목록에 넣는다. 예시는 최종 승인 카피가 아니다.

## D3. 정보 계층

- 현재 조건 요약, 후보로 나온 이유, 중요한 미확인 항목을 필요한 위치에 둔다. 모든 카드에 긴 경고를 반복하지 않는다.
- 원통화 가격과 기존 환산 표기, 공개 Trust 등급, 출처명/원문 링크 정책을 유지한다. Trust를 임대수익률처럼 보이게 하지 않는다.
- 없는 GLI 폼 정보는 "조사 예정"을 유지한다. 내부 운영 시점·모델 공급사·진단 오류를 고객 화면에 노출하지 않는다.
- 후보 건수는 Codex의 resultSet에서 받는다. 플랫폼 전체 등록 수와 검색 응답 수를 별도로 구분하며 전체 시장 수를 추정하지 않는다.
- 결과가 바뀌었을 때만 기존 승인 정책의 변경 안내를 사용한다. 바뀌지 않았는데 갱신·추가 후보를 발견한 것처럼 표시하지 않는다.

## D4. 상태와 이벤트

| 상태 | 필요한 화면/동작 |
|---|---|
| 첫 질문 전 | 첫 입력의 목적과 전송 상태 |
| 검색 진행 | 입력 보존, 중복 전송 방지, 읽을 수 있는 진행 상태 |
| 답변 완료 | 최신 답변 다음에 입력창, 연결된 후보와 일관된 개수 |
| 후보 없음 | 질문/조건 보존, 데이터 미연결과 조건 불일치에 맞는 메시지 영역 |
| 일부 출처 미완료 | 확보된 후보와 제한된 탐색 범위를 표현할 공간. 문구는 승인 필요 |
| 실패·재시도 | 입력 보존, 재시도 액션, 공급사/원시 오류 노출 없음 |
| 후속 질문으로 결과 변경 | 새 결과 이동 연결, 답변과 결과의 동일 resultSet 유지 |
| 특정 후보 상담 | 선택 자산 식별과 해제, 일반 질문으로 복귀 |
| 상세에서 복귀 | 직전 대화·조건·후보·적절한 스크롤 복원 |

진행 안내에 실제로 수행되지 않은 근거 검증 완료 체크를 넣지 않는다. QA 상태 전환 버튼은 별도 검수 파일에서만 제공하며 공개 산출물에 넣지 않는다.

## D5. 모바일과 접근성

- 320/360/390/412px 및 768/1440px를 검수한다. 기존 0916 모바일 승인 개선을 보존한다.
- 키보드가 열린 상태에서 마지막 질문, 입력 내용, 전송 버튼을 확인할 수 있어야 한다. 안전 영역, 세로 높이가 낮은 기기, 화면 확대를 고려한다.
- 10턴 이상의 대화와 긴 자산명·가격 범위·다국어를 포함한다. 고정 높이 때문에 입력이나 답변을 잘라내지 않는다.
- 명확한 입력 레이블·키보드 초점·읽기 순서·전송 상태를 제공한다. 상태 읽어주기가 전체 대화를 반복 낭독하지 않게 한다.
- 향후 iOS·Android 앱에서도 같은 상담/API를 쓸 전제를 유지한다. 이번 시안에 앱 전용 푸시·결제 기능을 추가하지 않는다.

## 납품물과 금지 범위

1. 최신 승인본 대비 변경 파일/영역 목록과 의도. 원본 기준 파일 또는 해시를 함께 명시한다.
2. 변경된 HTML/CSS/JS와 필요한 자산만 제공한다. 완성 시안을 별도로 제공해도 병합 기준은 변경 목록이다.
3. 상태/이벤트 대응표와 예제 데이터. 예제 값은 디자인 검수용임을 문서에 명시하고 실제 API 결과인 것처럼 배포하지 않는다.
4. 새 문구·신규 UI·기존 화면에서 달라진 부분을 승인 목록으로 정리한다. 관련 없는 개선은 제안으로만 분리한다.
5. 폭별 캡처와 정상/실패/긴 대화/키보드 상태 검수 결과. 실제 기기 미시험은 명시한다.
6. Codex가 승인된 변경만 React에 통합한 뒤 사용자에게 원본 시안과 비교 결과를 제출한다.

브랜드, 폰트, 색상, 메뉴, 다른 페이지, 자산 원문 데이터, 등급 정책, 멤버십/Cash 정책, 뉴스 내용, 실제 AI SDK/키는 변경하지 않는다. 기존 시안용 support.js나 window.claude.complete를 실제 서비스 호출 경로로 가져오지 않는다. 불가피한 변경은 사용자에게 먼저 보고한다.

## B2. Claude Design의 이번 제작 범위

1. **P0 후속 입력 동선:** 최신 답변 아래에서 바로 이어 묻기. 긴 대화 중 과거 답변을 읽는 사람에게 강제 이동하지 않기. 데스크톱에서 입력창을 계속 노출하는 방법을 제안하되, 별도 고정 패널을 확정한 것으로 해석하지 않는다.
2. **P0 후보 연결:** 카드의 자산 질문 동작은 선택 대상 표시 후 기존 AI 대화 입력으로 연결한다. 자동 전송하지 않는다. AI 질문과 전문가 상담은 이름·위치·동작을 분명히 구분한다. 상세 왕복 시 질문·선택·목록 순서 보존.
3. **P1 현재 조건:** 국가/도시, 매입 또는 거주 임대, 예산, 목적, 목표 월수입을 구분한다. 총예산과 월수입을 하나의 금액 칩으로 합치지 않는다. 미정 조건은 AI가 결정한 것처럼 채우지 않는다. 새 편집 조작은 제안/승인 대상으로 분리.
4. **P1 대화와 목록 관계:** 기존 후보에 대한 질문은 후보 목록을 그대로 두고 관련 후보로 이동 가능하게 한다. 새 검색 결과가 도착했을 때만 목록 변경을 알린다. 서로 다른 전체 수/반환 수/관련 후보 수를 섞지 않는다.
5. **P0 모바일:** 대화/결과 간 빠른 이동과 돌아왔을 때 위치 복원. 입력창이 키보드·하단 안전 영역에 가려지지 않는 안. 탭/고정 전환 컨트롤 등 새 구성은 시안에서 비교 제안하고 사용자 승인 후 확정한다. 가로 스크롤 카드만을 유일한 후보 접근 방식으로 강제하지 않는다.

답변의 문단 개행과 원문 출처 이동도 함께 설계한다. 현재 로컬 화면은 긴 답변을 한 덩어리로 표시하고 본문의 URL도 일반 텍스트로 보인다. Codex는 이번에 이를 임의 스타일 변경으로 고치지 않는다. Claude가 기존 승인 서체/색상 안에서 문단과 클릭 가능한 서버 출처 링크의 시안을 제안한다. 모델이 작성한 HTML/임의 URL을 그대로 렌더링하지 않는다.

브랜드·서체·컬러·카드 외형 및 랜딩/뉴스/멤버십/소개는 기존 승인 그대로다. 초기 랜딩에 상담 페이지 전체를 복제하지 않는다. 데모의 전문가 연결을 실제 접수/발송 성공으로 꾸미지 않는다.

## B3. Codex 백엔드와의 경계

| 항목 | Codex 책임 | Claude 디자인 책임 |
|---|---|---|
| 상담 조건 | 누적 조건 검증, 투자자/임차인·총예산/월수입 분리 | 제공된 조건의 배치와 미정 상태 |
| 이전 후보 | 공개 자산 ID 재조회, 순번→정확한 ID, 자료 소실 시 확인 요청 | 선택/해제/상세 복귀 및 관련 카드 이동 |
| 비교/설명 | 이전 후보 비교 중 새 수집·대체·자동 재정렬하지 않음 | 목록 유지와 새 결과 변경의 시각적 구분 |
| 근거 | 서버 자산 사실, 원문 URL, 중요 확인 항목 제공 | 답변/출처 연결을 읽기 쉽게 표현 |
| 순수익 | 같은 호실 계약·비용 근거 없으면 계산 확정하지 않음 | 자료 없는 숫자·가상 수익률 생성 금지 |
| 권한/호출 | OpenRouter 상담, Gemini 별도 수집, 키·권한·비용 서버 처리 | 실제 SDK·키·window.claude.complete 연동 금지 |

이번 로컬 API 계약: 기존 `POST /api/search`에 `previousAssetIds`(이전 화면 순서, 최대 18개)와 선택적 `selectedAssetIds`(그 목록의 부분집합). 제목/가격/요약을 클라이언트가 권위 있는 자료로 보내지 않는다. 응답 `resultSet.assetIds/returnedCount`, `consultation.mode=search|review|clarify`, `referencedAssetIds`, `missingAssetIds`를 제공한다. `citations`는 서버 원문이 있을 때 `sourceName/url`을 포함한다. 이 계약은 단일 JSON 완료 응답이며 실시간 단계 이벤트가 아니다.

현재 연결된 것은 기존 후속 입력의 `previousAssetIds` 전송이다. **선택 칩·카드 질문 버튼·조건 칩·모바일 전환 UI는 아직 없다.** `selectedAssetIds` 이벤트 연결은 승인 시안 통합 때 Codex가 한다. 현재 정적 시안 카드와 서버 자산의 일부 필드 불일치는 별도 C1 미완 항목이다. Claude가 시안 숫자를 바꿔 해결한 것으로 처리하지 않는다.

## B4. 필수 검수 시나리오

- 프놈펜 1억원 투자 검색 → "목표 월세 100만원" → "부대비용 포함 총예산 1억2천만원": 장소/목적 보존, 두 금액을 구분해 표시.
- 후보 3건 → "두 번째 물건의 리스크는?": 실제 화면 두 번째 ID에 연결, 새 검색/다른 후보 삽입 없음.
- "아까 두 후보만 순수익 기준으로 비교해줘": 후보/기존 가격 보존, 월세 근거·비용 미확인 상태 수용. XXX·가상 수익률 금지.
- 선택 대상 자료를 다시 찾지 못함: 다른 후보를 대신 보여주지 않고 대상 확인 흐름으로 연결.
- 자산 AI 질문과 전문가 상담을 각각 실행: 서로 다른 목적이 명확하며, 실제 접수 없는 완료 메시지 없음.
- 10턴 대화·320/360/390/412px·200% 글자 확대·키보드 표시·상세 왕복·재시도: 입력/전송 접근성 및 맥락 보존. 실기기 미시험은 명시.

## B5. 납품 및 승인 체크리스트

납품은 이 지시서 하나를 진입점으로 하고, 변경된 파일/영역·기존 승인본 해시·HTML/CSS/JS 패치·상태별 캡처·모바일 검수 결과·이벤트 매핑을 함께 제공한다. 검수용 버튼은 별도 파일만 사용한다. 원본 전체 덮어쓰기나 디자인 외 기능 확장은 하지 않는다.

사용자 별도 승인 대상: (1) 데스크톱 대화/결과 배치와 고정 입력 방식, (2) 모바일 전환 방식, (3) 자산 질문/전문가 상담/조건 편집의 신규 문구와 조작, (4) 최종 시안 React 통합, (5) 공개 배포. Codex가 이 승인 전 시각 변경을 선행하지 않는다.
