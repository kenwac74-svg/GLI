# DATA MODEL — 2026-08-26

목업의 하드코딩 데이터를 실제 스키마로 옮기기 위한 기준. 필드명은 목업의 것을 그대로 썼다. 물리 설계는 GPT 재량이나 **의미와 노출 방침은 유지**해야 한다.

---

## 1. 자산 분류

```
부동산 ─ 주거용 · 상업용 · 레저 · 프로젝트
```

`cat` 필드에 위 넷 중 하나. 목업의 값은 `"주거용" | "상업용" | "레저" | "프로젝트"`다.

**분류 기준은 소재가 아니라 행위다.**

- 부동산을 사는 것이면 주거용·상업용·레저. 선분양이라 아직 건물이 없어도 구조가 부동산 구입이면 여기다.
- 부동산 개발에 파이낸싱해서 이익금을 나누는 것은 소재가 부동산이어도 **프로젝트**다. 부동산 구매 행위가 아니다.
- **애매한 것은 모두 프로젝트로 넣는다.** 프로젝트는 성격으로 정의된 유형이 아니라 잔여 범주다.

**레저** = 골프장·리조트 회원권, 콘도미니엄·호텔 객실(운영 위탁), 방갈로·빌라(단독 운영), 마리나·선착장, 캠핑장·글램핑. 카지노도 개념상 레저지만, 실제 상품이 물리적 공간이 아니라 테이블 지분 취득이면 프로젝트다.

**프로젝트에 들어가는 것** = 개발 파이낸싱, 사업체 지분·조인트벤처, 토지 개발·인허가 단계, 완공 임박 재고 물량, 비부동산 사업 투자(F&B·물류), 농장·플랜테이션. 농장·플랜테이션은 레저가 아니다.

고객에게 중요한 것은 권리냐 실물이냐가 아니라 "이게 나중에 돈이 되는가"다. 이용권/수익권 구분은 분류 기준으로 쓰지 않는다.

## 2. 자산 (asset)

목업의 `raw[]` + `M[]`이 합쳐진 형태다. `M[i]`가 검색용 정량 필드, `raw[i]`가 표시용 필드다.

### 식별·분류

| 필드 | 예 | 출처 |
|---|---|---|
| `id` | — | 시스템 |
| `cat` | `"주거용"` | 관리자 |
| `txn` | `"임대" \| "매매" \| "프로젝트"` | 크롤 or 관리자 |
| `cc` | `"KH" \| "VN" \| "PH" \| "MY"` | 크롤 |
| `country` | `"Cambodia"` | 크롤 |
| `loc` | `"BKK1, Phnom Penh"` | 크롤 |
| `region_id` | — | 관리자 (지역 등급 연결용) |
| `origin` | `"GLI 검증" \| "GLI 발굴"` | 시스템 |

`cc`는 필터·검색용 코드, `country`는 지역 데이터 조회 키다. 지금은 둘이 중복이므로 실제 구현에서는 하나로 합치고 표시용 국가명을 파생시키는 편이 낫다.

### 표시

| 필드 | 예 |
|---|---|
| `title` / `titleEn` | `"BKK1 레지던스"` / 영문명 |
| `spec` | `"2베드 74㎡ · 15층"` — 한 줄 요약 |
| `summary` | 3~4문장 설명 |
| `img` | 대표 이미지 경로 |
| `imgnote` | `"참고 이미지" \| "시행사 제공"` 등 출처 고지 |
| `stock` | `true`면 스톡 사진 |
| `images[]` | 갤러리 (있는 자산만) |
| `tags[]` | `["강전망","리버뷰","고층"]` — 검색 키워드 매칭용 |

### 금액

| 필드 | 의미 |
|---|---|
| `priceLabel` | 가격 항목의 이름. 유형마다 다르다 (`"매매가"`, `"월세"`, `"목표 금액"`, `"프로젝트 안내"`) |
| `price` | 현지 통화 표기 문자열. `"자료상 가격 미기재"`도 유효한 값이다 |
| `krw` | 원화 환산 표기 문자열 |
| `monthly` | 월세 (원, 숫자) — 검색용 |
| `krw_num` | 매매가 (원, 숫자) — 검색용. 목업에서는 `M[i].krw` |

**표시용 문자열과 검색용 숫자를 분리해서 유지할 것.** 목업이 그렇게 되어 있다. 가격 미기재 자산이 실재하므로 숫자 필드는 nullable이다.

카드에서는 K 단위로 축약하고(`shortPrice()`), 상세에서는 전체 금액을 쓴다.

### 정량 (주거·상업)

`beds`, `area`(㎡). 검색 필터용.

### 근거

| 필드 | 의미 |
|---|---|
| `basis` | 기준 자료. `"시행사 Fact Sheet"`, `"토지 등기 사본 · 용도 변경 접수증"` |
| `docDate` | 자료 일자. `"2025년 11월 26일 자료 기준"` |
| `facts[]` | `{label, value}` 쌍의 항목표 |
| `strengths[]` | 확인된 강점 |
| `checks[]` | 확인이 필요한 항목 |

**`basis`와 `docDate`는 필수다.** 값이 없으면 화면에 올리지 않는다. `facts[]`의 값이 없을 때는 필드를 지우지 말고 `"조사 예정"`을 넣는다 — 무엇을 모르는지가 정보다.

### 등급

`trust` — 목업에서는 0~100 숫자를 손입력하고 `GRADE_OF()`가 8단 등급으로 바꾼다. 실제로는 §5의 입력 항목에서 계산한다. **점수는 내부 값이고 화면에 나오지 않는다.**

## 3. 출처 기록 (provenance)

목업에 없는, 구현에서 반드시 추가해야 할 테이블이다. 필드 하나하나가 어디서 왔는지 남는다.

```
{
  asset_id, field_path,          // "facts[2].value"
  value,
  source_type,                   // crawl | document | interview | visit | admin
  source_url,      source_name,  // 크롤이면 URL, 문서면 문서명
  captured_at,     doc_date,     // 수집 시각 / 자료 자체의 일자
  verified_by,     verified_at,  // 전문가 확인 (null이면 미확인)
  conflict_with                  // 다른 출처와 값이 다를 때
}
```

**이 테이블이 Trust 등급의 계산 근거다.** 확인된 필드 비율, 자료 최신성, 출처 간 불일치가 모두 여기서 나온다. 등급을 손으로 매기는 대신 이 기록에서 계산해야 크롤링을 붙인 의미가 생긴다.

`conflict_with`가 중요하다. AI가 찾은 값과 전문가가 확인한 값이 다를 때 덮어쓰지 말고 둘 다 남긴다 — 불일치 자체가 등급을 내리는 사유다.

## 4. 지역 (region)

목업의 `REGION[country]`. 실제로는 **국가 → 주 → 도시 → 구역 → 블록** 계층이다.

```
{
  level,                  // country | state | city | district | block
  parent_id,
  scope,                  // "구역 단위까지 조사 · 블록 보완 중"
  city[],                 // [{l:"공항", v:"차량 35분"}] 인프라
  grades[],               // [{l:"치안", g:"C"}] 6개 항목
  items[],                // 현지 관측 기록
  log[],                  // 확인 이력
  say[]                   // 주민 코멘트
}
```

### 점수 누적 모델

국가에 기준점수를 두고 하위 계층에서 가산·감산한다.

```
필리핀 치안 50  →  BGC +20  →  70
                  앙헬레스 −20  →  30
```

(수치는 예시다. 실제 값은 사업 측이 정한다.)

**국가 기준점수는 화면에 노출하지 않는다.** 노출되면 "필리핀은 치안이 나쁩니다"가 되어 §5의 국가 정보 방침을 위반한다. 고객에게는 구역 단위 최종값만 보인다.

**미결**: 최종값만 보이면 구성이 사라진다. BGC 70(50+20)과 방콕 어느 구역 70(75−5)이 같아 보이지만 하나는 국가가 낮고 구역이 좋은 것, 하나는 국가가 좋고 구역이 평범한 것이다. 국가 리스크는 좋은 구역이 막아주지 못한다(정치 불안·외환 규제는 BGC에도 온다). 표시 방법은 정해지지 않았다.

### 계층별 노출 방침

| 계층 | 방침 |
|---|---|
| 국가 | 현황 정보를 고객에게 알리지 않는다. 스코어링 내부 입력으로만 |
| 주·도시 | 인프라 차원의 차이. 무료 공개 (공항·의료 접근 등) |
| 구역·블록 | 데이터로는 찾기 어렵고 사람이 가야 나온다. GLI 고유 가치가 여기 있다. PREMIUM |

### 기록 항목 (`items[]`)

```
{ lay, cat, tone, scope, sum, text, when, how }
```

- `lay` — 열람 계층 (1=무료, 상위는 등급 필요)
- `cat` — `"치안" | "침수·배수" | "위생" | "전력" | "수질·수압" | "의료 접근"`
- `tone` — `"pos" | "neg"`
- `sum` — 한 줄 요약, `text` — 서술
- `how` — `"현장 방문" | "현지 인터뷰" | "전화 확인"`

**기록은 자산이 아니라 지역에 붙고 같은 구역 자산이 공유한다.** 외부 수집 매물의 기록 수가 0으로 나오는 것은 정상이며, 직영과 외부 수집의 차이가 그렇게 드러난다.

조사의 **양**(기록 개수)은 노출하되 등급 계산에 넣지 않는다. **깊이**(서술 밀도)는 열면 문장이 말하므로 배지로 표기하지 않는다. **범위**(어느 계층까지 채웠나)는 `scope`에 적는다.

## 5. 등급 (grade)

**8단: S · A+ · A · B+ · B · C+ · C · D.** 점수제가 아니라 등급제로 간다.

### 유형별로 재는 대상이 다르다

| 유형 | 재는 것 | S | D |
|---|---|---|---|
| 부동산 | 객관적 자료가 얼마나 검증되었는가 | 확인 항목이 대부분 채워짐 | 확인이 거의 되지 않음 |
| 프로젝트 | 리스크가 얼마나 낮은가 | 자료가 신뢰할 만한 대형 사업 주체 | 주체가 신뢰하기 어려운 개인이거나, 공식 계약 절차가 불투명한 그레이 비즈니스 |

프로젝트에서 **낮은 등급이 나쁜 자산이라는 뜻이 아니다.** 이런 류는 대체로 수익성이 높다. D는 결함이 아니라 위험·수익 위치다.

### 계산 입력

부동산 — 출처 기록(§3)에서 계산한다.
- 확인된 필드 비율 (`verified_at`이 있는 필드 / 필수 필드)
- 자료 최신성 (`doc_date` 경과)
- 출처 간 불일치 건수 (`conflict_with`)
- **조사량은 넣지 않는다.** **치안도 넣지 않는다.**

프로젝트 — 사업 주체 중심으로 계산한다.
- 사업 주체의 규모·이력·계약 확인 여부
- 계약 구조의 법적 지위 명확성
- 실적 자료 확보 정도
- 인허가·권리 확인 단계

높은 수익률을 내건 주체의 신뢰도가 낮으면 등급이 내려간다. **GLI가 수익률을 판정하는 것이 아니라 주체를 판정한다.**

### 표시 규칙

배지에 꼬리표를 붙이거나 색을 다르게 하지 않는다. 상세에 해설도 넣지 않는다. 등급과 수익률을 나란히 놓기만 하고, 두 값의 대비가 관계를 스스로 드러내게 한다.

## 6. 프로젝트 템플릿

**프로젝트는 자동 크롤링이 없다.** 전부 GLI가 손수 입력한다. 관리툴에서 표시 템플릿을 고르고 내용을 기입해 공개한다.

### 공통 머리 (4종 공유)

자산명 · 소재지 · 분류 배지 · 대표 이미지 · 기준 자료와 자료 일자 · **발굴 경로** · 등급.

발굴 경로는 자산별로 관리자가 공개 수위를 정한다: 파트너사 이름까지 / 경로만(`"2026년 3월 프놈펜 방문 중"`) / 비공개(`"관리자 지정 · 비공개"`).

프로젝트의 유래가 고유 가치다 — 동남아 부동산을 탐색하러 현지에 가서 파트너사와 사람을 만나다 알게 된 사업 기회다. **발굴 경로를 등급 뒤에 숨기지 않는다.** 상세에서 잠금 없이 열린 본문에 둔다.

### 금전 필드 (4종 공유)

| 필드 | 규칙 |
|---|---|
| `goal` / `goalKrw` | 목표 금액. 표시한다 |
| `pct` | 진행률. **모인 금액은 숫자로 쓰지 않고 진행률로만** 짐작하게 한다 |
| `min` | 최소 참여 금액 |
| `apy` | 예상 수익률. **사업 주체가 제시한 숫자.** GLI 산정 아님을 화면에 밝힌다. `"제시 없음"`도 유효 |
| `backers` | `"20명 이상"` — 정확한 숫자를 쓰지 않는다 |
| `term` | 예상 기간 |

### 템플릿별 항목

**A 사업 참여형** (개발 파이낸싱, 이익금 배분)
소재 사업 · 참여 방식 · 배분 구조 · 회수 방식 · 사업 주체

**B 지분 취득형** (사업체 지분, JV, 카지노 테이블 지분)
취득 대상 · 지분 범위 · 정산 주기 · 사업 현황 · 운영 주체 · 실적 자료 유무

**C 토지·개발 단계형**
면적 · 지목과 용도 · 인허가 단계 · 개발 계획 · 사업 주체

**D 자유 서술형**
위 셋에 안 맞는 것. 설명과 자료 첨부만. 애매한 건이 막히지 않게 하는 도피구다.

운영 사업형(농장·F&B·물류 직접 운영)은 지금 만들지 않는다. D로 받고 물량이 쌓이면 승격.

### 프로젝트 상세의 구성

공통 골격을 쓰되 유형 전용 섹션을 더하고 부동산 전용 줄은 뺀다.

- **더한다**: 사업 정보 섹션 (목표 금액·진행률·금전 필드·템플릿별 항목·발굴 경로). 잠금 없이 열린 상태.
- **뺀다**: 건물 제원 / 거래 실행 조건 / 비슷한 조건의 자산.
- **바꾼다**: 거래 실행 단계 → 주체 실사·계약 구조 검토·참여 절차 지원. 후속 질문 → 주체 확인·정산 순서·중단 시 처리.

### 신뢰 표기의 성격 차이

프로젝트는 출처가 GLI 자신이라 교차 확인할 대상이 없다. 부동산의 "AI가 모으고 전문가가 확인" 문구를 그대로 쓰면 안 된다. 약점이 아니라 다른 종류의 근거다.

## 7. 등급 열람 게이팅

`mkRow(tierId, level, summary, inside)`가 `state.unlocked >= level`로 열림/잠김을 판정한다.

| 레벨 | 등급 | 열리는 것 |
|---|---|---|
| 1 | FREE | 공개 정보. 헤더·장단점·지도·도시 인프라 |
| 2 | BASIC | AI가 정리한 위험 신호, 전체 제원, 비슷한 조건의 자산 |

**접힌 줄은 라벨만 두지 않는다.** 닫힌 상태에서도 등급 배지 + 안에 무엇이 있는지 요약 한 줄 + 기록 개수를 보여준다. 라벨만 있으면 리모컨이 되고, 정보를 담고 있으면 아니다.

FREE~STANDARD는 결제 외의 활동으로도 도달 가능하고, PREMIUM·BUSINESS만 과금이 필수다. 도달 경로 세 가지(활동 / 멤버십 / 자산별 이용권)를 우측 패널에 나란히 적고, 버튼은 한 개만 둔다.
