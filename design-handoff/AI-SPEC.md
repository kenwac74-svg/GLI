# AI SPEC — 2026-08-26

목업의 AI 검색은 **이미 동작한다.** 이 문서는 그 계약을 옮기기 위한 것이다. 해당 코드는 `source/gli-demo.dc.html`의 `search()`, `localParse()`, `normalize()`, `rank()`, `pipeVals()`에 있다.

---

## 1. 역할 분담

```
사용자 문장  →  [LLM] 조건 추출  →  [GLI 데이터] 순위 계산  →  결과 + 근거
```

**LLM은 문장을 조건으로 바꾸는 일만 한다.** 자산을 추천하거나 순위를 정하지 않는다. 순위는 GLI 자산 데이터로 계산한다.

이유: LLM이 추천까지 하면 왜 그 자산이 나왔는지 설명할 수 없다. 목업은 각 결과에 `why[]`(매칭 이유)를 붙여 보여준다 — 검증을 파는 제품이므로 순위의 근거가 재현 가능해야 한다.

화면 문구도 이 구분을 밝힌다: `"질문은 Claude가 해석해 검색 조건으로 바꾸고, 후보 순위는 GLI 자산 데이터로 계산합니다."`

---

## 2. 조건 추출

### 시스템 프롬프트

목업이 쓰는 것을 그대로 옮긴다.

```
너는 동남아 부동산 투자 자문 GLI의 검색 파서다.
사용자 문장에서 조건을 뽑아 JSON만 출력한다.
```

### 출력 스키마

```json
{
  "cc": "KH | VN | PH | MY | null",
  "txn": "임대 | 매매 | null",
  "budget": 50000000,
  "beds": 2,
  "keywords": ["임대수익", "강전망"],
  "reply": "조건을 한 문장으로 되읽어주는 답변"
}
```

- `budget` — 원 단위 정수. 없으면 `null`
- `beds` — 스튜디오·원룸은 `0`
- `keywords` — 자산의 `tags[]`와 매칭된다. 목업이 인식하는 값: `강전망 리버뷰 강변 고층 도심 소형 신축 선분양 휴가 수영장 호텔 복합 저예산 임대수익 BKK1 KLCC KL 분양`
- `reply` — 채팅 영역에 표시. 조건을 되읽어 사용자가 오해를 바로잡을 수 있게 한다

**JSON만 출력하게 하고, 파싱 실패 시 폴백으로 넘긴다.** 목업은 `try/catch`로 감싸고 실패하면 `f = null`로 두어 정규식 파서를 쓴다.

### 폴백 파서

`localParse(q)` — LLM 없이 정규식으로 같은 스키마를 만든다. 오프라인·API 실패·비용 절감 상황에서 쓴다. 화면은 이때 문구만 바꾼다(`engineNote`): `"조건 해석을 기기 안에서 처리하며 후보 순위는 동일한 GLI 자산 데이터로 계산합니다."`

**이 폴백을 버리지 말 것.** AI가 죽어도 검색이 되는 것이 제품의 안전선이다.

## 3. 정규화 (`normalize`)

LLM 출력을 그대로 쓰지 않는다. 실사용에서 반복적으로 틀리는 두 가지를 교정한다.

```js
// 1. 통화 단위 누락 — 10만 미만이면 달러로 보고 환산
if (f.budget && f.budget < 100000) f.budget = Math.round(f.budget * 1385);

// 2. "월세가 잘 나오는 투자" = 세입자가 아니라 임대수익용 매수
if (f.txn === "임대" && f.budget && f.budget > 8000000) {
  f.txn = "매매";
  f.keywords.push("임대수익");
}
```

두 번째가 중요하다. "프놈펜에 5,000만원으로 월세가 잘 나오는 투자"는 월세 5,000만원짜리 세입자가 아니라 5,000만원으로 임대수익형 자산을 사려는 사람이다. 이 교정이 없으면 결과가 0건이 된다.

환율 1,385원/USD는 상수로 박혀 있다. 실서비스에서는 환율 소스를 붙일 것.

## 4. 순위 계산 (`rank`)

LLM을 쓰지 않는다. 조건과 자산을 대조해 점수를 낸다.

| 조건 | 처리 |
|---|---|
| 기본 점수 | 부동산 8, 프로젝트 4 |
| `cc` 불일치 | **제외** (continue). 일치 시 +40 |
| `txn` 불일치 | **제외**. 일치 시 +30 |
| `budget` | 예산 대비 비율로 가감 |
| `beds` | 일치 시 가산 |
| `keywords` | `tags[]`와 교집합만큼 가산 |

**국가와 거래 유형은 감점이 아니라 제외다.** 예산은 초과해도 근처면 보여준다 — 조금 넘는 후보를 아예 안 보여주면 사용자가 판단할 기회를 잃는다.

예산 비교는 거래 유형에 따라 대상이 다르다. 월세 예산은 `monthly`와, 총 투자금은 `krw`와만 비교한다. 섞으면 결과가 무의미해진다.

각 자산에 `why[]`를 쌓는다 — `"캄보디아 소재"`, `"임대 물건"`, `"예산 범위"`. 이것이 카드에 표시되는 매칭 이유다.

## 5. 파이프라인 상태

검색 진행을 4단계로 보여준다. `pipeVals()`가 상태를 계산한다.

```
요청 이해 → 후보 탐색 → 근거 검토 → 답변 구성
```

상태 값: `idle | understanding | searching | reviewing | composing | complete | error`

```js
// pipeState가 null이면 실제 상태에서 파생
let st = s.pipeState;
if (!st) st = s.busy ? "searching" : (s.hits ? "complete" : "idle");
```

**API 연결**: `s.pipeState` 자리에 검색 API의 진행 단계를 넣으면 된다. 단계가 실제와 다르면 `pipeVals()`의 `activeAt` 매핑만 고친다. 실패 단계는 `errAt` 상수 대신 API가 알려준 단계를 넣는다.

### CSS 클래스 계약

```
.pipe-step.is-idle      대기
.pipe-step.is-active    진행 중 (pulse, reduced-motion에서 정지)
.pipe-step.is-done      완료
.pipe-step.is-error     오류
.pipe-mob               모바일 압축 표기 (≤768px)
.pipe-mob.is-error      모바일 오류
.pipe-err               오류 문구
```

`.pipe-n`(번호 자리)의 내용도 상태에 따라 바뀐다: 숫자 → `✓` → `!`. 색상만으로 구분하지 않기 위한 처리다.

파이프라인 아래 상태 전환 칩 7개는 검수용이다. 제거하려면 `<div class="statedemo">` 블록과 `pickPipeState`, `state.pipeState`를 삭제한다. 라벨은 이미 떼어둔 상태다 — 보는 사람에게 데모로 읽히지 않게 하기 위한 것이므로 라벨을 되붙이지 말 것.

## 6. 미구현 — 후속 대화

상세 페이지에 후속 질문 칩이 있으나 답이 없다. 유형에 따라 질문이 다르다.

**부동산**: `"이 나라에서 외국인이 살 수 있나요"` `"실제로 월세가 얼마나 나오나요"` `"계약까지 몇 번 가야 하나요"`
**프로젝트**: `"사업 주체를 어떻게 확인했나요"` `"돈이 어떤 순서로 돌아오나요"` `"사업이 멈추면 어떻게 되나요"`

구현 시 자산 문맥을 함께 실어 호출한다.

```
system: GLI 자산 상세 문답. 아래 자산 정보와 지역 기록만 근거로 답한다.
        확인되지 않은 것은 "조사 예정"이라고 답하고 추측하지 않는다.
context: { asset, region, basis, docDate, facts, checks }
```

**추측을 막는 것이 핵심이다.** GLI가 파는 것이 "무엇을 알고 무엇을 모르는지 구분해 준다"는 것이므로, 모르는 것을 그럴듯하게 채우면 제품의 주장이 무너진다. `checks[]`에 있는 항목을 물으면 "아직 확인되지 않았다"고 답해야 한다.

## 7. AI가 쓰이는 다른 자리

| 위치 | 용도 | 상태 |
|---|---|---|
| 자산 탐색 | 문장 → 검색 조건 | 동작 |
| 랜딩 히어로 입력 | 값을 들고 탐색으로 이동 후 실행 | 동작 |
| BASIC 단계 위험 신호 | 자료에서 위험 항목 추출·요약 | 미구현. 손입력 |
| 크롤링 정규화 | 수집 HTML → 필드 | 미구현. `CRAWLER-SPEC.md` |
| 후속 대화 | 자산 문맥 문답 | 미구현 |
| 지역 기록 요약 | 관측 기록 → 한 줄 요약(`sum`) | 미구현. 손입력 |

BASIC의 위험 신호는 AI가 뽑되 **원문 대조가 가능해야 한다.** 요약만 남고 근거가 사라지면 안 된다. 출처 기록(`DATA-MODEL.md` §3)에 원문 위치를 남긴다.
