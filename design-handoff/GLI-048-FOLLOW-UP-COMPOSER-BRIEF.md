# GLI-048 Claude Design 작업지시서

## 1. 작업 개요

- 작업명: GLI AI 상담 결과 하단 후속 질문 컴포저 추가
- 대상 화면: `/explore`
- 디자인 담당: Claude Design AI
- 기능 연결 담당: Codex
- 상태: 디자인 핸드오프 대기

현재 사용자는 상단 AI 탐색 입력창에서 최초 질문을 보낼 수 있다. 답변은 `조건을 이어서 상담하세요` 패널에 누적되지만 답변을 읽은 위치에서 후속 질문을 입력할 수 없다. 다시 화면 상단으로 이동해야 하므로 대화 흐름이 끊기고, 모바일에서는 이동 부담이 더 크며, 일회성 검색 기능처럼 느껴진다.

첫 번째 AI 답변이 생성된 뒤 상담 패널 하단에서 바로 다음 질문을 입력하고 보낼 수 있는 후속 질문 컴포저를 설계한다.

## 2. 정보 구조 원칙

이 작업은 기존 최초 검색 UI를 대체하거나 복제하는 작업이 아니다.

- 상단 입력창: 새로운 탐색을 시작하는 최초 질문
- 상담 패널 하단 입력창: 기존 조건과 대화를 이어가는 후속 질문

두 입력창의 역할이 시각적으로 혼동되지 않아야 한다. 사용자가 아직 질문하지 않은 상태에서는 기존 상단 입력창만 보이고, 빈 상담 패널에 후속 입력창을 미리 노출하지 않는다.

## 3. 원본 동결 원칙

`source/gli-demo.dc.html`과 기존 CSS/시각 언어가 유일한 디자인 기준이다. 이번 작업에서 허용된 변경은 `/explore` 상담 패널 하단의 후속 질문 컴포저와 그 상태 표현뿐이다.

다음 요소는 변경하지 않는다.

- 기존 문구, 폰트, 색상 토큰, 카드 형태, 여백 체계
- 상단 최초 검색 컴포저의 구조와 역할
- 탐색 파이프라인과 결과 카드의 구조
- 헤더, 필터, 자산 카드, 다른 페이지
- GLI 정책, 자산 데이터, Trust 등급, 멤버십 정책
- AI 공급사 이름을 노출하는 문구

범위 밖의 개선점은 구현하지 말고 별도 제안으로 기록한다.

## 4. 필수 사용자 흐름

### 4.1 최초 진입

- 후속 질문 입력창을 표시하지 않는다.
- 기존 상단 검색 입력창만 사용한다.
- 최초 검색 기능을 페이지 안에 두 번 보여주는 인상을 만들지 않는다.

### 4.2 첫 답변 완료

- 첫 AI 답변이 표시되면 상담 패널의 마지막 답변 바로 아래에 후속 질문 컴포저가 나타난다.
- 답변과 입력 영역 사이는 기존 `line` 색상과 패널 간격 체계를 사용한다.
- 사용자는 상담 패널을 벗어나지 않고 다음 질문을 입력할 수 있어야 한다.

### 4.3 후속 질문 전송

- 전송한 사용자 질문은 기존 대화 목록의 마지막에 추가된다.
- 질문 아래에 GLI AI의 다음 답변이 이어진다.
- 컴포저는 항상 최신 대화 아래에 유지된다.
- 새 답변이 추가되면 최신 대화가 자연스럽게 보이되 갑작스러운 전체 페이지 점프는 피한다.

### 4.4 처리 중

- 입력창과 전송 버튼을 비활성화해 중복 전송을 막는다.
- 컴포저 가까이에 처리 상태를 표시한다.
- 권장 문구: `GLI AI가 답변을 정리하고 있습니다`
- 기존 4단계 최초 탐색 파이프라인을 후속 질문마다 크게 반복하지 않는다.
- 작은 진행 표시나 버튼 내부 상태처럼 대화 흐름에 맞는 간결한 표현을 사용한다.

### 4.5 오류

- 기존 대화는 유지하고 컴포저를 다시 활성화한다.
- 오류 문구와 재시도 동작은 컴포저 가까이에 배치한다.
- 권장 문구: `답변을 불러오지 못했습니다. 다시 보내 주세요.`

## 5. 컴포저 구성

Claude는 기존 디자인 언어 안에서 최종 형태를 결정하되 다음 요소를 포함한다.

- 내용에 따라 제한적으로 높이가 늘어나는 textarea
- 전송 버튼 또는 Lucide `Send` 아이콘 버튼
- 전송 버튼의 비활성, 처리 중, 오류 상태
- 명확한 키보드 포커스
- 스크린리더용 입력 레이블과 전송 버튼 이름

권장 문구:

- 입력 레이블: `후속 질문`
- placeholder: `이어서 궁금한 점을 물어보세요`
- 텍스트 버튼: `보내기`
- 아이콘 버튼: `aria-label="후속 질문 보내기"`

입력창 주변에 사용법, 단축키, 모델 공급사 또는 긴 기능 설명을 추가하지 않는다.

## 6. 데스크톱 지시

- 상담 패널의 폭과 정렬선을 그대로 따른다.
- 대화 내용과 컴포저가 하나의 상담 영역으로 읽혀야 한다.
- 입력창과 전송 버튼의 높이와 기준선을 맞춘다.
- 컴포저가 별도의 큰 카드나 카드 안의 카드처럼 보이지 않게 한다.
- 긴 답변 뒤에도 후속 입력 위치를 쉽게 찾을 수 있어야 한다.

Claude는 다음 중 현재 디자인에 더 자연스러운 방식을 선택할 수 있다.

1. 대화 목록의 마지막에 일반 흐름으로 배치
2. 상담 패널 내부 하단에서만 제한적으로 sticky 처리

화면 전체에 고정되는 fixed 입력창은 사용하지 않는다.

## 7. 모바일 지시

360px, 390px, 430px, 768px에서 직접 확인한다.

- 입력 글자 크기는 최소 16px이다.
- 터치 영역은 최소 48px, 전송 버튼은 가능하면 52px 이상이다.
- 가상 키보드가 열렸을 때 입력창과 버튼이 가려지지 않아야 한다.
- `100vh`만 사용해 키보드 높이를 오판하지 않는다.
- `env(safe-area-inset-bottom)`을 고려한다.
- 긴 한국어 질문에도 가로 넘침이나 버튼 밀림이 없어야 한다.
- sticky를 사용한다면 상담 패널을 벗어나 결과 카드나 하단 내비게이션을 가리지 않아야 한다.
- textarea와 전송 버튼의 가로 또는 세로 배치는 실제 폭을 보고 결정하되 버튼이 지나치게 작아지지 않아야 한다.

## 8. 기능 연결용 DOM 계약

Claude HTML에는 다음 훅을 사용한다. 시안용 동작은 가능하지만 실제 API 호출 코드는 작성하지 않는다.

```html
<form data-followup-composer>
  <textarea
    data-followup-input
    aria-label="후속 질문"
    placeholder="이어서 궁금한 점을 물어보세요"
  ></textarea>
  <button type="submit" data-action="runFollowUp">
    보내기
  </button>
  <p data-followup-status aria-live="polite"></p>
</form>
```

상태 클래스:

```text
.is-loading
.is-error
```

Codex가 연결할 기능:

- 최근 대화 문맥과 누적 검색 조건 전달
- `/api/search` 호출
- 사용자 질문과 GLI AI 답변 추가
- 전송 중 비활성화와 상태 클래스 연결
- 오류와 재시도 처리
- 최신 대화 위치 이동

## 9. 시안에 포함할 상태

1. 최초 질문 전: 후속 컴포저 없음
2. 첫 답변 완료: 후속 컴포저 표시
3. 후속 질문 입력 중
4. 후속 답변 처리 중
5. 후속 답변 완료 후 대화가 두 차례 이상 누적된 상태
6. 오류 후 재전송 가능 상태
7. 모바일 가상 키보드를 고려한 입력 상태

## 10. 접근성 및 동작 조건

- Enter 전송 여부는 기존 검색 입력 동작과 일관되게 정한다.
- 여러 줄 입력이 필요하므로 `Shift+Enter` 또는 모바일 줄바꿈이 가능해야 한다.
- 포커스 표시를 제거하지 않는다.
- 처리 상태는 색상만으로 전달하지 않는다.
- `aria-busy`, `aria-live` 또는 동등한 접근성 상태를 제공한다.
- 애니메이션을 사용하면 `prefers-reduced-motion`을 존중한다.

## 11. Claude 납품물

- 수정된 `source/gli-demo.dc.html`
- 필요한 경우 동일 파일 내부 CSS와 시안용 JS
- 변경된 클래스와 DOM 훅 목록
- 원본과 육안으로 달라진 항목 목록
- 데스크톱 1440px 상태 캡처
- 모바일 390px 상태 캡처
- 최초, 처리 중, 후속 답변 완료 상태 캡처

`support.js`의 시안 실행 로직은 React로 전달하지 않는다. Codex가 HTML/CSS 구조를 React에 옮기고 실제 이벤트와 API를 연결한다.

## 12. 완료 판정

- 사용자가 첫 답변을 읽은 위치에서 바로 후속 질문을 보낼 수 있다.
- 상단 최초 검색창과 하단 후속 컴포저의 역할이 혼동되지 않는다.
- 후속 질문 처리 중인지 멈춘 것인지 명확히 알 수 있다.
- 데스크톱과 모바일에서 입력창, 버튼, 대화 내용이 겹치지 않는다.
- 기존 Claude 디자인의 폰트, 색상, 크기, 여백과 정보 계층이 유지된다.
- GLI 이외의 AI 공급사 이름이 화면에 노출되지 않는다.
- 이번 작업 범위 밖의 화면과 문구가 변경되지 않는다.
