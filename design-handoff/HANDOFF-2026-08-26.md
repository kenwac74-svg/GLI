## 1. 역할 구분

**디자인 담당이 정한 것** — 화면 구조, 정보 계층, 등급 체계, 노출/비노출 방침, 카피. 이것들은 사업 판단으로 확정된 사항이며 구현 편의로 바꾸지 않는다. 바꿔야 할 이유가 생기면 구현하지 말고 사용자에게 보고할 것.

**GPT가 정하는 것** — 프레임워크, 라우팅, 상태 관리, API 형태, AI 호출 방식, 크롤러 실행 환경, 저장소 스키마의 물리 설계, 배포.

## 2. 지금 동작하는 것 / 동작하지 않는 것

### 이미 동작한다 (그대로 옮기면 된다)

- **AI 검색의 전체 흐름.** `window.claude.complete`가 있으면 문장을 JSON 조건으로 파싱하고, 없으면 `localParse()` 정규식 파서로 대체한다. 순위는 두 경우 모두 `rank()`가 계산한다. → `AI-SPEC.md`
- **필터·정렬·등급 판정·조사량 집계** — `renderVals()` 안의 계산이 곧 뷰 모델이다.
- **등급별 열람 게이팅** — `mkRow(tierId, lvl, …)`이 `state.unlocked` 레벨과 비교해 열림/잠김을 결정한다.
- **화면 전환** — `state.view` 값으로 전환. 라우터로 바꿀 때 매핑은 §4.

### 동작하지 않는다 (GPT가 구현)

| 항목 | 현재 상태 | 필요한 것 |
|---|---|---|
| 자료 크롤링 | 없음. 16건 전부 하드코딩 | 수집 → 정규화 → 저장. `CRAWLER-SPEC.md` |

## 3. 크롤링의 현실적 제약

브라우저에서 외부 사이트를 직접 fetch하면 CORS로 막힌다. 크롤링은 서버 측 실행이 필요하다. GPT 사이트 기능만으로 모사할 경우 선택지는:

1. **수집 결과를 정적 JSON으로 미리 만들어 넣는다.** 크롤러는 별도로 돌리고 산출물만 앱에 싣는다. 기능 목업 단계에서 가장 현실적이다.
2. **프록시를 경유한다.** 서버 함수 한 개로 대상 URL을 받아 HTML을 되돌려준다.
3. **LLM에 URL을 주고 요약을 받는다.** 웹 접근이 가능한 모델이면 수집과 정규화를 한 번에 처리한다. 다만 원문 대조가 안 되므로 출처 기록(`DATA-MODEL.md` §3)을 반드시 남겨야 한다.

어느 쪽을 택하든 **출처와 자료 일자를 잃지 않는 것**이 조건이다. GLI가 파는 것이 검증이므로, 어디서 온 값인지 모르는 데이터는 화면에 올릴 수 없다.

## 4. 화면과 라우트 맵

`state.view` 값 → 권장 경로.

| view | 화면 | 권장 경로 | 비고 |
|---|---|---|---|
| `land` | 랜딩 (기본 진입) | `/` | 히어로 입력값을 `?q=`로 탐색에 전달 |
| `home` | 자산 탐색 | `/explore` | `?q` `?cc` `?cat` `?txn` |
| `detail` | 자산 상세 | `/assets/[id]` | 유형에 따라 섹션 구성이 다르다 |
| `fav` | 관심자산 | `/favorites` | 계정 귀속 |
| `plan` | 멤버십 | `/membership` | |
| `co` | 결제 확인 | `/membership/checkout` | |
| `about` | GLI 소개 | `/about` | |
| `news` / `article` | 뉴스 / 기사 | `/news`, `/news/[id]` | |
| `paper` | 백서 | `/whitepaper` | 웹3 기준 문서. 내용 수정하지 않는다 |
| `trust` | 검증 체계 | `/about/verification` | 현재는 소개 안의 앵커 |
| `soon` | 준비중 | `/coming-soon?f=` | |

**최상단 메뉴는 4개다** — GLI 소개 / 자산 탐색 / 멤버십 / 커뮤니티. 우상단에 관심자산·로그인·언어. 자산 탐색의 1차 축은 **국가별 → 자산 유형 → 거래 유형** 순서다.

## 5. 절대 바꾸지 말 것

사업 판단으로 확정된 표시 규칙이다. 구현 편의로 어기면 제품의 주장이 무너진다.

**등급**
- 등급은 **S · A+ · A · B+ · B · C+ · C · D** 8단. 점수를 화면에 노출하지 않는다.
- 등급이 재는 대상이 유형마다 다르다. 부동산 = 자료가 얼마나 검증되었는가. 프로젝트 = 리스크가 얼마나 낮은가.
- 프로젝트의 낮은 등급은 결함이 아니라 위험·수익 위치다. **배지에 꼬리표를 붙이거나 색을 다르게 하지 않고, 해설도 넣지 않는다.** D에 높은 수익률이, S에 은행 금리 수준이 붙는 것이 정상이다.
- 치안은 등급(Trust)에 넣지 않는다. 치안은 지역 등급 쪽이다.

**국가 정보**
- 국가의 일반 현황(치안·시장 전망·정치 안정성)을 고객에게 알리지 않는다. 필리핀 매물을 보러 온 사람은 이미 감안하고 왔다.
- 국가 기준점수를 화면에 노출하지 않는다. 고객에게는 구역 단위 최종값만.
- 국가 카드에 붙는 것은 GLI 재고 정보뿐 — 자산 수, 구역 수, 실사 횟수.

**조사량**
- 기록 0건을 숨기지 않는다. 고객에게는 "별로 알려지지 않은 곳"이라는 정직한 정보이고, GLI에는 조사 우선순위 신호다.
- 조사량은 노출하되 등급 계산에 넣지 않는다.

**금전 표기 (프로젝트)**
- 예상 수익률은 **사업 주체가 제시한 숫자**다. GLI가 산정·추정하지 않는다. 화면에 출처를 밝힌다.
- 대신 사업 주체의 신뢰도를 등급에 반영한다.
- **목표 금액만 표시하고 모인 금액은 진행률로만** 짐작하게 한다. 정확한 모금액을 숫자로 쓰지 않는다.
- 참여자 수는 정확한 숫자 대신 "○○명 이상".

**화면 표기**
- "DEMO", "미구현", "준비 중" 같은 표시를 붙이지 않는다. 보는 사람에게 최종 완성 버전으로 보여야 한다. 데모 여부와 가짜 정보는 소스 주석에만 기록한다.
- 자산 카드의 가격은 K 단위로 축약(RM 1,352K~3,174K), 상세 페이지는 전체 금액.
- 섹션마다 "○○ 열기" CTA를 달지 않는다. 결제 버튼은 우측 패널 한 곳에만.

**스테이징 데모(`stg.glibiz.com`)에서 가져올 것은 없다.** Web3 생태계 기반으로 만들었던 폐기된 기획안이다. TARGET APY, YIELD SIMULATOR, CONFIRM STAKING, GLIB 스테이킹 수량, AI RISK RADAR, 우측 5탭 — 전부 되살리지 않는다. 참고할 것은 그 데모에 실려 있던 **자산의 성격**(백주 브랜드 같은 비부동산 건이 실재한다는 사실)뿐이다.

## 7. 미결 사항 (사업 판단 대기)

구현 전에 답이 필요한 것들이다. 임의로 정하지 말 것.

1. **활동 점수의 구산 기준** — 등급을 활동으로 올릴 수 있다고 화면에 적었으나, 무엇을 하면 몇 점인지, 등급별 목표치가 얼마인지 미정. 정해지기 전까지 화면에 수치를 넣지 않는다.
2. **상업형 상세의 전용 섹션** — 공통 골격 + 유형 전용 섹션 방식은 정해졌으나 상업형에 무엇을 넣을지 미정.
3. **레저형 필드** — 객실 수·부지 면적·운영 상태·편의시설·계절성. 데이터 수령 후.
4. **비부동산 사업 투자** — 프로젝트로 흡수하기로 했다. 물량이 쌓이면 그때 분리한다.
5. **거래 체결 수** — 랜딩 지표에서 0으로 나오므로 실제 체결이 생길 때까지 노출하지 않는다.
