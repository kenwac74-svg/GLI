# GLI-052 Claude Design 작업지시서

버전: 2026-10-07
작업명: AI 탐색 결과 화면 개선 (일반 AI 수준의 답 + GLI 확인 정보)
대상: 결과 화면 `/explore` (랜딩 검색 후 결과 포함). **PC 먼저, 모바일은 PC 확정 후 별도**
시각 설계 담당: Claude Design AI
기능 통합 담당: Codex
최종 승인: GLI Product Owner(기획자)
현재 상태: 디자인 작업 대기 (구성은 기획자 검토 완료, 이미지 시안은 미작성)
범위: 사내 비공개 기술 데모. 법률·제휴·사업 논의는 다루지 않는다.

## 1. 작업 목적

사용자가 같은 질문을 일반 AI(ChatGPT, Gemini 등)와 GLI에 했을 때 GLI가 더 낫다고 느끼게 만드는 결과 화면을 설계한다.
2026-10-07 모바일 실서비스 점검에서 확인된 문제는 다음과 같다.

- 질문을 보내면 입력창이 비고, 약 50초 동안 읽을 것이 없다. 진행 표시("3/4")는 실제 진행과 맞지 않는다.
- 답은 5~6문단의 긴 글 한 덩어리로 한꺼번에 나온다. 결론은 "자료에 확인된 후보가 없다"인 경우가 많다.
- 결과 영역에 "0건의 후보"가 뜨고 눌러 볼 것이 없다.
- 기획자 평가: 일반 AI가 더 빠르고 자연스럽고 친절하다.

목표 구조는 두 층이다.

1. **바닥선: 일반 AI 수준의 답.** 빨리 읽기 시작할 수 있고, 한 덩어리 글이 아니라 구역으로 정리되어 한눈에 들어온다.
2. **GLI의 몫: 그 위에 얹는 것.** GLI가 확인한 후보(등급, 출처 링크, 이미지), 비교·저장·상담 같은 다음 행동. 일반 AI는 줄 수 없다.

## 2. 기획자 검토 결과 (구성 시안 v1·v2)

구성 시안은 비공개 Artifact로 있으며, **구성만 보여 주는 것이고 시각 기준이 아니다.** 글자 크기와 색은 이 지시서와 `DESIGN-RULES.md`를 따른다.

- 현재 vs 목표 구성(모바일 기준): 구역 6개 모두 승인.
- PC 구성(왼쪽 대화 / 오른쪽 GLI 확인 후보): 좋음. 단 **기존 UI의 대폭 변경은 최소화**해야 하며 시안 그대로 적용하기는 어렵다.
- 결정 기록: `docs/research/P0-2_RESULT_SCREEN_DECISIONS.md`.

## 3. 현재 화면과 변경 최소화 원칙 (가장 중요)

### 3.1 현재 화면 캡처 (2026-10-07, glibiz.net)

- `GLI-052-assets/current-pc-home.jpg` PC 첫 화면
- `GLI-052-assets/current-pc-result.jpg` PC 결과 화면(답 도착 후, 질문: "프놈펜에서 월 700달러 이하 1베드 임대 찾아줘")
- `GLI-052-assets/current-mobile-waiting-8s.jpg` 모바일, 질문 8초 뒤

현재 PC 결과 화면에서 확인된 것은 다음과 같다. 새로 만들 것보다 **이미 있는 것을 고치는 쪽**이 변경이 작다.

- 대화 패널 안에 답이 글로 나온다. 같은 패널에 출처 칩과 **조건 태그**(캄보디아 프놈펜 · 임대 · 월 예산 700 USD · 1베드)가 이미 있다.

- 목록 오른쪽의 **이미지 칸이 비어 있다**(이미지가 없거나 로고로 대체됨).

### 3.2 원칙

- `source/gli-demo.dc.html`과 기존 CSS/시각 언어가 기준이다. 폰트, 색상 토큰, 카드 형태, 여백 체계, 헤더, 필터, 자산 카드, 다른 페이지는 바꾸지 않는다.
- 6.2의 "내 조건" 줄은 새로 만드는 것이 아니라 현재 조건 태그를 다듬어 확장하는 것으로 시작한다. 2단계 안(2열 배치)도 현재 패널과 목록 구조를 최대한 재사용한다.
- 새 화면을 처음부터 그리지 않는다. **현재 결과 화면(`현재 화면 캡처` 참고) 위에서 무엇을 더하고 무엇을 바꿔야 하는지**를 제안한다.
- 바꾸는 범위가 커질수록 제안을 두 단계로 나눈다. (1단계: 기존 UI를 거의 그대로 두고 응답 영역만 개선, 2단계: 대화/후보 2열 배치)
- 범위 밖 개선점은 구현하지 말고 별도 제안으로 기록한다.

## 4. 결과 화면 구성

답 영역은 위에서 아래로 다음 구역으로 정리한다. 모든 구역이 매번 나오는 것은 아니며, 내용이 없는 구역은 보이지 않는다.

| 구역 | 내용 | 표시 |
|---|---|---|
| 한 줄 결론 | 질문에 대한 답을 가장 먼저 한 문장으로 | 가장 눈에 띄게 |
| 지역/선택지 | 질문과 관련된 지역이나 선택지 2~3개와 짧은 설명 | **일반 정보** 표시, 이미지 있음 |
| 비교 | 선택지 두 개의 장단점을 두 칸으로 | **일반 정보** 표시 |
| 먼저 확인하세요 | 결정 전에 따질 것 | 6절 참고 |
| GLI가 확인한 후보 | 등급, 출처 링크, 이미지, 확인할 것, 비교·저장·상담 | **GLI 확인** 표시 |
| 이어서 물어보세요 | 다음 질문 | 6절 참고 |

핵심 규칙은 **"일반 정보"와 "GLI 확인"을 사용자가 눈으로 구분할 수 있어야 한다**는 것이다. 일반 정보는 GLI가 검증한 사실처럼 보이면 안 된다. 표시 문구와 모양은 Claude Design이 제안한다.

## 5. 이미지(썸네일) 규칙

출처에 따라 세 가지로 나눈다. 세 가지가 한 화면에 섞여 나오며 서로 구분 가능해야 한다.

| 대상 | 이미지 | 표시 |
|---|---|---|
| GLI가 확인한 후보 | GLI가 미리 입수해 DB에 둔 이미지 | 실제 매물 이미지 |
| 외부 사이트가 출처인 후보 | 그 사이트에서 가져온 이미지 | 실제 매물 이미지 |
| 일반 도시 정보(지역 카드) | 생성형 AI로 만든 도시 분위기 대표 이미지 | **실제 건물·방이 아님을 표시** (예: "도시 이미지") |

- 도시 대표 이미지는 특정 건물의 내부나 외형을 정확히 보여 주는 이미지가 아니다. 도시의 분위기를 시각화한 것이다.
- 이미지가 없을 때의 대체 표시와 이미지 로딩 중 표시(답은 먼저 나오고 이미지는 나중에 채워질 수 있다)를 포함한다.
- 이미지 생성 방식과 보관은 기능 연결 담당이 정한다. 디자인은 도시 대표 이미지의 **스타일 방향**(톤, 구도, 일관성)을 제안한다.

## 6. 버튼과 "내 조건"

### 6.1 버튼은 배우지 않아도 되는 UI여야 한다

- 사용자에게 "이 버튼을 누르면 이렇게 됩니다"라는 설명 문구가 필요한 구조는 실패로 본다.
- 버튼은 **한 종류**로 단순화하는 안을 우선 검토한다. 누르면 그 내용으로 바로 다음 질문이 이어진다.
- "먼저 확인하세요"에 어떤 정보를 띄울지는 **미결정**이다. 디자인은 설명 없이도 의미가 전달되는 표현을 제안하고, 내용은 기획자가 정한다.

### 6.2 "내 조건" 줄

- 지금 어떤 조건으로 결과를 보고 있는지 태그로 보여 주고, 하나씩 뺄 수 있다. 현재 화면의 조건 태그를 출발점으로 삼는다.
- 보여 줄 조건은 **시스템이 질문에서 이해해 실제 검색에 쓴 조건**만이다. (현재 서버가 이미 계산하는 값: 국가, 도시, 지역, 거래 유형, 자산 유형, 예산, 침실 수, 목적 등)
- 태그를 빼면 그 조건을 뺀 결과로 바뀐다. 처리 중 상태를 포함한다.

## 7. 후보가 없을 때

- 확인된 후보가 없어도 빈손으로 끝나지 않는다. 비슷한 조건의 대안이나 조건을 바꾸면 후보가 생기는 방향을 보여 준다.
- **"조사 요청" 버튼을 사용자 화면에 두지 않는다.** 조사 요청은 시스템과 사람의 업무이며 사용자에게는 보이지 않는다. 사용자가 보는 것은 "지금 확인된 것"과 "다음에 할 수 있는 것"뿐이다.
- 후보 없음 화면에 "0건"만 크게 보이지 않게 한다.

## 8. 처리 중 화면 (최우선 개선점)

- 질문을 보낸 뒤 사용자의 질문이 화면에 남아 있어야 한다.
- 첫 문장은 몇 초 안에 나오기 시작하는 것을 전제로 설계한다. 구역이 위에서부터 차례로 채워지는 모습을 시안에 포함한다.
- 실제 진행과 맞지 않는 단계 숫자("3/4" 같은 표시)를 쓰지 않는다.
- 현재는 대화 영역이 화면 아래쪽에 있어서 위에서 기다리는 사용자에게 보이지 않는다. 처리 중에 사용자가 읽을 수 있는 위치에 답이 나타나야 한다.

## 9. PC 지시 (먼저 확정)

- 1단계(기존 UI 최소 변경): 현재 상담 패널 안에서 글 덩어리를 구역별 카드로 정리하고, "추천 순위 TOP 3" 목록의 비어 있는 이미지 칸을 채운다.
- 2단계(제안): 왼쪽 대화, 오른쪽 "GLI가 확인한 후보"를 나란히 두는 배치. 후보가 오른쪽에 고정되어 대화를 읽는 동안 볼 수 있다.
- 두 단계의 차이와 변경 범위를 표로 비교해 기획자가 고르게 한다.

모바일은 PC 확정 후 별도 작업으로 한다. 모바일은 PC와 설계를 따로 해야 할 수 있다.

## 10. 필수 상태

- 질문 직후 / 첫 구역 도착 / 모든 구역 도착
- 후보 있음 / 후보 없음
- 이미지 로딩 중 / 이미지 없음
- 조건 태그 제거 후 다시 찾는 중
- 오류(답을 만들지 못함): 기계적 안내문 한 줄로 끝나지 않게 다음 행동을 보여 준다.

## 11. 접근성과 기존 규칙

- 사용자는 40~60대 투자자다. `DESIGN-RULES.md`의 **14px 미만 금지**를 따른다. (구성 시안은 작은 글자를 썼으므로 그대로 옮기지 않는다.)
- 색만으로 "일반 정보"와 "GLI 확인"을 구분하지 않는다. 문구나 모양을 함께 쓴다.
- 키보드와 화면 읽기 도구에서 구역 순서와 처리 중 상태를 알 수 있어야 한다.
- AI 공급사 이름(Gemini, OpenAI 등)을 화면에 노출하지 않는다.
- GLI가 확인하지 않은 가격, 수익률, 법적 상태를 확인된 사실처럼 보이지 않게 한다.

## 12. 기능 연결용 전제 (Codex 확인 사항)

디자인은 아래를 가정하되, 구현 가능 여부는 기능 연결 담당이 확인한다. 현재 응답은 하나의 `answer` 글과 `matches` 목록이다.

- 답을 구역별로 나눈 구조화된 응답과 순서대로 채우는 전달 방식(스트리밍)이 필요하다.
- 각 구역과 후보에 **일반 정보 / GLI 확인 / 외부 출처** 구분 값이 필요하다.
- 후보 카드에는 이미지 주소, 이미지 종류(DB / 외부 / 도시 대표), 출처 링크, 등급이 필요하다.
- "내 조건" 태그는 서버가 이해한 조건 값을 그대로 쓴다.
- 사용자의 검색·답변 기록은 시스템이 보관한다. 화면에 노출하지 않는다.
