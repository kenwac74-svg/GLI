## 1. 지시서 §5.2와 다른 부분 — 랜딩 입력창

**지시서**: 랜딩 히어로에 입력 가능한 요소를 두지 않는다.

**실제 적용**: 한 줄 입력창 1개를 두었다.

**이유**: 이 랜딩의 목적은 기능 제공이 아니라 마케팅과 후킹이다. AI가 핵심 기능인데 첫 화면에서 만져볼 수 없으면 "AI로 찾아준다"는 주장이 문구로만 남는다. Lofty·Propy 모두 히어로에 실제 입력 요소를 둔다. 사용자와 협의해 승인받았다.

**중복 회피 설계** — 지시서 §5.2의 취지는 지켰다.

| 랜딩 히어로 | 탐색 화면 |
|---|---|
| `<input>` 한 줄 | `<textarea>` 3행 + 실행 버튼 |
| 필터 없음 | 국가·거래유형 필터 레일 |
| 파이프라인 없음 | 4단계 파이프라인 |
| 예시 질문 칩 없음 | 예시 질문 칩 3개 |
| 결과 없음 | 결과 카운트·정렬·그리드 |
| 대화 없음 | 후속 대화 |

**동작**: 입력값을 들고 탐색 화면으로 이동한 뒤 거기서 검색을 실행한다. 랜딩에서는 검색하지 않는다.

```
startExplore()  →  query = hook  →  nav("home")  →  search(hook)
onHookKey(Enter) →  동일
```

**GPT 연결 제안** (판단은 GPT가):
- 입력값을 쿼리스트링으로 넘기는 방식 `/explore?q=<hook>`
- 탐색 화면 마운트 시 `q`가 있으면 자동 실행
- 값이 비어 있으면 검색 없이 `/explore`로만 이동 (현재 시안도 동일)

라우팅 방식은 GPT 재량이다. 훅 이름만 유지해 주면 된다.

## 2. DEMO 상태 전환 컨트롤

파이프라인 아래 `DEMO` 라벨이 붙은 칩 7개(`idle` `understanding` `searching` `reviewing` `composing` `complete` `error`)가 있다. 누르면 파이프라인이 해당 상태로 바뀐다.

**목적**: 지시서 §13의 검수 화면 13종 스크린샷을 대체한다. 스크린샷은 상태 조합마다 캡처가 필요해 비용이 크고, §16에서 "고해상도 전체 페이지 캡처는 전달하지 않는다"고 하여 산출물로도 쓰이지 않는다. 실제로 눌러 보는 편이 정확하다. 사용자 승인을 받았다.

**제거 방법**: 마크업의 `<div class="statedemo">…</div>` 블록과 로직의 `pickPipeState`, `state.pipeState`를 삭제하면 된다. 삭제 후 파이프라인은 실제 검색 상태에서 파생된다.

```js
// pipeVals() 내부 — pipeState가 null이면 실제 상태에서 파생
let st = s.pipeState;
if (!st) st = s.busy ? "searching" : (s.hits ? "complete" : "idle");
```

**API 연결 제안**: `s.pipeState` 자리에 검색 API의 진행 단계를 넣으면 된다. 시안은 `understanding`→`searching`→`reviewing`→`composing`→`complete` 순서를 가정한다. 단계가 실제와 다르면 `pipeVals()`의 `activeAt` 매핑만 고치면 된다.

`error` 상태는 2단계(`후보 탐색`)에서 실패하는 경우를 예시로 그렸다. 실패 단계는 `pipeVals()`의 `errAt` 상수로 결정된다. 실제로는 API가 알려준 실패 단계를 넣어야 한다.

### 신규

| 이름 | 발생 요소 | 전달 값 | 상태 변화 |
|---|---|---|---|
| `startExplore` | 히어로 주 CTA `<a>` | — | `query ← hook`, `view ← "home"`, 검색 실행 |
| `onHook` | 히어로 `<input>` | `e.target.value` | `hook` |
| `onHookKey` | 히어로 `<input>` | `e.key` | Enter 시 `startExplore` 동작 |
| `pickPipeState` | DEMO 칩 `<button>` | `data-v` | `pipeState` |

### CSS 클래스 계약 (지시서 §6.1)

```text
.pipe-step.is-idle     대기
.pipe-step.is-active   진행 중 (pulse, reduced-motion에서 정지)
.pipe-step.is-done     완료 (체크)
.pipe-step.is-error    오류
.pipe-mob              모바일 압축 표기 (≤768px에서만 표시)
.pipe-mob.is-error     모바일 오류
.pipe-err              오류 문구
```

`.pipe-step`의 번호 자리(`.pipe-n`) 내용도 상태에 따라 바뀐다: 숫자 → `✓`(완료) → `!`(오류). 색상만으로 구분하지 않기 위한 처리다 (지시서 §8.2).

## 6. 디자인 담당의 후속 제안 (구현하지 않음, 승인 대기)

지시서 §15에 따라 적용하지 않고 목록으로만 남긴다.

**제안 1 — 모바일 고정 CTA**
랜딩을 스크롤하면 주 CTA가 화면에서 사라진다. 하단 고정 CTA 하나가 전환에 유리할 수 있다. 다만 푸터 고지를 가릴 위험이 있어 safe-area 처리가 필요하다. 지시서 §15에서 승인 대상으로 지정된 항목이다.

**제안 2 — 파이프라인 일시정지 버튼**
지시서 §8.1이 언급한 ticker/marquee 정지 버튼. 현재는 hover·focus·reduced-motion으로만 멈춘다. 터치 기기에서는 정지 수단이 없다. 작은 일시정지 아이콘을 두면 해결되지만 새 버튼 추가라 승인이 필요하다.

**제안 3 — 히어로 입력창의 자동완성 힌트**
입력창에 국가·예산 예시를 순환 표시하는 placeholder 애니메이션. 후킹 효과는 크지만 reduced-motion 처리와 접근성 검토가 필요하다.

**제안 4 — 수익 시뮬레이터**
PREMIUM 등급의 가치를 자료 열람 이상으로 만드는 요소. `monthly`·`krw` 실데이터로 계산 가능하다. 이전 핸드오프(`DESIGN-RULES.md` §9)에서 이미 제안한 항목이다.

**제안 5 — 자산 사진 실사진 교체**
캄보디아 8건이 Unsplash 스톡이다. "검증"을 파는 서비스에서 메시지를 훼손한다. 디자인으로 해결할 수 없는 문제라 사업 측 결정이 필요하다.
