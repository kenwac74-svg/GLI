# GLI-051 Claude Design 작업지시서

버전: 2026-09-13  
작업명: 모바일 가로 잘림 제거와 핵심 화면 반응형 보정  
대상: 랜딩 `/`, 자산 탐색 `/explore`, 공통 헤더  
시각 설계 담당: Claude Design AI  
기능 통합 담당: Codex  
최종 승인: GLI Product Owner  
현재 상태: 디자인 작업 대기

## 1. 작업 목적

실제 Android Chrome 화면에서 랜딩 콘텐츠 오른쪽이 잘리고 페이지 전체에 가로 스크롤이 생긴다. 로컬 `/explore`에서도 같은 공통 헤더 때문에 동일한 문제가 재현된다.

이번 작업은 기존 Claude 디자인을 재설계하는 작업이 아니다. 승인된 브랜드와 화면 구성을 유지하면서 모바일에서 다음 결과를 만든다.

1. 페이지 전체의 가로 넘침을 제거한다.
2. 모바일 헤더의 필수 행동만 남겨 모든 버튼이 화면 안에 들어오게 한다.
3. Android 글자 확대 환경에서도 랜딩 제목과 지표가 잘리거나 겹치지 않게 한다.
4. 의도된 내부 가로 스크롤과 결함인 페이지 전체 가로 스크롤을 명확히 구분한다.

## 2. 확인된 재현 결과

2026-09-11에 로컬과 공개 사이트를 브라우저 뷰포트로 측정했다.

| 테스트 폭 | 문서 표시 폭 | 실제 문서 폭 | 초과 폭 |
|---:|---:|---:|---:|
| 360px | 345px | 434px | 89px |
| 390px | 375px | 434px | 59px |
| 412px | 397px | 434px | 37px |

확인된 현상:

- 모바일 헤더 오른쪽의 언어와 메뉴 버튼이 화면 밖으로 밀린다.
- 페이지 하단에 브라우저 전체 가로 스크롤이 생긴다.
- 실제 Android 화면에서는 랜딩 H1의 마지막 글자와 세 번째 통계 카드가 오른쪽에서 잘려 보인다.
- `/explore`의 예시 질문과 필터 칩은 내부 가로 스크롤로 설계되어 있으나, 공통 헤더의 넘침 때문에 페이지 전체도 함께 움직인다.

## 3. 원인

현재 반응형 규칙은 1024px 이하에서 `.nav-links`를 숨기고 `.mobile-menu`를 표시한다. 그러나 헤더 우측의 다음 요소는 그대로 유지된다.

- 관심자산 버튼
- 로그인 버튼
- 언어 전환 버튼
- 모바일 메뉴 버튼

480px 이하 규칙은 간격과 공통 버튼 padding만 줄이므로 필요한 전체 너비를 해소하지 못한다. 랜딩 H1도 1000px 이하에서 `42px`로 고정되고 더 작은 휴대전화용 단계가 없다.

관련 현재 규칙:

```css
@media(max-width:1024px) {
  .nav-links { display:none }
  .mobile-menu { display:block }
}

@media(max-width:480px) {
  .nav-in { gap:10px }
  .btn { padding:0 16px }
}
```

`body { overflow-x:hidden }`만 추가하는 방식은 사용하지 않는다. 원인을 남긴 채 버튼과 내용을 잘라내므로 완료로 인정하지 않는다.

## 4. 변경 허용 범위

Claude가 수정할 수 있는 범위:

- 모바일 공통 헤더의 표시 우선순위와 배치
- 모바일 랜딩 H1 크기·줄높이·자동 줄바꿈
- 모바일 랜딩 통계의 축약 배치와 글자 줄바꿈
- 모바일 컨테이너의 `min-width`, `max-width`, overflow 규칙
- 의도된 내부 가로 스크롤의 시각적 단서
- 위 변경에 직접 필요한 접근성 속성

다음은 변경하지 않는다.

- 랜딩 헤드라인과 본문 문구
- GLI 로고, 색상, 폰트 계열, 카드 모양과 기본 디자인 토큰
- 자산·가격·Trust 등급·멤버십·회사 정보
- 랜딩과 `/explore`의 역할 구분
- 데스크톱 내비게이션의 메뉴 구성
- API, 검색, 크롤러, 데이터와 React 코드
- 승인되지 않은 새 섹션, 새 마케팅 문구 또는 새 이미지

범위 밖의 개선점은 구현하지 말고 `IMPLEMENTATION-NOTES.md`에 별도 제안으로 기록한다.

## 5. 모바일 헤더 지시

### 5.1 권장 구성

768px 이하에서는 다음 세 요소만 첫 줄에 유지한다.

1. GLI 로고
2. 관심자산 아이콘 버튼
3. 햄버거 메뉴 버튼

로그인과 언어 전환은 이미 모바일 메뉴 안에 있으므로 첫 줄에서는 숨긴다. 메뉴에서 해당 기능에 접근할 수 있어야 한다.

헤더 요구사항:

- 320px에서도 모든 표시 요소가 한 줄 안에 들어온다.
- 로고는 찌그러뜨리지 않는다.
- 관심자산과 메뉴의 터치 영역은 각각 최소 `48×48px`이다.
- 모바일 메뉴는 오른쪽 화면 경계를 넘지 않는다.
- 메뉴가 열렸을 때 내부 세로 스크롤과 safe area를 유지한다.
- 헤더의 버튼을 가로 스크롤시키지 않는다.

Claude가 다른 구성이 더 적합하다고 판단하면 구현 전에 다음을 별도 제안한다.

- 화면에 남길 요소와 메뉴로 이동할 요소
- 320px에서의 예상 너비 합계
- 기존 권장 구성보다 나은 이유

## 6. 랜딩 히어로 지시

- 헤드라인 문구는 그대로 유지한다.
- 768px 이하에서는 기존 `<br>`을 비활성화하고 자연스러운 줄바꿈을 사용한다.
- 480px 이하에는 별도 H1 크기와 줄높이를 지정한다. 시작 검토값은 `36px / 1.18`이며 Claude가 육안 검수 후 확정한다.
- 360px 이하에서 추가 단계가 필요하면 고정 breakpoint 값으로 제안한다. `vw` 기반 글자 크기는 사용하지 않는다.
- `word-break:keep-all`을 유지하되, 글자 확대 시 긴 구절이 컨테이너 밖으로 나가지 않아야 한다.
- 좌우 여백은 기존 모바일 `20px` 체계를 우선 유지한다.
- CTA 문구와 버튼 높이, 색상, 아이콘은 변경하지 않는다.

## 7. 통계와 내부 스크롤 지시

랜딩 통계 3개는 가능하면 한 줄 축약형을 유지한다. 단 다음 조건이 우선이다.

- 숫자와 레이블이 카드 밖으로 나오지 않는다.
- 세 카드의 높이와 숫자 기준선이 동일하다.
- Android 글자 크기 130%에서 겹침이 없어야 한다.
- 320px에서 3열이 불가능하면 `2+1` 또는 한 줄 내부 스크롤을 시안으로 제안하고 변경 이유를 기록한다.

다음 요소의 내부 가로 스크롤은 유지할 수 있다.

- `.prompt-row`
- `.frail`
- `.tiers`
- `.thumbs`
- 비교표 스크롤 래퍼

내부 스크롤은 문서 전체 폭을 늘리지 않아야 한다. 다음 항목 일부가 보이거나 약한 가장자리 fade가 있어 터치 사용자가 스크롤 가능성을 알 수 있게 한다.

## 8. 기술 계약

Claude는 `design-handoff/source/gli-demo.dc.html`만 시각 원본으로 수정한다. React, 생성 파일과 API 코드는 수정하지 않는다.

다음 기존 계약은 유지한다.

- 공통 헤더의 `data-action` 값
- `goFav`, `goSoonMy`, `goSoonLang`과 모바일 메뉴 이벤트
- 랜딩 `startExplore`, `goTrust`
- `/explore` 검색·필터 이벤트 훅
- 기존 클래스 이름은 가능한 한 유지하고 새 클래스가 필요하면 목록으로 제공

Codex는 승인 후 다음만 수행한다.

- 원본으로부터 React 정적 화면 재생성
- 승인된 클래스와 상태 연결
- 라우팅·이벤트 연결 확인
- 지정 뷰포트 회귀 검수

## 10. 수치 기반 완료 기준

각 지정 화면에서 다음 스크립트 결과가 `true`여야 한다.

```js
document.documentElement.scrollWidth <= document.documentElement.clientWidth
```

완료 조건:

- 페이지 전체 가로 스크롤이 없다.
- 헤더 요소가 잘리거나 겹치지 않는다.
- 랜딩 H1의 모든 글자가 보인다.
- 통계 카드와 CTA가 화면 안에 들어온다.
- 내부 스크롤 요소는 자체 영역 안에서만 움직인다.
- 48px 터치 영역과 16px 입력 글자 기준을 유지한다.
- 키보드 포커스와 메뉴 접근성이 유지된다.
- 1440px 데스크톱 화면은 이번 허용 범위 밖에서 육안 차이가 없다.
- 문구·데이터·색상·기능 동작은 변경되지 않는다.

## 11. 납품물

Claude는 다음 파일과 캡처만 전달한다.

```text
design-handoff/source/gli-demo.dc.html
design-handoff/CHANGELOG-GLI-051.md
design-handoff/IMPLEMENTATION-NOTES.md
design-handoff/FILE-HASHES.txt
```

필수 보고 내용:

- 변경한 CSS 선택자와 변경 이유
- 새 클래스 또는 DOM 훅
- 원본과 육안으로 달라진 모든 요소
- 의도적으로 변경하지 않은 영역
- 각 테스트 폭의 `clientWidth`, `scrollWidth`, 통과 여부
- 320/360/390/412/768/1440px 캡처

이미지와 생성 파일이 바뀌지 않았다면 다시 전달하지 않는다. `support.js`는 시안 실행용이며 제품 React 코드로 전달하지 않는다.

## 12. 승인과 구현 순서

1. Claude가 이 문서에 따라 HTML/CSS 시안을 작성한다.
2. Claude가 육안 차이 목록과 캡처·측정값을 제출한다.
3. GLI Product Owner가 디자인을 승인한다.
4. Codex가 승인된 변경 구간만 검토한다.
5. Codex가 생성기를 실행하고 React 이벤트를 연결한다.
6. 로컬에서 동일 뷰포트를 재검수한다.
7. GLI Product Owner의 별도 승인 뒤에만 공개 배포한다.

디자인 승인 전에는 Codex가 임의 CSS 보정, 생성 파일 갱신 또는 공개 배포를 하지 않는다.
