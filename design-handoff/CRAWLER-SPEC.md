# CRAWLER SPEC — 2026-08-26

현재 목업의 자산 16건은 전부 하드코딩이다. 크롤링은 없다. 이 문서는 무엇을 수집하고 무엇을 수집하지 않는지, 수집한 값을 어떻게 화면 필드로 옮기는지를 정한다.

---

## 1. 원칙

**출처를 잃은 값은 화면에 올리지 않는다.** GLI가 파는 것이 검증이므로, 어디서 왔는지 모르는 데이터는 자산으로서 가치가 없다. 수집한 모든 필드는 출처 기록(`DATA-MODEL.md` §3)을 남긴다.

**덮어쓰지 않는다.** 같은 필드에 다른 값이 들어오면 최신 값으로 갈아치우는 대신 둘 다 남기고 `conflict_with`로 연결한다. 불일치는 지워야 할 오류가 아니라 등급을 내리는 정보다.

**모르는 것을 채우지 않는다.** 값이 없으면 필드를 비우거나 `"조사 예정"`을 넣는다. AI에게 추정하게 하지 않는다.

**크롤링은 부동산만이다.** 프로젝트는 전부 손입력이다(§5).

---

## 2. 수집 대상

| 종류 | 예 | 얻는 것 |
|---|---|---|
| 시행사 자료 | Fact Sheet, 브로슈어, 가격표 | 세대수·타입·면적·완공일·개발사·가격 |
| 인허가 공개 정보 | 개발면허, 광고허가 | 인허가 단계, 권리 관계 |
| 현지 중개 매물 | 파트너사 리스팅 | 매물 단위 가격·면적·거래 유형 |
| 지도·인프라 | 공항·병원·역까지의 거리 | 도시 계층 인프라 (`REGION.city`) |
| 뉴스·보도 | 개발 계획, 시장 동향 | 주변 개발 계획 (`checks[]` 항목 확인용) |

**수집하지 않는 것**

- 국가 단위 현황 정보 — 치안 지수, 정치 안정성, 시장 전망. 고객에게 알리지 않는 계층이므로 수집할 이유가 없다. 지역 등급의 내부 입력이 필요하면 사업 측이 기준점을 정한다.
- 구역·블록 단위 생활 정보 — 데이터로는 찾을 수 없다. 사람이 가야 나오고, 그것이 GLI의 고유 가치다. 크롤러가 흉내내면 제품의 근거가 무너진다.
- 개인 식별 정보 — 주민 코멘트는 익명 처리된 상태로만 저장한다.

## 3. 파이프라인

```
발견  →  수집  →  정규화  →  대조  →  게시 대기  →  전문가 확인  →  게시
```

| 단계 | 처리 |
|---|---|
| 발견 | 대상 URL·문서 등록. 파트너사 자료는 관리자가 업로드 |
| 수집 | 원문 저장. HTML·PDF 원본을 버리지 않는다 |
| 정규화 | LLM으로 필드 추출. 출력 스키마는 `DATA-MODEL.md` §2 |
| 대조 | 기존 값과 비교. 불일치는 `conflict_with`에 기록 |
| 게시 대기 | 등급 계산. 필수 필드 미충족이면 대기 유지 |
| 전문가 확인 | 원본·현장 확인. `verified_by`, `verified_at` 기록 |
| 게시 | 공개 |

**원문을 버리지 않는 것이 조건이다.** 등급이 "자료가 얼마나 검증되었는가"를 재므로 원문 대조가 안 되면 등급을 계산할 근거가 없다.

### 정규화 프롬프트의 요구 사항

```
- 문서에 명시된 것만 추출한다. 없는 값은 null로 둔다.
- 추정·보간·상식 보충을 하지 않는다.
- 각 값이 문서의 어느 부분에서 나왔는지 위치를 함께 반환한다.
- 통화 단위와 면적 단위를 원문 그대로 유지한다. 환산은 후처리한다.
```

"자료상 미표기", "조사 예정"이 정상적인 결과값이다. 목업의 16건 중에도 `permit:"자료상 미표기"`, `done:"조사 예정"`인 건이 여럿 있다. **빈칸을 부끄러워하지 않는 것**이 이 제품의 성격이다.

## 4. 주기와 갱신

| 항목 | 주기 | 이유 |
|---|---|---|
| 가격·재고 | 잦게 | 가장 빨리 낡는다. `checks[]`에 "현재 가격·재고"가 반복 등장 |
| 인허가 단계 | 월 | 상태 변화가 등급에 직결 |
| 완공 예정일 | 분기 | 지연이 잦다 |
| 도시 인프라 | 반년 | 잘 안 바뀐다 |
| 시행사·권리 | 변동 시 | 이벤트 기반 |

`docDate` 경과가 등급 입력이다. 갱신이 멈춘 자산은 등급이 자연히 내려가야 한다 — 한 번 A를 받은 자산이 2년 뒤에도 A인 것은 거짓이다.

## 5. 프로젝트는 크롤링하지 않는다

프로젝트 자산은 전부 GLI가 손수 입력한다. 관리자가 표시 템플릿(A~D)을 고르고 내용을 기입해 공개한다. 상세는 `DATA-MODEL.md` §6.

이유: 프로젝트는 현지에 가서 파트너사와 사람을 만나다 알게 된 사업 기회다. 공개 자료가 애초에 없다. 크롤링할 대상이 존재하지 않는다.

그래서 신뢰 표기의 성격도 다르다. 부동산은 "AI가 모으고 전문가가 확인"이지만 프로젝트는 출처가 GLI 자신이라 교차 확인할 대상이 없다. **부동산의 문구를 그대로 쓰지 말 것.** 약점이 아니라 다른 종류의 근거다.

프로젝트에서 등급이 재는 것도 자료 검증이 아니라 리스크다. 계산 입력은 사업 주체의 규모·이력·계약 확인 여부, 계약 구조의 법적 지위, 실적 자료 확보 정도, 인허가 단계다.

---

## 6. 조사량과 조사 우선순위

지역 기록(`REGION.items`, `REGION.say`)은 크롤링 산출물이 아니라 **사람이 현지에서 만든 기록**이다. 크롤러는 여기에 쓰지 않는다.

기록이 0건인 자산은 0으로 표시된다. 숨기지 않는다.

- 고객에게는 "별로 알려지지 않은 곳"이라는 정직한 정보다.
- GLI에는 조사 우선순위 신호다. **기록이 0인데 조회수가 쌓이는 자산은 조사해야 할 대상이다.**

구현 시 조회수를 자산 단위로 집계해 관리툴에서 볼 수 있게 하면, 크롤링이 닿지 않는 영역의 조사 계획이 데이터로 잡힌다. 관심 등록 시 사람이 조사하는 기존 방침을 조회수까지 확장하는 것이다.

## 7. 실행 환경 (기능 목업 단계)

브라우저에서 외부 사이트를 직접 fetch하면 CORS로 막힌다. 선택지:

1. **정적 JSON 사전 생성** — 크롤러를 별도로 돌리고 산출물만 앱에 싣는다. 목업 단계에서 가장 현실적이다.
2. **프록시 서버 함수** — 대상 URL을 받아 HTML을 되돌려주는 함수 하나.
3. **웹 접근 가능한 LLM에 URL 전달** — 수집과 정규화를 한 번에. 다만 원문 대조가 안 되므로 §1의 원칙을 지키기 어렵다. 출처 URL과 수집 시각은 반드시 남길 것.

1번을 택해도 스키마와 출처 기록은 실서비스와 같게 만들어 둘 것. 나중에 크롤러를 붙일 때 데이터 이관이 없어야 한다.
