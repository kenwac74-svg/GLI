# GLI SNS 정보 출처 기획회의

날짜: 2026-10-01 (Asia/Seoul)
상태: 논의 중. 개발 지시서, 확정 정책 또는 수집 승인서가 아니다.

## 회의 목적과 경계

- 핵심 질문: Facebook 공개 부동산 그룹 등을 GLI의 지속적인 정보
  출처로 활용할 수 있는가? 직접 크롤링이 어렵다면 화면 캡처로
  정보를 확보하고 자동 정리하는 구조가 가능한가?
- 특정 링크를 지금 읽을 수 있는지와 장기 자동 수집 가능성을 구분한다.
- 수동 캡처는 추출 품질을 검증하는 실험안이지 최종 운영안으로 확정한
  것이 아니다. 협력 중개사 등록 방식도 대안이며 사용자 채택 전이다.
- 개발 채팅은 구현을 담당하고 별도 기획 채팅은 시나리오와 의사결정만
  다룬다. 코드/설정/키 변경, 자동 수집 실행, 계정 연결, 유료 API 시험,
  커밋/푸시/공개 배포는 이 회의만으로 허용하지 않는다.

## 현재까지 확인한 내용

- 사용자는 제공한 Facebook 그룹이 공개 그룹이라고 설명했다.
- 공유 링크와 확인된 실제 그룹 주소 모두 Codex in-app 브라우저에서
  로그인 화면으로 이동했다. 게시물 본문은 읽지 못했다. 이 결과로
  그룹 비공개 또는 특정 봇 차단 원인을 확정하지 않는다.
- 정상적으로 표시되는 화면을 캡처해 OCR/AI로 구조화하는 파이프라인은
  기술적 설계가 가능하다. 단 이 그룹에서 실제 수집/추출 시험은 안 했다.
- 캡처는 읽을 수 있는 화면의 정보 추출 방법이다. 접근 거부 자체를
  해결하는 방법으로 간주하지 않는다. 탐지 회피/접근 제한 우회는 제외한다.
- Meta 공식 설명은 무허가 자동 수집을 제한한다. 공개 열람, 자동 수집,
  이미지 재게시 권한은 각각 구분해야 한다. 캡처라는 형식만으로 자동
  수집 허가가 생기는 것은 아니라는 것이 현재 검토 의견이다.
- Groups API 폐지 주장은 미니가 제시했으나 공식 변경 문서 직접 조회는
  429로 실패했다. 검증 완료된 API 경로가 있는 것으로 기록하지 않는다.

## 시나리오 분기

| 안 | 성립 조건 | 검증할 내용 |
|---|---|---|
| A 직접 웹 수집 | 허용된 접근과 게시물 응답 확보 | 필드/링크/날짜, 페이지 누락, 갱신 안정성 |
| B 자동 브라우저 캡처 | 정상 렌더링, 허용된 자동 접근 | 펼치기/스크롤, 중복, 화면 변화, 처리 시간 |
| C 수동 캡처 후 자동 처리 | 권한 있는 표본과 원문 링크 확보 | OCR/추출 정확도, 단건 비용, 검수 작업량 |
| D 협력자 원자료 제출 | 중개사 참여와 이용/게시 동의 | 참여율, 자료 표준화, 신규/수정/거래완료 갱신 |

공통 검토 구조: 원문/권한/수집시각 -> 식별/중복 판정 -> 변경분만 처리
-> 가격/통화/지역/매매·임대 추출 -> 번역/관측 환율 환산 -> 검수
-> DB 반영 -> 만료/재확인. 모든 화면을 매번 LLM에 보내는 안은 피한다.
가격이 보증금/할부금/총매매가/월세인지, 동일 호실인지, 거래 완료인지
불명확하면 추측하지 않는다. 광고는 임대계약/순수익 검증 자료가 아니다.

## 미니 협업 관찰

- 기존 Gemini 대화: https://gemini.google.com/app/4eef3ca59310ee40
- Codex의 자동 입력 요청은 세 차례 일반적인 능력 밖 응답을 받았다.
- 마지막 거절 바로 뒤에 동일 내용의 질문이 다시 게시됐고 상세 답변이
  나왔다. 사용자는 수동 입력이라고 설명했다. 현재 화면에서 두 질문의
  내용과 응답 차이는 확인했으나 내부 요청/차단 원인은 알 수 없다.
- 따라서 단순히 질문 길이 때문이라고 결론내릴 수 없다. '다른 AI의
  지시를 인식하여 거부한다'는 가설도 아직 확정하지 않는다.
- 미니 제안: 캡처 추출은 가능, 접근 문제와 별개, 15~20건으로 가격·통화·
  거래유형·위치 추출과 비용을 먼저 측정. 이는 제안이며 승인/실행 전이다.
- 미니의 '수동 캡처 위험 0', '이미지 처리 비용 수십 배', '즉시 차단'
  등 단정은 독립 검증 없이 사실이나 정책으로 채택하지 않는다.

## 다음 회의에서 결정할 사항

1. 원하는 자료량·갱신 주기와 수동 작업 허용 범위.
2. 접근 가능한 표본, 사용/공개 범위와 권한 확보 방식.
3. 작은 추출 실험의 승인 여부 및 정확도·비용·누락률 평가 기준.
4. 실험 결과에 따른 A/B/C/D 선택과 개발 채팅에 전달할 승인 항목.
