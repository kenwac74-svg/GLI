# GLI 사람 보조형 데이터 수집·갱신 및 어드민 기획

날짜: 2026-10-01
상태: 기획 초안. 어드민/수집 에이전트 구현이나 운영 시작 승인이 아님.
관련: RAW-DATA-ACQUISITION-REVIEW-20261001.md

## 전제와 목적

완전 자동 실시간 크롤링을 전제하지 않는다. 사람이 캡처·자료 등록·
갱신에 참여하되 반복 작업은 최대한 시스템이 수행한다. 현재 GLI에는
이 운영 어드민이 없으며 아래는 추후 어드민 설계에 반영할 요구사항이다.
목표는 자동화율 자체가 아니라 최신의 유효한 매물을 적은 노동으로 확보하는 것이다.

## 역할 분리

| 단계 | 시스템/AI가 돕는 일 | 사람이 필요한 상황 | 결과 |
|---|---|---|---|
| 출처 등록 | URL 정규화, 국가/채널 분류, 중복 출처 탐지 | 수집·이용 범위 결정, 작성자/운영자 동의 확보 | 출처 카드 |
| 주소 발견 | 승인된 범위 검색, 페이지 내 상세 링크 추출, 후보 URL 목록 | 검색 밖의 비공개 링크 제공, 채널 가입 승인 | URL 큐 |
| 접근 확인 | 페이지 열기, 표시 여부 확인, 접근 실패 분류 | 로그인/MFA/CAPTCHA, 초대·승인 절차 | 접근 가능/사람 필요/중단 |
| 캡처 | 허용된 화면 스크롤·펼치기·캡처, URL/시각 동시 기록 | 앱 전용 화면, 도구 접근 불가 화면, 누락 구간 보완 | 원자료 묶음 |
| 자료 정리 | OCR/텍스트 추출, 매물별 분리, 연락처 등 민감정보 표시 | 서로 다른 글이 섞였거나 이미지가 불명확할 때 분리 확인 | 추출 초안 |
| 필드 추출 | 가격/통화/기간/면적/지역/매매·임대 추출, 번역, 환율 환산 | 보증금/할부금/총액 등 원문 자체가 모호할 때 확인 | 구조화 후보 |
| 중복·변경 | ID/URL/해시 비교, 동일 호실 후보와 변경 필드 표시 | 다른 호실인지 애매할 때 병합/분리 결정 | 신규/변경/동일/의심 |
| 등록 검수 | 누락·충돌 필드만 강조, 근거 화면 바로 연결 | 초기 게시 승인, 중요 가격·거래유형 충돌 판단 | 게시/보류/제외 |
| 갱신 | 재확인 대상 예약, 재방문·변경 비교, 확인 문안 초안 | 중개사 연락, 실제 판매/임대 완료 확인 | 최신/미확인/완료 |

주소 확보와 캡처도 모든 플랫폼에서 항상 가능하지 않다. 현재 브라우저
도구는 접근 가능한 페이지에서 보조할 수 있으나 무인 상시 수집 서비스가
아니다. 추후 작업 실행기와 스케줄러는 별도 구현한다. 접근 제한을 우회하지 않는다.

## 기본 운영 흐름

1. 운영자가 출처와 허용 범위·담당자·희망 갱신 주기를 등록한다.
2. 시스템이 주소 후보를 모으고 이미 처리한 주소를 먼저 제외한다.
3. 접근 가능한 자료는 캡처/다운로드하고 실패한 자료만 사람 큐로 넘긴다.
4. 사람이 확보한 캡처도 같은 수신함으로 드래그하거나 링크와 함께 등록한다.
5. 시스템이 신규/변경 자료만 추출·번역·태그화한다.
6. 운영자는 예외와 중요 필드만 확인해 등록 승인한다.
7. 다음 확인일에 시스템이 다시 확인하고, 연락이 필요한 건만 담당자에게 배정한다.

자료 확보 방식이 자동/수동인지와 매물 신뢰도는 별개다. 캡처만으로
실제 매물 존재, 소유권, 외국인 취득 가능성, 실제 임대수익을 확정하지 않는다.

## 향후 어드민 필수 기능

- 출처 관리: URL, 국가, 채널, 이용 범위/근거, 접근 방식, 담당자, 갱신 주기.
- 통합 수신함: URL·이미지·PDF·CSV 묶음 등록. 링크 없는 캡처는 출처 보완 큐.
- 수집 작업 큐: 예약/실행/완료/사람 필요/실패, 실패 이유와 재시도 이력.
- 검수 화면: 원문/캡처와 추출 필드를 나란히 비교, 근거 위치 표시.
- 변경 검수: 이전 값과 새 값, 가격/통화/거래상태 변경을 우선 표시.
- 예외 큐: 접근 필요, OCR 불명확, 가격 충돌, 중복 의심, 갱신 기한 초과.
- 일괄 처리: 같은 출처·같은 문제 묶음 승인. 중요 충돌은 별도 확인.
- 담당자 작업함: 현지 확인/연락 요청, 답변·증빙 등록, 재확인 날짜.
- 감사 이력: 누가 무엇을 수정/승인했는지, 이전 원자료/필드 버전 보존.
- 권한: 자료 확보 담당, 검수 담당, 게시 승인 담당을 구분하는 설계.

이는 기능 요구사항이며 UI 디자인은 Claude Design과 사용자 승인으로 확정한다.

## 최소 데이터와 상태

원자료에는 sourceId, 원문 URL 또는 제출 경로, 원문 게시시각(확인된 경우),
capturedAt, lastCheckedAt, 수집 담당/방식, 원본 파일, 내용 해시,
이용 범위 근거, 추출 버전, 필드별 근거와 확인 상태를 연결한다.
캡처 시각과 원문 게시 시각을 혼동하지 않는다.

자료 처리 상태: 접수 -> 추출 -> 검수 필요 -> 게시 가능/보류/제외.
매물 상태: 모집 중(출처 주장)/상태 미확인/거래 완료/재확인 필요.
페이지 소실만으로 거래 완료를 확정하지 않는다. 미확인 값을 AI로 채우지 않는다.
만료·보관 기간과 자동 게시 범위는 향후 별도 승인한다.

## 사람 작업을 줄이는 장치

- 운영자는 출처·검색 조건을 한번 등록하고 다음 회차에 재사용한다.
- URL/ID/파일 해시로 동일 자료를 걸러 OCR와 LLM 재처리를 줄인다.
- 구조화 데이터/텍스트 파서를 우선하고 이미지나 애매한 필드만 AI로 보낸다.
- 번역은 원문·버전 단위로 캐시한다. 가격 변경 시 전체를 재번역하지 않는다.
- 확인이 필요한 이유와 선택 가능한 조치를 한 작업 카드에 모은다.
- 중개사 확인 메시지는 자동 작성하되 발송 승인/계정 권한을 별도로 둔다.
- 반복 예외는 다음 회차 규칙으로 바꾸되 AI 제안을 검수 없이 전역 적용하지 않는다.

## 시험과 승인 항목

자동 웹, 사람 캡처, 정기 파일 각각의 표본으로 다음을 측정한다:
유효 매물 수, 매물당 사람 작업시간, 가격/통화/거래유형 정확도,
캡처 누락률, 중복 오병합률, 갱신 지연, 매물당 처리 비용.
표본 수와 수치 목표는 아직 확정하지 않았다.

실행 전 사용자 승인: 첫 출처·표본 범위, 이용 권한, 담당자,
게시 검수 범위, 재확인 주기, 비용 한도. 기획 단계에서 이 값을 임의 확정하지 않는다.
이번 작성에서는 계정 연결/수집/유료 API 호출/제품 코드 변경/배포를 하지 않았다.
