# 무료 기본 정보 1차 검수

## 범위와 상태

- 사용자 승인: 한국인이 처음 매물을 살펴볼 때 필요한 직관적인 기본 정보부터 재검증한다.
- 데이터/소스 읽기 전용 검수. 새 수집, 유료 AI, 제품 코드/디자인/설정 변경, 배포는 실행하지 않았다.
- 로컬 D1 `discovered_assets`를 SQLite 읽기 전용으로 조회했다. 공개 DB와 동일하다고 간주하지 않는다.
- localhost:8776 연결 거부. 실제 무료 화면 렌더링, 한국어 번역 캐시와 원화 환산은 이번에 검증하지 못했다.
- 캄보디아/베트남 각 원문 URL 1건의 웹 읽기는 실패했다. 원문 대비 수집 정확도 검수는 미완료다.
- 아래 정보 층위는 검수 기준 제안이지 신규 요금제/공개 정책 승인이나 구현 지시가 아니다.

## 우선 확인할 문제

1. **정보 보존 경로:** `db/discovery-repository.ts`는 `mapListingRowToAsset` 반환값을 기준으로 저장한다. 다중 사진/수집 시각/최대 가격은 다시 붙이지만 `detailFacts`, `assetCategory`, `offerLabel`, `priceLabel`, `publicationBasis`, `documentDateLabel`, `publicResources`는 복원하지 않는다. 수집기가 만들었던 제원/분류가 저장 후 사라질 수 있다. 영향은 해당 필드가 있는 수집 경로에 한정한다.
2. **상세 설명 부족:** 베트남 42건 모두 요약이 제목과 동일하다. 목록 식별에는 사용 가능하지만 상세 검토에 추가 정보를 주지 못한다. 대표 사진 1장만 저장되어 있어 내부 상세에서 여러 사진을 비교할 수도 없다.
3. **자료 시점 혼동:** `lib/cambodia-live-discovery.ts`는 수집 시각을 `updatedAt`에 넣는다. 베트남은 원문 갱신일을 공란으로 보존한다. 기본 상세는 `updatedAt`을 날짜로 표시하는 반면 `sourceObservedAt`을 별도 표시하지 않는다. 원문 갱신일/GLI 확인일/미확인을 구분할 필요가 있다. 베트남 공란의 실제 렌더링은 미검증이다.
4. **미확인 침실과 Studio 혼동 위험:** 저장 매핑은 null 침실을 0으로 바꾸고 카드/상세는 0을 Studio로 표시한다. 이번 56건에는 침실 0이 없어 실제 오표시 표본은 발견하지 못했다. Dot Property 파서는 미확인 침실/욕실/면적을 가진 카드를 제외하므로 모든 매물에 발생한다고 일반화하지 않는다.
5. **무료 한국어/원화 표시:** 코드 경로는 있으나 실제 화면 성공은 미검증이다. 원화는 환율 API의 값과 기준 시각, 원문 통화와 거래 단위를 함께 확인해야 한다. 고정 환율이나 AI 추정 숫자를 대안으로 넣지 않는다.

## 기본 정보 검수 기준 제안

- 목록: 대표 사진, 읽기 쉬운 제목, 국가/도시/지역, 유형, 매매/임대, 원문 가격+통화+월 단위 여부, 원화 참고가격, 면적, 침실/욕실, 출처/확인 시점.
- 상세: 추가 사진, 원문 설명, 층/준공·입주/가구/보증금·관리비 등 원문에 있는 기본 제원, 출처 링크, 게시·갱신·확인 시점 구분.
- 미확인 필드는 사실값으로 채우지 않는다. 층수 등 제원이 없다는 이유만으로 가격/위치가 있는 모든 매물을 숨기는 정책을 새로 도입하지 않는다.
- 순수익·외국인 취득 가능 여부·권리 검증은 기본 매물 식별과 구분한다. 포털 기재 사실과 GLI 검증을 혼동하지 않는다.
