# GLI 구조 기획회의 연구 안건

날짜: 2026-10-02 (Asia/Seoul)
상태: 연구·논의 대기. 구현 지시서나 확정 정책이 아니다.

## 목적과 운영 경계

- 사용자 목표: 인간 전문가처럼 의도를 이해하고 후보를 먼저 제시한 뒤, 중요한 질문 하나로 범위를 좁혀 선택을 돕는 상담.
- JEV나 특정 모델 활용이 목적이 아니다. 속도·정확성·최신성·근거·비용의 균형을 실제 GLI 업무에서 검증한다.
- 구조 기획회의는 별도 포크 채팅에서 진행한다. 이 개발 채팅과 같은 저장소를 읽되 제품 코드·설정·키·DB·UI·수집 실행·유료 API·커밋·푸시·배포를 변경하지 않는다.
- 각 안건을 하나씩 논의하며 사용자 승인/보류/기각을 구분한다. 승인은 구체적인 범위에만 적용하고, 개발 적용은 별도 지시로 인계한다.
- 본 문서와 세 자문의 제안은 기존 정책을 덮어쓰지 않는다. 승인 전에는 registry나 실행 정책을 새 설계로 수정하지 않는다.

## 논의 출발점

- 현재 GPT Sites 공개 데모, D1 저장, KH/VN/PH 제한 출처 수집. AWS는 장기 목표이며 Firebase는 아직 이전 전이다.
- P56은 매 실제 검색에서 성공 캐시를 재사용하지 않고 외부 목록을 재조회하며, 직접 collector와 Gemini를 병렬 실행한다. 기존 후보가 충분해도 scout를 생략하지 않는다.
- 다만 최종 답변은 외부 결과를 기다린다. Gemini 탐색 30초는 코드의 제한이며 플랫폼 전체 요청 한계로 확인된 사실이 아니다.
- 최근 공개 시험: 직접 조회115건 + Khmer24 snapshot2건, Gemini 탐색30초 중단. 신규 매물117건이나 수익 검증117건으로 해석하지 않는다.
- 환율·주요 필터는 이미 서버 코드에서 처리한다. 수익 근거 부족과 후보 화면 노출 제한은 외부 조회 성공과 별도로 다룬다.
- 사용자는 최신 외부 후보를 기존 DB 후보와 비교하도록 승인했다. DB만으로 최종 추천하거나 주1회 수집으로 축소하는 것은 별도 정책 변경이다.

## 연구 안건 목록

아래 안건은 모두 세 자문의 공통 지적에서 도출했다. 순서는 현재 제안하는 논의 우선순위이며 채택 결정이 아니다.

### STR-01 상담 대기와 외부 최신 확인 분리

- 상태: 연구 대기 / 권장 첫 안건.
- 질문: 매 검색마다 최신 외부 확인을 시작하면서도 상담이 완료를 기다리지 않게 할 수 있는가?
- 비교안: 현재 응답 전 취합 / 제한시간 내 초기 결과 + 지속 보강 / 사전 적재 + 요청별 비동기 확인.
- 검토: DB 부족·외부 장애·늦은 신규 후보·사용자 이탈 시 처리, durable job/queue 및 실제 호스트 지원 여부. 응답 후 실행이 보장되지 않는 메모리 작업을 비동기 시스템으로 간주하지 않는다.
- 산출물: 잠정/최종 답변 계약, 최신성 고지, 작업 생명주기, 실패·취소·재시도 정책과 AWS 이식 경계.
- 측정: 첫 유용 답변/최종 답변 p50·p95, 최신 유효 후보 기여, 작업 유실률, 요청당 비용.

### STR-02 임대수익 근거 확보

- 상태: 연구 대기.
- 질문: 매매 후보와 어떤 임대 자료를 연결해야 수익 상담이 가능한가?
- 검토: 해당 호실의 실제 임대계약, 동일 단지 임대 호가, 공실·관리비·운영비 자료의 수집 가능성 및 갱신 비용. 각 자료는 동등한 증빙이 아니다.
- 산출물: 필수·선택 필드와 수집 우선순위, 근거 부족 시 가능한 추천의 범위.
- 측정: 수익 판단 가능한 후보 비율, 근거 최신성, 추정 오차와 자료 확보 비용.

### STR-03 AI와 서버의 판단 책임

- 상태: 연구 대기.
- 질문: 의도 해석·설명과 필수 조건·수치 비교·선정의 경계를 어디에 둘 것인가?
- 검토: 서버가 조건의 기준본을 소유하고 AI 출력이 이를 바꾸지 못하도록 검증. 코드 파싱 우선+AI 보완과 AI 파싱+코드 검증을 비교한다.
- 산출물: 단계별 입력/출력, 단일 상담 상태의 소유권, 출력 검증과 fallback 계약.
- 측정: 조건 누락/위반, 잘못된 환산, AI 호출 수와 파싱 정확도.

### STR-04 사실 추정 미확인 데이터 계약

- 상태: 연구 대기.
- 질문: 필드별 출처·관측 시각·검증 상태·추정 방법을 어떻게 저장하고 계산 결과에 전달할 것인가?
- 검토: 포털의 주장과 독립 검증된 사실을 구분. 임대수익률/총수익률/순수익률/ROI를 같은 지표로 혼용하지 않는다. 근거가 없으면 추정치를 자동 생성하지 않는다.
- 산출물: 증빙 상태 모델, 계산 입력과 결과의 상태 전파, 상담 문장 검증 규칙.
- 측정: 근거 없는 수치 주장, 추정을 사실로 제시한 비율, 근거 추적 가능성.

### STR-05 없음과 확인 실패의 분리

- 상태: 연구 대기.
- 질문: 수집 실패 / 수집 자료 없음 / 조건 부합 없음 / 수익 근거 부족을 어떻게 구분할 것인가?
- 검토: 부분 국가 성공, 오래된 snapshot, DB 장애, 외부 확인 대기 상태. 시장 전체 부재와 현재 자료의 부재를 구분한다.
- 산출물: 서버 상태 코드와 사용자 설명 계약. 고정 문구만 반복하지 않도록 상담 설명과 결합한다.
- 측정: 오해를 유발한 없음 답변 비율, 장애 fallback 성공률.

### STR-06 가정과 질문 후보 제시 정책

- 상태: 연구 대기.
- 질문: 질문보다 후보 제시를 우선하려면 무엇을 가정해도 되고 무엇을 확인해야 하는가?
- 검토: 명시 조건은 보존. 순수입 의도 해석과 근거 없는 수익률·세금 가정은 별개. 국가 미지정 시 현재 연결 국가 광역 탐색 원칙 유지 여부. 정확 후보와 조건 완화 후보를 구분하고 필수 예산 상한을 자동 완화하지 않는다.
- 산출물: 가정 정책 표, 중요한 후속 질문 하나의 선택 기준, 최대Top5/적은 후보/0건 표시 정책.
- 측정: 후보 전 확인 질문 수, 사용자 가정 수정, 후보 적합성. 자문에 제시된10~15%나 수익률은 미승인 예시다.

### STR-07 상담 상태와 후보 스냅샷 유지

- 상태: 연구 대기.
- 질문: 설명·비교·조건 변경·새 탐색을 구분하며 어떤 상태를 영속 저장할 것인가?
- 검토: 명시/가정 조건, 보여준 후보의 순서와 버전, 작업ID, 미확인/변경 알림. 늦게 온 결과로 비교 중인 후보를 조용히 교체하지 않는다.
- 산출물: 상태 전이와 재조회 조건, 후보/가격 변경 안내 및 사용자 선택 보존 계약.
- 측정: 불필요한 재수집·재번역, 후속 질문 맥락 유지, 사용자 선택 방해 사례.

### STR-08 신규 변경 동일 매물 식별

- 상태: 연구 대기.
- 질문: 출처별 레코드 변경과 출처 간 동일 호실 판단을 어떻게 분리할 것인가?
- 검토: 출처ID/정규 URL, 의미 필드 hash/diff, 별도 호실 오병합, 가격 변동, provenance 다중 보존. 건물명+면적+층수 구간 해시만으로 동일 매물을 확정하지 않는다.
- 산출물: 정체성·버전·병합 후보 모델, 자동 병합/보류 기준, 변경 기록 계약. 이미지 해시/버전은 기존 P53와 연결해 검토하되 현재 구현으로 표시하지 않는다.
- 측정: 중복 노출률, 오병합률, 신규·변경 감지 정확도와 저장 비용.

### STR-09 모델 편성과 검증 실험

- 상태: 연구 대기.
- 질문: Gemini/GPT 협업이 이 업무에서 단일 모델보다 실효성이 있는가? JEV의 제한적 호출을 유지할 근거가 있는가?
- 검토: 특정 모델 활용 자체를 목표로 하지 않는다. 신규 검색과 설명/비교 턴의 호출 수를 따로 비교하며 모델·요금·기능은 공식 자료와 실측으로 검증한다.
- 산출물: 대표 질의 세트, 통제된 A/B 평가, 로그/비용 측정 정의와 채택/중단 기준.
- 측정: 첫 유용 답변 시간, 후보 적합성, 근거 없는 주장, 불필요한 질문, 사용자 수정, 상담당 비용. 3초 달성이나 제3 모델의 영구 불필요를 미리 확정하지 않는다.

## 회의 기록 형식

각 안건마다 문제 / 확인 사실 / 미검증 가설 / 대안 / 사용자 결정(승인·보류·기각) / 미해결 질문 / 개발 인계 범위를 짧게 갱신한다. 자문 원문은 수정하지 않는다.

현재 결정: 연구 안건 저장과 별도 기획 채팅 포크만 승인됨. 위 대안의 구현 채택은 없음.

- 원자료: 사용자 첨부 `11466258-97db-436e-91b3-ed09a1ad1fdd/붙여넣은 텍스트.txt`의 Z-AI 자문. 아래는 원문 전체가 아닌 검토 요약이다.

### 차별점과 연결 안건

1. STR-01: 후보 수 대신 세그먼트별 신선도·커버리지로 추가 수집을 판단. 정기 수집(Tier 0), 상담 시 경량 목록 확인(Tier 1), 후보 상세 비동기 보강(Tier 2)을 비교한다. 기존 P56 최신 외부 확인 원칙을 바꾸려면 별도 승인이 필요하다.
2. STR-08: 출처별 게시 Listing과 실제 물건 Property를 분리하고 N:1 출처 이력을 보존. 출처 ID, 콘텐츠 hash, 복합 식별 신호를 구분하며 모호한 동일 호실 판단은 병합 대기 대상으로 둔다. 단일 hash나 위치 누락만으로 동일 여부를 확정하지 않는다.
3. STR-07: 제시한 후보 ID·순위·관측 시점을 불변 스냅샷으로 유지. 후속 지칭은 해당 스냅샷 기준이며 늦은 결과는 추가 결과로 구분한다. 사용자 비교/선택 중 자동 재정렬은 피한다.
4. STR-04: 필드별 VERIFIED / REPORTED / ESTIMATED / MISSING 증거 수준을 검토. 게시 임대료와 실제 계약 검증을 구분하고 추정 공식·입력·버전을 추적한다. AI가 근거 수준을 임의 승격하지 않는다. 이 명칭들은 미승인 제안이다.
5. STR-02/09: 수집 → 파싱 → 신규 → 활성 → 필수 조건 통과 → 정확 부합 → 수익 근거 확보 퍼널을 측정. 수집 건수를 추천 가능 후보 수나 검증된 수익 후보 수로 오인하지 않는다.
6. STR-06: 틀렸을 때 재계산으로 끝나는 가정과 재탐색/중대한 위험을 만드는 가정을 구분하는 판단 기준을 검토. 예산 오차·수익률·공실률 기본값은 근거 확보와 사용자 승인 전 적용하지 않는다.

### 미검증 전제와 반론

- 30초 중단은 현재 코드 제한으로 확인된 사실이며, 플랫폼 전체 제한이라는 Z-AI 가설과 구분한다.
- GPT Sites의 푸시 불가, 응답 후 작업 지속, Queues 연결 가능성은 현재 배포 환경에서 별도로 검증해야 한다.
- last_seen 누락은 거래 종료 증거가 아니다. 접근 실패·목록 누락·페이지 이동·명시 종료를 분리한다.
- 법률 규칙은 무기한 코드 상수가 아니라 출처·버전·적용 시점을 갖는 정책 데이터와 검토 책임이 필요하다.
- 명시적 필수 조건/수치는 코드가 검증하되 생활 선호 등 소프트 적합성의 AI 해석까지 일괄 금지할 필요는 없다.
- 제3 모델 불필요는 미검증 결론이다. 선택적 Critic과 단일 상담 모델의 효과를 STR-09에서 비교한다.
