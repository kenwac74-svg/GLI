# GLI 논의 인계와 저장 현황

기록일: 2026-11-11
담당: GLI 총괄 사업기획·PM
기록 근거: 현재 사업기획 대화의 사용자 합의, 기존 Git 문서·브랜치, 생성된 Web3 페이지, 사용자가 전달한 백서 전용 세션 링크와 오류 메시지.

## 2. 현재 대화에서 최종 합의한 Web2 방향

- 목적은 새로운 검색엔진·검증 이론을 만드는 것이 아니라 **최소 리소스로 좋은 고객 경험**을 제공하는 것이다.
- 빠른 기존 LLM의 유용한 답을 활용한다. 고객 답변 앞에 다른 LLM의 의무적인 사실검수·재작성 단계를 붙이지 않는다. Astra를 이미 연결했다는 이유로 역할을 만들어주지 않는다.
- 현재는 **기존 OpenRouter 연결을 우선 사용**한다. 꼭 필요한 근거 없이 새 OpenAI 직접 API 계정·키·추가 검색업체 연결을 요구하지 않는다.
- 질문과 관련된 GLI 보유자료가 있으면 **최상단**에 표시한다. 없으면 LLM 답변을 자연스럽게 보여주며 내부 후보 0건으로 탐색을 막지 않는다. 보유자료·이미지 준비 때문에 먼저 도착한 본문을 지연시키지 않는다.
- LLM의 숫자·출처·의미를 임의로 바꾸거나 고정 UI의 빈칸을 채우려고 정보를 만들지 않는다. AI 오류 가능성 안내와 기존 검증상태 구분은 유지한다. 자료 보유를 검증 완료로 승격하지 않는다.
- 처음부터 모든 정보를 조사해 장문을 내놓기보다, 이번 질문에 충분히 유용하고 적절한 답을 먼저 준다. 핵심 답을 일부러 미뤄 클릭을 요구하지 않는다.
- 같은 응답에서 다음에 사용자가 보낼 만한 질문을 제안한다. 선택하지 않은 질문의 답을 미리 조사하지 않는다. 제안 선택·수정·전송과 자유 입력을 모두 허용한다. 0~3개는 P-012의 첫 구현 기본값이지 모든 응답에 영구적으로 강제할 양식이 아니다.
- 목적 밖 질문은 필요 없는 장시간 검색 대신 일반 AI 이용과 GLI의 역할을 부드럽게 안내한다. 관련성은 단어가 아니라 질문 목적·대화 맥락으로 판단하며, 내부 자료 부족을 범위 밖 질문으로 취급하지 않는다.
- 고객의 실제 검색명령을 품질 개선 자료로 보관하고 관리자가 열람할 수 있어야 한다. 전체 대화의 영구 보관이나 제안 문구를 실제 검색수요로 집계하는 것은 별개다.

## 3. 원래 UI와 개선 UI B

사용자 지시대로 **검색·응답은 하나, 표현은 A/B 두 가지**다. 같은 질문·본문·출처·후보·대화 상태를 공유하고, 전환만으로 추가 LLM 호출을 하지 않는다. 작성 중 입력과 진행 중 요청도 유지한다.

- A는 기존 디자인과 동선을 최대한 유지한다.
- B는 클릭형 `GLI_검색결과_클릭형시안_v1.html`을 참고한다. 이전 생성형 대시보드 이미지나 Claude의 별도 연구안과 혼동하지 않는다.
- 세 예시 장면(후보 찾기·두 후보 비교·관리비 질문)은 실제 자유질문 처리나 전체 질문의 고정 양식이 아니다. 시안의 예시 가격·사진·답변을 실매물로 재사용하지 않는다.
- B안 보관 브랜치: `design/gli-search-ui-b-20261016`, 확인된 헤드 `c5eebeb0a27933708bf392fb5dedd664ed5c9b41`.
- 해당 브랜치는 검토 기록·자산 목록을 보관한 상태이며, HTML·PNG 원본의 원격 업로드 완료는 확인되지 않았다. 대화에 제공된 ZIP과 실제 Git 보관을 구별한다. 이 체크포인트가 원본 바이너리를 업로드한 것은 아니다.

대화에서 전달한 파일명: `GLI_review_package_20261108.zip`, `GLI_P012_handoff_20261108.zip`. 파일명은 인계 식별용이며 이 저장소에 같은 파일이 있다는 뜻은 아니다. 실제 전달받은 원본을 사용하고 없는 파일을 새 디자인으로 대체하지 않는다.

P-012의 최종 산출물은 실제 질문과 후속 대화를 사용하며 두 UI를 바꿔볼 내부 검토 화면이다. 명세 저장과 실제 동작·운영 반영은 서로 다르며, 이번에는 새 구현·배포 상태를 확인하지 않았다.

## 4. Web3 기획 분기와 반드시 유지할 정정

사용자는 이 대화에서 Web3 사업기획을 분리해 이어갈 페이지를 요청했다. 생성된 페이지는 [GLI Web3 사업기획](https://chatgpt.com/space/page_6cf64d5e8e588191aaa2c8ad0ca7c2b6)이다. 이는 핵심 맥락을 옮긴 별도 페이지이며, 전체 채팅·첨부자료를 복제한 네이티브 포크가 아니다.

현재 대화에서 확인되는 원래 목표는 **약 100만원 규모의 소액 투자자도 안방에서 해외부동산에 참여할 수 있게 하는 접근성**이다. 사업주가 해외부동산을 확보하고 토큰 기반 자금 조달·조각판매를 연결한다는 개념도 논의됐다. 약 100만원은 접근성의 목표 예시이며 확정 최소 투자금·상품 조건으로 바꾸지 않는다.

Web2와 Web3는 다른 층위의 수요를 해결하는 방향이고, Web2의 독립 사업성과 최소자원 원칙을 유지한다. 코인 발행이나 특허 출원 자체가 사업목표가 아니다. 신규 토큰 구조·권리·체인·발행량·보상률·환매 조건은 이 기록에서 추가 확정하지 않는다. 다른 프로젝트(CNYT 등)의 조건을 GLI 합의로 가져오지 않는다.

페이지에 제안했던 첫 안건은 ‘고객이 무엇을 받고, 누가 자산을 확보·운영하며, GLI는 어디에서 돈을 버는가’다. 이는 새 페이지의 논의 출발안이지 기존 백서 결정을 폐기하는 지시가 아니다.

**중요한 정정:** Web3 페이지는 아래 백서 전용 세션의 본문을 읽기 전에 만들었다. 사용자가 그 전용 세션을 지정했으므로, 페이지의 ‘미정’ 표기가 해당 세션에서 이미 확정한 정책을 미정으로 돌려서는 안 된다. 먼저 전용 세션의 기록을 복구·대조한 뒤 페이지를 조정해야 한다. 현재 페이지는 기존 백서를 대체하는 권위 있는 새 기준이 아니다.

과거의 ‘2027년 상반기 이후’ 언급은 관련 법규 정비를 전제로 한 일정 가정으로만 보존한다. 규제 시행·완료가 검증됐다는 사실로 기록하지 않는다. 이번에는 법률 조사나 모집·발행·배포를 승인·실행하지 않았다.

## 5. GLI 사업계획서·백서 전용 세션과 복구 상태

사용자가 지정한 대상: **GLI 사업계획서·백서 전용**
세션 식별자: `019fc2c1-b78d-7023-b2f5-ca82754ab65a`
제공 링크: `codex://threads/019fc2c1-b78d-7023-b2f5-ca82754ab65a`

대상 링크는 식별했으나 이 PM 대화에서 본문 전체를 읽은 것은 아니다. 같은 프로젝트라는 이유로 자동 열람하거나 작업을 시작시킬 수 있다고 주장하지 않는다. 이전 브라우저 연결 시도는 컨텍스트 오류로 실패했다. Git 기록도 다른 세션을 자동으로 실행시키지는 않는다.

사용자가 전달한 반복 오류:

```text
Error running remote compact task: Codex ran out of room in the model's context window. Start a new thread or clear earlier history before retrying.
```

이 메시지는 압축 작업의 컨텍스트 한도 초과 보고다. 누적 이력·큰 도구 출력·압축 구현 중 무엇이 구체적인 원인인지는 이 기록으로 확정하지 않는다. 원본 유실 여부도 확인되지 않았다.

**직전 안내에서 제안한 복구 작업은 아직 실행·성공 확인 전이다.** 기존 세션에 요약을 반복 요청하는 대신, 새 로컬 작업 채팅이 저장된 기록을 읽기 전용으로 찾고 나눠 읽는 방법을 제안했다. `CODEX_HOME` 또는 사용자 홈의 `.codex` 아래 기록 위치는 확인 후보일 뿐, 이 사용자 기기에 대상 원본이 있다고 확인한 것이 아니다.

복구 작업의 경계: 위 ID의 기록만 찾고 사용자 메시지·표시된 답변을 필요한 범위에서 순서대로 읽는다. 전체 기록을 다시 한 번에 입력하지 않는다. 인증정보·관계없는 세션은 읽지 않고 원본·설정·세션 DB를 수정·삭제하지 않는다. 확정사항·미정사항·폐기안·최신 상태·기존 문서와 커밋을 구별해 `GLI_WHITEPAPER_RECOVERY.md`로 저장하는 안을 전달했다. 앱 코드 변경·커밋·푸시·배포를 복구 작업 자체에 포함하지 않았다.

**대상 원문이나 복구 문서는 아직 확보되지 않았다.** 따라서 ‘그 세션의 모든 합의도 Git에 저장 완료’라고 보고할 수 없다. 이 체크포인트는 복구 필요와 대상·범위를 보존한 것이지 복구 산출물이 아니다.

## 6. 이어받을 작업과 승인 경계

1. GLI 데모 개발은 기존 [P-012](GLI_P012_SHARED_ANSWER_AB_UI_SPEC_20261108.md)의 공통 응답·보유자료 상단 표시·후속 대화·A/B 전환 구현을 기준으로 삼는다. 이 문서로 새로운 코드나 유료실험을 추가 지시하지 않는다.
2. 백서 전용 세션은 별도 복구 결과 또는 이미 저장된 문서의 경로·커밋을 확보해야 한다. 확보 후 현재 Web3 페이지와 대조하고 충돌을 표시한다. 모르는 내용을 일반 지식이나 다른 GLI 대화로 채우지 않는다.
3. PM은 기존 합의·새 제안·구현·실측·배포를 분리한다. 같은 처방을 반복하면 기존 Claude 독립 검토 규칙을 유지한다. 새 문서를 만드는 것만으로 제품 개선이 끝났다고 계산하지 않는다.

## 7. 이번 문서 변경 이력

2026-11-11: 사용자의 ‘지금까지 상의한 내용이 커밋·푸시됐는가’라는 확인에 따라 원격 브랜치와 P-012 안내를 점검했다. 이미 저장된 핵심 합의·시험은 원래 경로와 커밋을 참조하고, 누락된 최근 Web3 분기·전용 세션 식별·압축 오류·미실행 복구안을 보완했다. 기존 원문·실험 증거·과거 합의는 삭제하거나 덮어쓰지 않았다.

이번 변경은 인계 문서와 README 안내에 한정한다. 앱 코드·UI·DB·키·유료 모델 호출·서비스 배포·다른 브랜치 병합은 변경하지 않는다. 저장소 문서의 원격 반영과 다른 개발/백서 세션의 수신·착수는 별도 상태다.
