# P-012 — 공통 LLM 답변 + 원래 UI / 개선 UI 전환 개발명세서

작성: 2026-11-08
수신: **GLI 데모 개발 세션 / GLI 개발 도구**
기획·검토: GLI 총괄 사업기획·PM
성격: **개발팀 전달 명세 및 내부 개발·검토 실행 지시. 제품 채택·운영 배포 완료 문서가 아니다.**

## 1. 이번에 만들 것

**빠른 LLM이 준 답을 그대로 활용하고, 관련된 GLI 보유자료가 있으면 최상단에 먼저 보여준다. 보유자료가 없으면 LLM 답변만 편하게 보여준다. 고객이 다음 질문을 쉽게 선택하고 대화를 이어갈 수 있게 한다. 동일한 답변을 원래 UI와 개선 UI에서 번갈아 본다.**

사용자의 최신 지시 근거:
> “llm이 준 답을 의도적으로 검수하거나 검증하느라 시간을 쓸 필요 없어. 우리 것이 있으면 최상단에 보여주고, 없으면 llm이 준 답을 시각화 해서 잘 배치해 보여준다.”
> “gli 개발툴에게 넘길 개발명세서를 작성하고 원래 ui와 개선 ui 두개를 번갈아 이용해 볼 수 있는 구조로 만들도록 지시해”

이 명세를 받아 **실제로 질문을 입력하고 A/B를 전환할 수 있는 내부 검토 화면**을 구현한다. 추가 방향성 보고서나 또 하나의 정적 이미지가 최종 산출물이 아니다.

### 기존 합의와의 관계

- 마스터 §0.1의 좋은 답 활용·사람의 정보 확보·최소자원·구매/재방문/참여 목표를 유지한다.
- 공통 검색은 하나다. A/B는 모델 비교가 아니라 **같은 결과의 표시 방식 비교**다.
- 최신 지시에 따라 사용자 답변 앞에 의무적인 사실 검수·다른 LLM 재작성·독립 검증 단계를 두지 않는다. 기존 시험에서 나온 모든 문제의 해결을 이 화면 구현의 선행조건으로 삼지 않는다.
- 보유자료 우선 표시는 신규 승인된 표시 원칙이다. 관련 없는 재고를 끼워 넣거나, GLI가 보유했다는 이유만으로 검증등급을 올리는 승인이 아니다.
- 기존 서비스의 로그인·권한·키 보호·사용량/비용 제한·안전한 화면 처리는 유지한다. 이는 LLM 답변의 사실검수와 별개다.
- B안은 여전히 비교 검토용이다. 기존 운영 UI의 삭제·교체, main으로 앱 병합, 공개 배포는 별도 승인 사항이다.

## 2. 공통 처리 흐름

```text
사용자 질문 + 현재 대화의 필요한 맥락
          ├─ 기존 GLI 자료 조회 → 관련 자료가 있으면 공통 최상단 영역
          └─ 기존 OpenRouter의 빠른 모델 하나
                    → 필요한 경우 검색
                    → 답변 스트림 + 출처 + 선택형 후속 질문
                                      ↓
                          하나의 대화·결과 상태
                             ├─ A: 원래 UI
                             └─ B: 개선 UI
```

GLI 자료 조회와 이미지 준비 때문에 LLM 본문 표시를 기다리게 하지 않는다. 보유자료 0건·조회 오류를 전체 검색 실패로 바꾸지 않는다. 첫 답을 의도적으로 불완전하게 만들어 추가 클릭을 요구하지 않는다.

## 3. 응답 연결: 새 엔진을 만들지 않는다

1. 기존 OpenRouter 키·호출 기반을 사용한다. 초기 연결은 P-010에서 실제 시험한 단일 모델 설정을 우선 재사용한다. 모델의 실제 이용 가능성만 확인하고, 신규 계정·직접 OpenAI API·추가 검색 API를 요구하지 않는다.
2. Gemini 선행 수집 → Astra 검수 같은 의무 직렬 경로를 두지 않는다. 별도 의도분류·요약·평가·후속질문 생성 모델도 호출하지 않는다.
3. 사용자 원문과 필요한 최근 대화·참조 대상을 같은 응답 모델에 전달한다. 최신 자료가 필요할 때 검색을 쓰되, 모든 질문에 검색을 강제하지 않는다. 내부 매물 목록이 답변 가능한 세계의 전부가 되지 않게 한다.
4. 생성된 본문은 스트림으로 바로 전달한다. 다른 모델의 검수, 모든 이미지, 후속 질문 목록의 완성을 기다리지 않는다. 스트림 중인 답변을 완료된 답으로 표시하지 않는다.
5. 답변은 적절한 길이로 유지한다. 새로운 사실이나 필수 항목을 보태기 위해 재작성하지 않고, 표시를 위한 문단·표·이미지 연결만 수행한다.
6. 응답 오류·시간초과는 현재 받은 본문과 오류 상태를 구분해 표시한다. 몰래 다른 모델로 바꾸거나 자동 재시도로 반복 과금하지 않는다. 사용자가 다시 실행하는 동작은 명시적으로 제공한다.

모델 변경 실험과 공급자별 비교는 이번 기능의 필수 선행작업이 아니다. 사용자에게도 모델 선택을 요구하지 않는다.

## 4. GLI 자료가 있을 때 / 없을 때

| 상태 | 고객에게 보여줄 것 |
|---|---|
| 질문과 관련된 보유자료 있음 | 답변 영역 최상단에 **GLI 보유자료**로 표시하고, 그 아래 LLM 답변을 제공 |
| 보유자료 없음 | 해당 영역을 숨기고 LLM 답변부터 표시. ‘0건’ 경고로 탐색을 막지 않음 |
| 보유자료 조회 실패 | LLM 답변은 유지. 필요한 운영 오류만 기록하고 전체 답변 실패로 처리하지 않음 |
| 내부자료와 외부 답변이 다름 | 각각의 출처·기준시점을 유지. 자동 검수·통합 판정을 기다리지 않고 별도 자료로 표시 |

관련성은 기존 조건/조회 기능과 현재 대화 대상을 재사용한다. 새로운 시맨틱 검색 시스템을 만들지 않는다. 질문과 무관한 보유매물, 매입 질문의 임대매물을 매입 추천처럼 올리지 않는다.

보유자료의 실제 이미지·가격·출처·확인시각·기존 검증상태는 그대로 사용한다. 새 확인배지·수익 보증을 생성하지 않는다. 늦게 도착한 자료는 사용자가 읽던 위치를 불필요하게 이동시키지 않도록 반영한다.

## 5. A/B UI 전환 — 이 동작은 반드시 구현

화면의 같은 위치에 **[원래 UI] [개선 UI B]** 전환 버튼을 둔다. 최초 진입은 A다.

- **A:** 현재 앱의 메뉴·필터·목록·상담 영역 배치와 디자인을 유지한다. 새 공통 응답·상단 보유자료·후속 질문을 연결하는 최소 변경만 한다. 운영본 자체를 수정한다는 뜻이 아니라 내부 검토 환경의 A 화면이다.
- **B:** `GLI_검색결과_클릭형시안_v1.html`의 답변 표현을 참고해 연결한다. 생성형 대시보드 이미지나 이전 Claude 포크 A안과 혼동하지 않는다. 시안의 고정 답변·사진·가격을 실제 검색 결과처럼 재사용하지 않는다.
- **공통:** 모델, 프롬프트, 검색, 본문, 출처, 보유자료, 후보 순서, 후속 질문은 동일하다. B에서만 좋은 답을 다시 생성하지 않는다.
- 전환해도 대화·현재 질문·작성 중인 입력·선택 후보·진행 중인 요청을 유지한다. 검색 중에 전환해도 취소하거나 새 요청을 만들지 않는다.
- **A/B 전환의 추가 LLM 호출은 0회**여야 한다. 페이지 재마운트/URL 변경으로 기존 자동 검색이 재실행되지 않게 한다.
- A에서 질문하고 B에서 후속 질문을 보내도 같은 대화다. ‘두 번째 후보’가 전환 때문에 다른 대상으로 바뀌면 안 된다.
- UI 선택값은 표시 방식만 제어한다. URL이나 브라우저 저장값으로 인증·모델·비용 제한을 바꿀 수 없어야 한다.

독립된 두 검색 서비스나 두 DB를 만들지 않는다. 하나의 내부 검토 화면에서 전환할 수 있게 한다. 비교를 위한 무작위 실험/통계 시스템은 만들지 않는다.

## 6. 시각화와 후속 질문

### 시각화

B는 답변에 맞춰 제목·본문·표·출처·이미지·후보의 표시를 조합한다. 모든 질문을 ‘후보 → 수익률 → 지도 → 중개사’ 양식에 넣지 않는다. 짧은 답은 짧은 문장으로 끝낼 수 있다.

사진은 보유자료나 응답/기존 자료 경로에서 실제 확보한 것을 사용한다. 단지·지역 참고 이미지와 특정 호실 사진을 구별한다. 이미지가 없으면 텍스트로 먼저 보여주고, 빈칸을 채우려고 생성하거나 별도 수집을 필수 실행하지 않는다. 지도는 기존 기능과 위치자료가 있을 때만 연결한다. 새 지도 API 계약은 이번 범위가 아니다.

원 답변의 숫자·단위·추정 조건·출처를 임의 변경하지 않는다. LLM이 생성한 임의 HTML/스크립트는 실행하지 않고 기존 안전한 렌더러를 사용한다.

안내 문구는 두 UI에 작게 한 번 표시한다: **“AI 답변에는 오류가 있을 수 있습니다. 중요한 내용은 원문과 담당자에게 확인해 주세요.”** 매 문단마다 경고하거나 별도 확인 동의를 강요하지 않는다. 이 안내를 답변 검수 완료나 GLI 보증으로 표현하지 않는다.

### 후속 질문

같은 LLM 응답에서 방금 답과 관련된 사용자 관점의 후속 명령을 **0~3개** 받는 것을 첫 구현 기본값으로 한다. 제품 전체의 영구 개수 규칙은 아니다. 본문 뒤의 ‘이어서 알아보기’ 목록을 읽는 단순한 방식부터 사용해도 된다.

화면에서는 옅은 선택 칩으로 보여주고, 클릭 또는 키보드 선택 시 입력창에 문장을 넣는다. 고객이 수정하거나 전송하면 같은 대화로 실행한다. 선택만으로 자동 검색하지 않는다. 제안은 실제 disabled 버튼이 아니라 접근 가능한 선택 요소여야 한다.

제안을 표시하는 것, A/B를 바꾸는 것, 제안을 입력창에 넣는 것에는 추가 호출이 없다. 선택하지 않은 질문의 답은 미리 생성하지 않는다. 제안 파싱 실패 시 목록만 생략하고 정상 본문은 보존한다. 모든 답에 제안을 강제로 붙이거나 자유 입력을 막지 않는다.

부동산·거주와 무관한 질문에는 일반 LLM 이용을 부드럽게 안내하고 GLI의 역할을 짧게 알린다. 인사에는 자연스럽게 답한다. 정치·의료 등 단어만으로 관련 질문을 배제하지 않는다. 내부자료 부족을 범위 밖 질문으로 처리하지 않는다.

## 7. 최소 기술 경계와 수정 위치

**한 요청의 결과와 대화 상태를 상위 공통 처리부가 소유하고, A/B는 그 상태를 읽는 표시 컴포넌트로 분리한다.** UI 컴포넌트가 각자 모델을 호출하지 않게 한다.

공통 결과에는 답변/출처/보유자료/후속 질문/요청 상태와 식별값만 있으면 된다. 기존 타입을 재사용·최소 확장한다. 새로운 strict JSON 출력이나 복잡한 페이지 생성 규격을 필수로 만들지 않는다.

외부 출처는 GLI 자산 ID가 없어도 표시할 수 있어야 한다. 현재 `Citation.assetId` 필수 구조를 그대로 강제해 외부 출처를 버리거나, 존재하지 않는 DB ID/Trust 점수를 만들지 않는다. 일반 웹 출처와 보유자산 참조를 구분해 최소 확장한다. 후보가 없어도 유효한 본문은 정상 답변이다.

개발 시 우선 확인할 기존 위치(이름은 확인한 실행 브랜치 기준이며 현재 워킹트리를 먼저 대조):

| 위치 | 필요한 작업 |
|---|---|
| `app/api/search/route.ts` | 기존 인증·사용량 경계를 유지하며 단순한 공통 응답 경로 연결. 전량 수집·저장·검수를 응답의 필수 선행단계로 두지 않음 |
| `lib/ai-search.ts` 및 기존 OpenRouter 호출부 | 빠른 단일 모델 응답 재사용/분리. 내부 후보만 설명하는 지침과 의무 검수 경로를 이번 흐름에 복사하지 않음 |
| `lib/consultation-view.ts`, `lib/explore-session.ts` | 같은 결과·출처·참조 대상·대화 상태를 A/B에서 공유 |
| `app/components/claude-design-shell.tsx` 및 상담 표시부 | 기존 A 유지, B 표시 컴포넌트와 전환 연결. B 스타일이 A에 새지 않게 범위 분리 |

위 파일 전체 재작성이나 별도 서비스 도입을 지시하는 것은 아니다. 더 작은 재사용 경로가 있으면 개발 담당이 선택하고 변경 이유를 기록한다.

## 8. 구현 순서와 범위

1. 실제 개발 워킹트리와 기존 미커밋 변경을 확인하고 **실행 가능한 앱 기준에서 별도 기능 브랜치**를 만든다. 문서만 있는 main이나 B안 보관 브랜치를 앱 실행본으로 착각하지 않는다.
2. 기존 OpenRouter 응답을 공통 상태와 A 화면에 먼저 연결한다. 이어서 관련 보유자료의 상단 표시, 실제 생성된 후속 질문과 대화 연결을 완성한다.
3. 같은 상태를 B에도 연결하고 A/B 전환을 추가한다. 시안의 세 가지 고정 질문이 아니라 실제 자유 입력을 처리한다.
4. 아래 완료 조건을 확인하고, 사용자가 열 수 있는 **로컬 또는 기존 권한 내 비공개 검토 주소**와 변경 커밋을 보고한다. 단순 스크린샷이나 모의 답변만으로 실제 연동 완료라고 하지 않는다.

새 키·서비스 가입·모델 비교 실험·정교한 AI 채점·유료 조사·새 전문가 운영·결제·운영 배포는 하지 않는다. 관리자 검색명령 저장(P-009)은 유지되는 별도 요구다. 구현돼 있으면 같은 요청 ID로 한 번만 기록하고 UI 전환을 검색으로 세지 않는다. 미구현이면 상태를 보고하되 이를 이번 화면 연결의 선행조건으로 만들지 않는다.

P-011 검색 계수 불일치는 알려진 미해결 항목이다. 계수 의미의 완전한 해명을 코드·UI 연결과 저장된 결과 재생의 선행조건으로 삼지 않는다. 기존 키/사용량 제한과 자동 재시도 금지는 유지한다. 실호출은 기존 승인·사용 가능 범위에서 수행하고, 통제를 확인할 수 없어 실행하지 못한 부분은 정확히 구분해 보고한다. 타임아웃이나 요청 개수만으로 절대 과금 상한이 보장된다고 주장하지 않는다. 부족한 실행 권한을 임의로 확대하지 않는다.

## 9. 완료 조건 — 새 연구가 아니라 실제 동작 확인

| 확인 | 통과 기준 |
|---|---|
| 실제 질문·응답 | 기존 OpenRouter에서 받은 본문·출처가 표시되고, 모의 응답과 구별됨 |
| 내부자료 있음 | 관련 보유자료가 두 UI의 최상단에 나타남. 기존 확인상태는 바뀌지 않음 |
| 내부자료 없음/조회 실패 | 빈 재고를 이유로 답을 중단하지 않고 LLM 답변을 제공 |
| A/B 전환 | 반복 전환 및 스트리밍 중 전환에도 모델 추가 호출 0회, 본문/출처/후보/입력/대화 유지 |
| 후속 대화 | 실제 생성된 제안을 선택·수정·전송할 수 있고, 자유 입력도 가능. 실제 이전 대상을 이어받음 |
| 질문 다양성 | 기존 매물 탐색·비교·짧은 설명·범위 밖 입력을 특정 화면에 억지로 끼워 맞추지 않음 |
| 누락·오류 | 이미지/후속 목록이 없어도 본문은 표시. API 오류는 구분, 무단 재호출 없음 |
| 유지 범위 | 운영 UI·배포·키·권한·검증등급이 바뀌지 않고, B 해제로 A만 사용 가능 |

변경에 관련된 자동검사와 직접 클릭 확인을 수행하고, 저장된 결과로 할 수 있는 검사는 재호출하지 않는다. 실제 모델 연동 여부·후속 대화 확인·응답시간·비용은 관측한 것만 보고한다. 특정 응답속도나 모든 고객의 만족을 미리 보장하지 않는다.
