## 4. Codex 작업

### C1. 자산 정체성 및 표시 일치 (최우선)

- 원본 후보 → 검색 응답 → 카드 → 상세 → 관심 자산/상담 참조의 ID 매핑표를 만든다.
- 배열 위치로 서로 다른 물건을 연결하지 않는다. 실제 자산 필드는 서버의 정규화된 데이터 계약에서 제공한다. 시안 데이터는 시각 검수 fixture이며 운영 응답을 대체하지 않는다.
- 기존 ID가 서로 다른 물건에 쓰였다면 원문 키·실제 자산 근거로 충돌을 해소한다. 이전 링크·관심 자산의 의미를 다른 물건으로 바꾸지 않는다. 필요한 ID 이관은 별도 계획을 남긴다.
- 기존 카드의 디자인을 유지하면서 제목, 거래 유형, 원통화 가격, 위치, 사진, 등급, 출처를 같은 자산으로 연결한다. 정적 카드도 최신 응답 순서와 데이터로 표시한다.
- 렌트 비교 사례는 매입 후보와 구분한다. 같은 건물의 임대 사례를 같은 호실의 실제 수익으로 단정하지 않는다.
- 다른 포털의 유사 매물은 기존 정책대로 유지한다. 동일 원문 반복 처리 외에 임의 통합·삭제하지 않는다.
- 완료 증거: 세 문제 ID의 매핑표, 목록/상세/상담 필드 일치 테스트, 상세 왕복·관심 자산 회귀.

### C2. 구조화된 상담 상태와 후속 의도

- 총투자예산, 매입가 한도, 목표 월수입, 실제 거주 월세 한도를 다른 필드로 관리한다. 금액의 통화·기간·표면/순수입 여부를 구분한다. 아직 정해지지 않은 값은 null/미정이다.
- 투자자/임차인 역할, 거래 목적, 프놈펜 우선, 타국 대안 허용, 선택 자산, 조건 변경·해제 의도를 보존한다.
- 후속 질문은 지정된 필드만 갱신한다. "월세 100만원 받고 싶어"를 임차인 전환으로 해석하지 않는다. "아니, 내가 살 집을 빌리려는 거야"는 명시적 목적 변경으로 처리한다.
- 단순 정규식 추가로 종료하지 않는다. 기존 모델을 통한 구조화 의도 해석과 서버 스키마 검증·명시 변경 병합을 검토한다. 모델 결과가 지역·가격·권한을 임의 생성하거나 변경하지 못하게 한다.
- 추가 호출이 필요한 설계는 호출 횟수·지연·실패 처리·비용 영향부터 보고하고 승인받는다. 임차인/투자자 의미가 불명확한 fallback은 조건을 뒤집기보다 질문한다.
- 현행 환율 계약을 재사용하고 하드코딩 환율을 새로 추가하지 않는다. 전환 불가 시 임의 숫자를 만들지 않는다.
- A2/A3에 따른 질문·후보 노출 흐름을 연결한다. 국가 확대 동의는 확보된 다른 국가 파트너 자료 탐색에도 적용하되, 미연결 국가를 실시간 크롤링했다고 하지 않는다.
- 완료 증거: 아래 T1~T6의 다중 턴 상태와 후보 결과.

### C3. 결과 계약과 개수

- 응답에 requestId/resultSetId, 적용 조건, 반환 후보 ID·순서, 이번 검색 범위의 일치 수와 반환 수, 추가 반환 가능 여부를 분리하는 계약을 제안한다.
- matchedCount는 전체 시장의 물건 수가 아니다. 전체 일치 수를 알 수 없으면 null로 두며 모델이 추산하지 않는다. source-wide total을 반환 목록 길이로 만들지 않는다.
- 답변·진행 완료·결과 제목은 하나의 응답 계약에서 계산한다. 19건 중 18건을 반환하면 그 관계를 일관되게 표현한다. 플랫폼 전체 통계는 검색 건수와 분리한다.
- 요약 후보 최대 3개를 쓰더라도 실제 결과 전체와의 관계를 유지한다. A3 승인 없이 일방적으로 결과를 3개로 축소하지 않는다.
- 기존 18건 상한, 추가 로드 UI를 변경할 필요가 있으면 별도 보고한다. 자동으로 전수 검색/무제한 호출을 추가하지 않는다.
- 완료 증거: 0/1/18/19건, 전체 수 미확인, 후속 필터 변경, 오래된 응답 역전, 상세 복귀 테스트.

### C4. 임대수익 후보의 적합성

- 자산 매입, 임차인용 임대, 사업 참여의 분류를 바로잡는다. 0·미상 면적은 소형으로 가산하지 않는다.
- Trust는 자료 검토 등급이며 수익성 점수와 동일시하지 않는다. 기존 등급이나 사용자 승인 모의 데이터 자체를 임의로 재설계하지 않는다.
- 임대수입 자료가 있는 자산과 자료 확보가 필요한 자산을 구분한다. 매입가와 비교 가능한 임대 근거가 있을 때만 계산하고, 실제 계약/호가/추정과 비용 포함 여부를 명시한다.
- 추천 이유는 해당 자산과 현재 조건에서 나온 사실을 사용한다. 모든 후보에 같은 "임대 수요" 문장을 붙이는 것으로 검토를 대신하지 않는다. 부족한 GLI 폼 정보는 기존 정책의 "조사 예정"을 유지한다.
- A2에 따라 후보군 분리를 구현한다. 수익성 순위 산식이나 새 공개 점수 도입은 별도 제안이며 이번 승인 범위에 자동 포함되지 않는다.

### C5. 실제 AI 실행과 답변 진단

- 현재 환경에서 공급사 호출 여부, 성공/시간 초과/검증 실패/규칙 대체를 확인한다. 화면 템플릿만 보고 호출 장애를 추정하지 않는다.
- 내부 기록은 requestId, 경로, 지연, 제한된 실패 코드, 가능하면 사용량을 담는다. API 키·민감한 대화 원문은 로그에 남기지 않는다.
- 사용자는 GLI AI만 본다. 공급사명·원시 오류·모델 내부 추론을 노출하지 않는다. 답변은 예산 미정/근거 미확인/데이터 미연결을 거짓 완료로 바꾸지 않는다.
- 실제 실행 이벤트가 없는 로딩 단계는 진행 안내일 뿐 자료 검증 완료 증거로 사용하지 않는다. Claude에 제공할 상태를 서버와 클라이언트가 합의한다.
- 고정 템플릿뿐 아니라 의도 요약, 관련 후보 근거, 다음 질문이 일관된지 평가한다. 일반 면책 반복으로 상담을 대체하지 않는다.

### C6. 통합·검수·명세

- 승인된 Claude 변경분만 React로 통합한다. 기존 CSS/서체/색상/다른 페이지는 보존하며 필요한 차이는 먼저 보고한다.
- API-CONTRACTS/PRODUCT-DATA/openapi/registry/ACCEPTANCE와 HISTORY를 실제 변경분에 맞춰 갱신한다. 아직 없는 계약은 현재 동작으로 기록하지 않는다.
- 기존 단위 시험 통과와 상담 품질 합격을 분리한다. 아래 실제 문장을 회귀 시험과 사용자 시나리오에 추가한다.
- 공개 배포 전에 로컬 사용자 검수, 공급사 실제 호출을 포함한 제한된 통합 시험, 키 비노출 확인을 수행한다. 공개 배포는 별도 승인한다.

주요 범위: `lib/search.ts`, `lib/ai-search.ts`, `lib/gli-ai-orchestration.ts`, `app/api/search/route.ts`, 자산 정규화·데이터 정의, `app/components/claude-design-shell.tsx`, 생성기 및 관련 테스트. 파일 전체 재작성·기존 브랜치 교체는 요구하지 않는다.

## 6. 제안 데이터/이벤트 계약 (구현 전 합의안)

| 항목 | Codex가 제공할 의미 | Claude가 다룰 범위 |
|---|---|---|
| criteria | 역할, 목적, 금액별 의미, 지역 우선·확대 동의, 선택 자산 | 승인된 조건 요약·수정 진입점 |

## 8. 실행 순서와 완료 조건

1. 사용자 A1~A4 답변을 승인표에 기록한다. 보류 항목에 의존하는 작업은 착수하지 않는다.
2. Codex가 C1~C5 중 승인된 범위의 데이터·상태 계약과 재현 시험을 준비한다. Claude는 승인된 UX 범위를 별도 시안에서 작업한다.
3. 데이터/API 계약 변경이 시안에 영향을 주면 Codex가 변경 내용을 전달한다. Claude가 임의 값이나 문구로 빈자리를 채워 실제 구현으로 보고하지 않는다.
4. 사용자가 Claude 시안과 새 문구를 검수·승인한다. Codex가 승인 변경분만 통합한다.
5. T1~T12 결과와 시각 비교, 남은 항목을 사용자에게 보고한다. 미실행 시험은 통과로 적지 않는다.
6. 사용자 배포 승인 후 기존 사이트에 반영하고 실제 배포 식별자·주소·검증 범위를 HISTORY에 기록한다.

이번 문서 작업은 코드·현재 API 계약·디자인·공개 사이트를 변경하지 않는다. 신규 크롤러 국가, 어드민 확장, 멤버십·Cash 정책, 모바일 앱 제작, Claude/GPT/Gemini 전체 재배정은 별도 작업이다.
