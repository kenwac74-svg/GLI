# MY와 회원 문의 접수

2026-10-13 WORK-SEQUENCE 6단계 / GS-020·GS-016. 기존 MY 화면 스타일과 회원 인증을 재사용한다. 새 직원 조사 큐(GS-019)는 구현하지 않는다.

## 고객 범위

- MY: 이름/이메일과 로그인·로그아웃, 실제 DB 멤버십/열람 범위, 관심자산 목록·상세 이동·해제만 제공한다. 진행 상담/예약/알림 영역은 MY에서 제외한다. 기존 상담 운영 API/별도 과거 상세 경로를 삭제하거나 비활성화하지 않는다.
- 관심자산은 SQL0020의 안정 참조를 읽는다. 외부·fixture·정식 자산의 detailOrigin/referenceId를 보존한다. 표시 등급은 S~D이며 가격 단위/범위/설명과 보관 상태를 유지한다. 관심 해제는 수집 정보 자체를 지우지 않는다.
- 전문가 문의: `/my?inquiry=1` 일반 문의, `/my?consult=<stable-id>` 자산 문의. fixture의 내부 namespace를 보존한다. 비로그인은 로그인 화면으로 연결하고 문의 대상/복귀 주소를 유지한다. 잘못된 자산은 일반 문의로 몰래 변경하지 않는다.
- 이름/이메일은 회원 정보 자동 표시, 문의 내용 필수(기존 최소5·최대2000), 연락처 선택(최대120). DB 저장 성공 후 접수번호만 안내한다. 희망 일시/이메일 전송/직원 배정/예약/진행 관리 없음.

## 저장/API 계약

- `POST /api/inquiries`: Origin/JSON 검사와 로그인·ACTIVE 회원 확인. 입력은 submissionKey/requestText/contact/선택 assetId. userId/name/email 입력은 권한/신원으로 사용하지 않는다.
- 서버에서 자산을 조회하여 안정 참조를 확보한다. SQL0021의 private `member_inquiries`에 서버 회원 이름/이메일, 본문/선택 연락처/자산 ID를 저장한다. 기존 consultations 테이블의 예약/배정 lifecycle과 분리한다.
- `(user_id,submission_key)` 유일성 및 내용 hash. 같은 폼의 같은 내용 재시도는 같은 접수번호를 반환한다. 같은 키의 다른 내용은400. 계정 간 키는 분리한다. 네트워크 실패 시 폼 내용/키를 유지하고 저장 성공처럼 표시하지 않는다. 새로고침/다른 기기까지의 동일 문의 자동 판정은 제공하지 않는다.
- 응답: `{receiptNumber,status:"RECEIVED",created}`. 신규201/재시도200, no-store. 조회/관리 endpoint는 추가하지 않는다. 저장·감사 로그는 하나의 DB transaction이며 감사 로그에 문의 본문/연락처/이메일을 복사하지 않는다.
- 관리자 처리/개인정보 보존·삭제/이메일 연계는 정식 서비스의 별도 정책·권한 설계 대상이다. 운영자는 이번 임시 어드민에서 접수를 처리할 수 있다고 가정하지 않는다.

## 검증

- 실제 LOCAL0021 적용 전후9 listings/56 discovered/1 legacy favorite 유지, 새 문의0건. 공개 DB는 변경하지 않았다. 기존 migration ledger 문제가 있어0021만 명시적 --local 적용했다.
- 격리 SQLite: 회원 신원/선택 연락처·외부 참조, 일반 문의, 중복/동시 재시도, 계정 분리/비활성/입력 제한, 감사 실패 시 rollback. Built worker: 비로그인401/위조 신원 무시/중복200/관련 fixture 폼/invalid ID·빈 메시지400.
- 실제 브라우저 MY 메뉴→로그인 및 상세 문의→fixture 참조·로그인 복귀 주소 유지 확인. 실제 회원 로그인 이후 입력/접수/새로고침/해제 화면과 실휴대폰은 미검수. work/my-login-20261013.png는 비로그인 화면 증거일 뿐이다.
- 최종353개 테스트/타입/빌드/lint/migration 검증. 한국어·영어 전수 검수는 순서7에 남긴다. 유료 AI/새 수집/권한 확대/실결제/커밋/푸시/공개 배포 없음.

## 차후 Claude 역인계

MY의 세 영역 한정, 회원 자동 정보/선택 연락처 문의 폼, 접수번호 확인, 관심자산 보관/해제 상태를 큰 UI 개편 시 원본 디자인에 통합한다. 이번은 기존 스타일의 기능 연결·범위 정리이며 새 시각 방향을 채택하지 않았다.
