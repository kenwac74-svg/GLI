# 수집 매물 보관·관심자산 DB 설계안

상태: 2026-10-13 사용자 설계 승인. 구현 계획은 `docs/superpowers/plans/2026-10-13-discovery-retention.md`에서 검토 대기이다. 제품 구현/DB 변경/공개 배포는 아직 시작하지 않는다. WORK-SEQUENCE 2번 범위이며 AI 품질/새 수집원/유료 호출은 포함하지 않는다.

## 확인된 현재 구조

- `db/discovery-repository.ts`: 정규화 후보의 save/list/get, D1의 최신 payload 저장 및 얇은 갱신 보존. 별도 변경 버전 저장은 없다.
- `discovered_assets`: public_id와 출처 URL/거래 유형 유일성, 최신 payload, 최초 확보/확인 시각. 최신 정보와 조회 목록 개수 제한은 전체 저장 보관 정책과 별개이다.
- `favorites`: 계정과 정식 listings 내부 ID의 관계. 외부 후보/미등록 샘플에는 연결되지 않는다.
- `lib/discovery-storage.ts`: LOCAL/DEMO 및 D1 설정 경계. 기존 repository를 재사용하며 공개 저장 API를 새로 열지 않는다.

## 확정 정책

실제 확보한 수집 대상 후보는 Top5/사용자 선택과 무관하게 보관한다. 삭제/거래 완료된 관심 기록도 마지막 확보 정보를 유지한다. 변경은 최신본과 이력, 동일 내용은 확인 시각만 갱신한다. 확실한 동일 매물만 묶고 출처별 자료를 유지한다. 고객은 최신 정보와 가격 이력만 보고 전체 이력은 관리용이다.

## 제안 구조

1. 자산 참조: 정식 listing/외부 discovery/승인 샘플을 안정적인 public ID로 참조하는 서버 계층을 둔다. 기존 public ID/상세 URL/관심 기록을 바꾸지 않는다. 샘플 정보를 외부 실제 사실로 변환하거나 가짜 검증 등급을 부여하지 않는다.
2. 관심 관계: 사용자 ID + 자산 참조 ID 유일 관계로 확장한다. 기존 favorites 데이터를 보존해 이전하고 기존 API 계약/감사 이력/계정 격리/한도를 유지한다. 관심 해제는 관계 해제이지 수집 매물 삭제가 아니다. 기존 테이블을 먼저 삭제하지 않는다.
3. 최신본/버전: 기존 discovery 최신 저장 경계를 확장해 의미 있는 내용 hash와 변경 버전을 관리한다. 새 정보 저장과 버전 기록은 원자적으로 처리한다. 동일한 연속 내용은 버전을 늘리지 않지만 A→B→A 변화는 새 변경 사건으로 남긴다.
4. 보관 상태: 원문 삭제/거래 완료/확인 실패를 구분한다. 단순 403/timeout을 삭제나 거래 완료로 판정하지 않는다. 마지막 정보 조회를 유지하고 현재 추천 가능 여부를 별도로 판단한다.
5. 출처 묶음: 출처별 레코드를 남긴 채 그룹/별칭 관계로 묶는다. 증거 없는 제목·면적 유사도만으로 병합하지 않는다. 동일 호실 식별 근거가 없으면 별개 보관한다. 기존 ID는 그룹 후에도 조회/관심 해제가 가능해야 한다.

## 변경 비교·표시 계약

- 비교는 부분 갱신을 기존 정보에 안전하게 합친 뒤 수행한다. 누락 필드가 기존 설명/사진/제원을 지우지 않는다.
- 확인 시각, 실행별 FX 참고가격, 표시용 번역만 달라진 경우 매물 원문 가격/내용 변화로 기록하지 않는다. 원문 수정 시각과 GLI 관측 시각을 구분한다.
- 가격 이력은 같은 출처/거래 유형/원문 통화 기준으로 기록한다. 환율 변화, 다른 포털의 다른 호가, 월세와 매매 가격을 하나의 가격 변동처럼 합치지 않는다.
- 고객 API에는 최신 공개 정보와 가격 변경 내역만 내보낸다. 전체 payload 버전/내부 병합 근거/수집 오류/운영 로그는 관리 권한 뒤에 둔다.
- 고객용 가격 이력 디자인은 Claude Design 승인 후 연결한다. DB/API부터 준비하며 임의 새 그래프/패널을 만들지 않는다.
- 모든 단계에서 인증·소유권 검증은 서버가 수행한다. client가 보내는 user ID/자산 사실/등급은 저장 근거가 아니다.

## 이식·진행 경계

- LOCAL D1 마이그레이션과 repository 중심으로 구현한다. 기존 데이터는 보존하고 되돌림/중단 시나리오를 검증한다. 공개 DB 마이그레이션은 별도 지시가 필요하다.
- AWS 이전에서는 업무/API/ID 계약을 유지하고 DB adapter를 교체한다. D1 전용 SQL은 repository 밖으로 전파하지 않는다.
- 이미지 URL/이미지 메타데이터 이력은 보존한다. 실제 파일 사전 확보·byte hash·객체 버전 관리는 기존 P53 후속으로 남기며 이번 단계에서 추가 다운로드를 하지 않는다.
- 후보 저장은 기존 수집 성공 결과에 연결한다. 저장 실패를 정상 영속 저장처럼 숨기지 않고 이미 확보된 후보 응답과 저장 실패 상태를 구분한다. 새 수집 확대/AI 호출은 하지 않는다.

## 완료 증거

저장→재조회→재시작 보존, Top5 밖 후보 저장, 신규/동일/변경/가격 되돌림 버전, 누락 필드 보존, 삭제/완료 매물 관심 유지, 병합 후 ID 복원, 사용자 간 격리, 내부 이력 비공개를 시험한다. 코드/SQLite/실제 로그인 브라우저/공개 환경 검수는 따로 보고한다.

설계 승인 후 현재 코드에 맞춘 변경 파일/마이그레이션/테스트 순서의 구현 계획을 작성하고 검토받는다.
