# GLI-052 최종 시안 로컬 통합

## 승인과 범위

사용자 요청: "시안을 모두 반영해서 커밋 푸시 하기 직전 버전을 보고 싶다."
GLI-052-R 보완본의 상담 디자인/상태/표시 문구를 로컬 검수본에 통합한다.
이 요청은 커밋·푸시·공개 배포 승인이 아니다. 과거 승인 대기 문구는 로컬
검수 범위에서 채택하며, 실제 운영 답변을 시안의 fallback 문장으로 바꾸지 않는다.

## 원본과 구현

- 원본: `design-handoff/source/gli-052-consultation.dc.html`. 수령본 그대로 보존.
- 기존 `gli-demo.dc.html`, 생성 정적 화면과 공통 CSS는 그대로 유지한다.
- `render-claude-handoff.mjs`가 원본 상담 CSS 블록만 별도 파일로 추출한다.
  `app/generated/claude-consultation.css`는 수동 편집하지 않는다.
- `ConsultationPanel`은 같은 템플릿 구조/클래스/문구의 React 이벤트 버전이다.
  기존 정적 패널 안에 portal로 연결하며 입력 노드를 매 키 입력마다 재생성하지 않는다.
- `lib/consultation-view.ts`는 서버 응답의 표시 projection이다. 검색·정렬·검증 등급
  결정·AI 호출·수익 추정은 하지 않는다. 부모 shell이 기존 API를 한 번 호출한다.

## 동작 계약

### 사용자 선택 목록 정렬 (2026-10-12 승인)

- 기존 정렬 메뉴를 셸 이벤트에 연결한다. `rec`는 서버/초기 카드 순서, `trust`는 표시 등급(S~D), `new`는 원문 `sourcePublishedAt` 내림차순이다. 같은 등급/날짜는 기본 순서를 유지하며 미기재/잘못된 날짜와 등급은 뒤로 둔다.
- 수집/확인/갱신 시각을 원문 등록일로 대신하지 않는다. 최초 샘플에 등록일이 없으면 최근 등록순에서도 기본 순서를 유지한다.
- 선택은 탭의 sessionStorage에 보존하고 상세 복귀/새로고침/언어 전환 시 적용한다. 표시만 재정렬하며 API 후보 순서, 추천 순위 표식, 상담 요약의 의미와 근거는 변경하지 않는다. 추가 AI/검색 호출은 없다.
- 원본 디자인 HTML/CSS는 변경하지 않는다. 코드: `lib/result-sort.ts`, `ClaudeDesignShell`; 테스트: `tests/result-sort.test.mjs`.

1. search: 서버 후보 순서 그대로 전체 목록, 최대 3건만 상담 요약. 관련 후보가
   1~2건이면 빈 자리를 만들지 않는다. 요약과 카드의 순번/가격/ID는 동일하다.
2. review/clarify: 기존 전체 결과와 순서를 보존한다. 참조 ID만 요약하며 미확인·소실
   ID는 제외하고 소실 안내를 표시한다. 기본 검색 순서를 프론트에서 다시 매기지 않는다.
3. 출처는 assetId/url/label 조합으로 구분한다. 실제 HTTP(S) URL만 링크로 만든다.
   같은 URL이어도 서로 다른 자산의 출처는 합치지 않는다. URL이 없으면 링크를 만들지 않는다.
4. 원문 답변을 개행 단위로 표시하고 마지막 무구두점 문장도 보존한다. 이전 대화는
   기본 접힘이지만 삭제하지 않는다. 후속 전송은 기존 서버의 8턴 문맥 제한을 유지한다.
5. 카드의 질문 진입점은 선택 자산 chip을 설정한다. 요청의 selectedAssetIds를 기존
   서버가 공개 자산 repository로 검증한다. 모바일 후보 선택/응답으로 키보드를 강제 열지 않는다.
6. S1: 전송 당시 composer가 보일 때(최초 질문은 전송 위치) 따라가기를 준비한다.
   scroll 이벤트의 누적 48px 이동으로 해제하고 응답 반영 직전 재확인한다. 렌더링에
   따른 앵커 보정과 사용자 스크롤을 분리한다. 해제 상태에서는 새 답변 버튼만 제공한다.
7. 후속 오류는 초안을 보존하고 실패 질문을 중복 누적하지 않는다. 재시도는 사용자
   전송 때만 한다. 조건 변경 안내는 건수뿐 아니라 ID/순서 변화도 확인한다.

## 시안에서 실행하지 않는 부분

- `window.claude`, fixture responder, 로컬 rank/도시 파서, QA 버튼·로그는 제품에 넣지 않는다.
- R11/R12의 예산 확대 버튼은 서버가 근거 있는 선택지를 반환하는 계약이 없으므로
  예시 7천만원 등의 숫자를 자동 생성하지 않는다. 현재는 실제 AI의 질문에 입력으로 응답한다.
  원본도 options가 없으면 질문 문장만 표시하는 계약이다.
- R15~R22는 시안 fallback/프롬프트다. 실제 Astra/Gemini 정책을 덮어쓰지 않는다.
- 전문가 상담 신청은 기존 coming-soon 상담 경로를 유지한다. 직원 상담 서비스가
  실제 개통됐다는 뜻이 아니다.
- 환산가는 API의 rate가 있을 때만 같은 환율로 양 끝을 표시한다. 실시간 환율
  필터와 다양한 통화 확장은 기존 GS-013 잔여 작업이다.
