# GLI-052 상담 아키텍처 검토안

2026-09-18 / 제안 상태. A1·A4는 승인됐지만 이 아키텍처·AI 이용 정책·추가 호출 비용은 확정하지 않았다. 이 문서는 현재 구현을 설명하는 API 계약이 아니다.

2026-09-30 P42 추가: Jev는 자유 답변이나 투자 판단이 아닌 첫 질문의 매입/임차 모호성 판단에만 제한 도입했다. 명확한 질문은 Jev 없이 기존 Astra 의도 해석 → 검증된 수집/필터 → Astra 상담, 조건부 Gemini 탐색·번역을 사용한다. Jev가 확실한 모호성이라고 판단하면 후보 조회 전 확인 질문 한 개를 반환한다. 불확실/실패 시 Astra로 복귀한다. 아래의 과거 다중 모델 확장 제안이 Jev 후보 재정렬이나 자율 도구 루프로 구현된 것은 아니다. 현재 계약과 검증 한계는 [API-CONTRACTS.md](API-CONTRACTS.md)의 P42 항목을 따른다.

### P42의 실제 빠른 경로와 확대 조건

| 요청 | 지금 실행하는 단계 | 목적 |
|---|---|---|
| 매입·임차가 명확하거나 후속 상담 | 기존 Astra 의도 → 필요한 출처/Gemini → 근거 상담. Jev 0회 | 불필요한 직렬 호출 방지 |
| 첫 자산 탐색에서 매입·임차가 불명확 | Jev 1회; `clarify` 확률 0.95 이상과 집중도 0.85 이상이면 확인 질문 1개 | 다른 거래 유형의 후보를 먼저 수집하지 않음 |
| Jev가 불확실/실패 | Jev 1회 후 기존 Astra 경로. 재시도 없음 | 잘못된 고정 질문보다 상담 품질 우선 |

숫자/예산이나 거주·투자 단서가 있으면 Jev에 넘기지 않는다. 지역·거래 유형·예산을 확정하거나 후보를 승인하는 주체는 서버 검증과 근거 상담이며 Jev 선택값이 아니다. 현재 응답은 동기식 JSON이고, 공급사 호출별 시작/종료/토큰/비용은 기존 내부 원장에만 기록된다. 고객에게는 하나의 GLI AI로 보이며 Fable은 참여하지 않는다.

후속 확대 순서는 (1) 실제 익명화 질문의 `clarify/continue` 정답 라벨 수집, (2) Jev·기존 경로의 오분류와 요청 전체 지연·비용 비교, (3) 부정확한 확인 질문이 충분히 낮을 때만 임계값 조정, (4) 검증된 후보 사실만 대상으로 별도 의미 매칭 실험이다. 현재 0.95/0.85는 실데이터로 보정한 값이 아니다. 한 번의 약 605ms 모델 응답이 전체 상담의 속도 개선을 보장하지 않으며, Jev 불확실 경로는 오히려 최대 2초 느려질 수 있다. 문제 발생 시 `GLI_JEV_ROUTING=disabled`로 이 분기만 끄고 기존 경로를 유지한다.

후속 결정: 같은 날 사용자가 제한된 비로그인/무료 실제 AI 체험 방향 및 OpenRouter 모델 비교를 승인했다(P30/P31). 현재 비교 대상은 Fable/Astra이고 Gemini는 별도 API로 유지한다. [현재 구현](OPENROUTER-COMPARISON.md)은 상담 adapter와 내부 비교 도구이며 아래의 상태/도구 루프 전체가 구현된 것은 아니다. 아래 승인 대기 설명은 당시 검토 기록이고 체험 수량·공개 배포는 여전히 미확정이다.

## 문제 정의

### 2026-09-18 승인 후 1차 구현

사용자의 "진행해"로 Astra 주 상담/의도 선해석 연결을 승인받았다(P32). 기존 검토안 전체나 공개 배포 승인은 아니다.

- 로컬 `LLM_PROVIDER=openrouter`, `OPENROUTER_MODEL=openai/gpt-6-astra`, `GLI_LOCAL_AI_PREVIEW=enabled`. Gemini 직접 API 탐색은 유지한다.
- 현재 OR 경로: 이용권 확인/차감 → Astra 의도 구조화(최대 30초/4096 tokens) → 서버 검증 → 기존 출처 수집/Gemini scout → 동일 조건의 엄격 필터 → Astra 근거 상담(최대 90초/8192 tokens).
- 한 요청에 OR 최대 2회, 자동 재시도/대체 모델 없음. 별도 Gemini discovery 호출은 기존 조건을 따른다. 고정 순차 파이프라인이며 자율 도구 반복은 아니다.
- `criteria.consultation`에 통화별 예산/총예산/거주 월세와 목표 월수입(표면/순수입/미정), 완공·임차인·가구·현금 매수 요청을 보존한다. 기존 최대 8턴 및 클라이언트 context 계약과 호환된다.
- 국가/도시는 기존 서버 해석 경계로 고정한다. 모델이 국가/도시/임의 URL/도구 실행 인자를 출력할 수 없다. 다국가 대안 동의, 지원하지 않는 도시 별칭, 선택 후보 기억은 후속 작업이다.
- 완공/임차인/가구/총취득비용/실제 임대료는 표준화된 증빙 필터가 아직 없다. 상담 모델에 미확인 조건으로 전달하며 가격 통과를 조건 전체 충족으로 설명하지 않는다. 검증 불충분 시 후보 0건 선택도 가능하다.
- 예산 환산은 기존 1380 KRW/USD 데모 값이며 최신 환율이라고 인용하지 않는다. 총예산에서 추정 세금/수수료를 차감하지 않는다. 실시간 검색 환율/다통화 비교 정합성은 GS-013 잔여 작업이다.
- 모델 실패는 규칙 경로로 복귀한다. 공개 응답은 기존 `ai|rules`만 유지하며 공급사/비용/키/실패 내부 코드를 노출하지 않는다. 의도 단계만 성공한 부분 실패를 사용자에게 표시하는 UX는 추가 설계 대상이다.
- 합성 3턴(총 6회 OR) 실호출에서 의도/예산/지역/완공/승계 유지 통과. API 보고 비용 $0.149044, 턴당 약 9~13초. 실제 수집 시간을 포함한 전체 서비스 지연의 측정값은 아니다.

아래 "현재 경로"와 미승인 표현은 **이 구현 전의 검토 기록**이다. 최신 구현 계약은 API-CONTRACTS/CURRENT-STATE/HISTORY를 따른다.

목표는 검색 화면의 문장을 부드럽게 바꾸는 것이 아니라 사용자가 대화의 연속성을 느끼도록 만드는 것이다. 질문의 의미, 이전 조건, 선택 자산, 답할 수 있는 자료를 함께 판단해야 한다. "사업은 언제나 제외", "항상 3개 표시", "예산부터 필수 입력" 같은 고정 분기는 A2·A3 미승인 사항이다.

현재 경로는 대체로 규칙 조건 추출 → 수집/후보 선택 → advisor 설명이다. `lib/ai-search.ts`의 runAdvisorSearch는 모델 호출 전에 searchAssets를 실행한다. 모델은 이미 좁혀진 후보를 설명·재정렬할 뿐 검색 조건 자체를 충분히 수정하지 못한다.

공개환경의 `app/api/search/route.ts`는 회원 이용권/잔여량이 없는 경우 advisor provider를 disabled로 넘긴다. 로컬 Gemini 미리보기와 공개 비로그인 이용은 다르다. 당시 스크린샷이 비로그인 규칙 경로였는지는 해당 응답·로그를 확인해야 하며, 키 오류라고 단정할 수 없다. 기존 수집/Gemini 탐색이 회원 사용량 판단보다 먼저 실행될 수 있는 비용 경계도 같이 검토한다.

## 제안: 상태를 가진 도구 사용형 상담자

사용자 메시지 → 상담 상태/최근 대화 읽기 → LLM이 의도와 다음 행동 제안 → 서버 검증 → 필요한 도구 실행 → 근거를 받은 LLM 답변 → 상태·자산 ID·UI 동시 갱신.

일회성 고정 파이프라인이 아니라 제한된 반복 구조다. 설명만 필요한 질문은 도구 없이 답하고, 필요하면 조회나 계산 결과를 받고 답한다. 호출 수·시간·비용 상한은 서버에서 강제하며 무한 반복을 허용하지 않는다.

### 1. 공유 상담 상태

- 목적/역할: 임대수입 투자, 본인 거주 임대, 계절 체류, 사업 참여 등. 명시 사실과 해석 가설을 구분한다.
- 금액: 총투자예산, 매입가 한도, 목표 월수입, 거주 월세 지출을 각각 통화·기간·표면/순수입 여부와 함께 저장한다.
- 지역: 우선 지역과 대안 허용 지역을 구분하고 사용자의 확대/철회 동의를 보존한다.
- 맥락: 검토한 후보 ID, 선택 자산 ID, 배제 이유, 직전 확인 질문, 사용자가 수정한 조건, 미확정 정보.
- 기억: 최근 대화와 요약, 검증된 구조화 상태를 함께 사용한다. 요약문만으로 금액·동의·자산 ID를 재구성하지 않는다.
- 검증: LLM은 변경안을 제안하고 서버가 명시된 변경만 반영한다. 클라이언트 조건과 선택 ID를 무조건 신뢰하지 않는다. 세션 간 정보는 격리한다. 보관 기간/계정 간 복원 정책은 별도 결정한다.

### 2. 다음 행동 선택

LLM이 설명, 확인 질문, 현재 자료 조회, 허용 출처 추가 탐색, 특정 자산 확인, 후보 비교, 수익 시나리오 계산 중 필요한 행동을 선택한다. 선택 근거는 사용자 의도·자료 유무·빠진 정보가 결과를 얼마나 바꾸는지다.

- 예산이 없더라도 가능한 비교나 설명은 진행할 수 있다. 예산 없음을 예산 적합으로 바꾸지는 않는다.
- 빠진 정보가 잘못된 추천을 만들 때는 중요한 질문부터 묻는다. 같은 질문을 반복하거나 모든 대화를 설문으로 바꾸지 않는다.
- 후보 수는 근거·질문의 폭·비교 필요성에 따라 정한다. API 반환 상한과 화면 요약 개수는 상담 정책과 구분한다.
- 일반적인 검토 방법은 설명할 수 있다. 최신 시세·세금·가격·수익률은 조회 근거 없이 구체적인 수치로 단정하지 않는다.

### 3. 서버 도구와 권한 경계

권고 도구는 자산 조회, 허용 출처 탐색, 개별 자산/임대 근거 조회, 환율 조회, 후보 비교, 입력 근거 기반 수익 계산이다. 초기 도구는 읽기 전용 중심으로 제한한다. 새 국가 출처 연결이나 관심 등록/상담 신청 등 쓰기 작업은 각각 승인된 범위와 사용자 액션에 연결한다.

LLM은 도구 이름·인자를 제안한다. 서버가 허용 출처, 지역 범위, 데이터 타입, 사용자 권한, 호출 예산을 검증한 뒤 실행한다. 모델이 임의 URL 수집, DB 직접 수정, Trust 재계산, 결제, 자동 게시를 하지 못하게 한다. 수집된 문서 속 지시는 데이터로 취급한다.

가격/통화 계산과 건수는 결정적 서버 함수가 맡는다. 결과마다 근거, 조회 범위, 자료 시점, 자산 ID를 반환한다. 같은 건물 임대 호가와 해당 호실 실제 계약은 다른 근거다. 부족한 입력을 가짜 숫자로 채워 수익률을 계산하지 않는다.

### 4. 답변과 UI의 하나의 결과 계약

자연어 답변, 참고 후보, 적용 조건, 확인 질문, 선택 자산, 후보 개수는 동일 resultSet을 참조한다. 답변 생성 모델도 검증된 ID만 인용한다. UI는 시안 카드의 가상 값을 검색 데이터 대신 보여주지 않는다.

Claude는 한 가지 고정 답변 템플릿이 아니라 설명만 있는 답변, 질문이 필요한 답변, 후보/비교가 있는 답변, 일부 근거 부족, 재시도 상태를 설계한다. 최신 답변 아래 입력창과 특정 후보 이어 묻기는 승인된 A4 범위다. 새 문구와 시각안은 별도 승인한다.

실제 진행 이벤트와 답변 텍스트 스트리밍을 구분한다. 내부 추론이나 공급사 이름을 보여주지 않는다. 모델 실패를 성공적인 근거 검토처럼 꾸미지 않고, 내부에서는 fallback 원인을 구별한다.

### 5. 모델 수와 비용

2026-09-23 확정 P36: Fable은 일단 상담 흐름/추가 유료 비교에서 제외한다. 아래 다중 모델 확장 논의는 과거 제안이며 즉시 구현할 요구사항이 아니다. Astra 의도 해석/상담과 Gemini 탐색 보조/번역만 현재 역할로 유지한다. Claude Design 작업은 이 결정과 별개다.

초기에는 기존 연결 모델 하나를 주 상담자로 삼아 상태·도구·답변 품질부터 검증하는 안을 권고한다. 모델을 한 번 호출한다는 뜻은 아니며 조회 결과를 받아 답할 때 추가 호출이 필요할 수 있다. 호출 수와 응답시간은 측정한다.

기존 세 모델 활용 구상을 폐기하는 것은 아니다. 이후 동일한 상담 상태/근거 계약 뒤에서 탐색·심화 검토 역할을 교체할 수 있게 한다. 매 턴 세 모델을 직렬로 호출하거나 모델별 별도 기억을 만들지 않는다. 어느 모델이 좋은지는 GLI 실제 시나리오 평가로 정한다.

모든 유료 도구·모델 호출 전에 이용권과 사용량을 확인한다. 기존 결과 재사용, 필요한 필드만 전송, 변경 조건만 재검색, 호출/시간 제한으로 비용을 통제한다. 한도 수치, 체험량, 실제 비용 증가는 측정 후 사용자에게 제안한다.

## 이번 사례의 기대 흐름

1. 처음 질문: 월세 수입을 얻을 투자, 프놈펜 우선, 다른 국가도 허용, 예산 미정으로 이해한다.
2. 현재 자료로 할 수 있는 설명/조회는 수행하고, 추천을 크게 바꾸는 미확정 조건을 골라 묻는다. 후보 3개나 예산 선질문을 강제하지 않는다.
3. "월세 100만원 받고 싶어": 월수입 목표로 기록한다. 매입 예산이나 임차료로 전환하지 않는다.
4. "그럼 두 번째는 왜 좋아?": 현재 결과의 두 번째 안정 ID를 참조하여 이유와 미확인 근거를 설명한다. 결과 순서가 달라져 모호하면 확인한다.
5. "다른 나라는?": 동의를 이미 받았음을 기억하고 연결된 다른 국가 자료를 조회한다. 미연결 출처를 탐색했다고 하지 않는다.

## 우선 결정할 추가 정책

**비로그인 체험에도 실제 AI 상담을 제공할지** 결정이 필요하다. 권고안은 제한된 실제 AI 체험 후 로그인/멤버십으로 이어지는 방식이다. 이는 제안이며 기존 멤버십 가격·열람권 변경 승인이 아니다. 체험 횟수·비용 상한·악용 방지·실제 오류 표현은 따로 정한다.

로그인 회원만 실제 AI를 이용하게 유지할 수도 있다. 이 경우 비로그인 이용자가 규칙 검색을 실제 AI 상담으로 오해하지 않도록 진입 흐름을 Claude와 설계해야 한다. 사용자 승인 없이 접근 정책이나 유료 호출을 확대하지 않는다.

## 검증 및 범위

평가 대상은 말투만이 아니라 의도 보존, 다음 행동 적절성, 불필요한 재질문, 근거 일치, 후보/상세 일치, 요청당 지연·호출비용이다. GLI-052 T1~T12에 동작 선택과 비로그인/회원/한도소진 경로를 추가하는 안을 제안한다.

이 턴은 승인 기록과 아키텍처 논의만 수행한다. C1 데이터 연결, C3 건수 일치, C5 진단 등 독립 작업의 착수 승인은 유지하되, A2·A3에 의존하는 추천 정책은 확정하지 않는다. 코드 수정·배포·추가 유료 호출은 실행하지 않았다.
