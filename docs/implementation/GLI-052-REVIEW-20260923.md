- 원인: 모바일 좌우 여백/패널 안쪽 여백/발화자 열에 더해 새 후보 블록이 본문 열 안에 중첩된다. 기존 좁은 본문 구조에 새 블록의 높이가 추가된다. 근거: HTML 166~190행, 1189~1285행.

## 채택할 가치가 있는 개선

- 원래 디자인 토큰을 유지하며 문단·출처·후보 이동·선택 자산 칩을 추가한 방향.
- 카드 선택이 질문을 자동 전송하지 않고 입력창에 초점을 주는 동작. 390px에서 확인.
- 후보 블록을 답변 생성 시점에 묶어 두는 구조. 과거 이력의 대상 보존에 유리하나 ID·링크 유효성은 서버 연결 필요.
- 새 문구와 변경 이력을 별도 제공하고 전체 덮어쓰기, support.js 실제 서비스 이식, 임의 API 연동을 금지한 납품 방식.
- 히어로 접기와 섹션 이동을 임의 적용하지 않고 승인 대상으로 남긴 점.

## 개선 제안과 재납품 기준

1. 모바일은 “답변 → 짧은 관련 후보 요약 → 바로 이어 묻기”를 우선하고 큰 사진/긴 후보 설명은 기존 결과 목록에서 확인하는 안을 제시한다. 중복된 긴 카드 목록을 대화 안에 만들지 않는다.
2. “추천 순위 TOP3 / 후순위”는 평가 체계가 확정되기 전 “이번 답변의 관련 후보 / 후보 더 보기” 같은 중립적 문구를 제안한다. 문구는 승인 전 적용하지 않는다.
3. 추천 이유 텍스트에 숨겨진 질문 동작 대신 “이 자산에 질문”을 알아볼 수 있는 아이콘·이름·터치 영역을 제안한다. 전문가 연결과 명확히 분리한다.
4. 이력 접기는 유용하나 첫 인사까지 “이전 대화 1개”로 세는 현재 표현은 어색하다. 일정 대화 길이 이후 접거나 질문·답변 묶음을 단위로 삼는 안을 제시한다.
5. Claude 재납품: search/review/clarify·실패·부분 결과·선택 대상 소실 상태, 총예산/월수입 두 금액, 모바일 왕복 2안, 6개 폭 캡처와 10턴·글자 확대 검수, 문서/소스 스크롤 규칙 일치.
6. Codex 통합: 승인된 UI 차이만 연결하고 기존 의도 해석·검색·번역·후보 보존 코드는 유지. 같은 ID/순서/금액/원문 링크를 카드·상담·상세에서 확인한 후 별도 배포 승인.

이 문서는 검수 의견이다. 새 디자인·문구·추천 정책 승인 또는 구현 완료를 뜻하지 않는다.

## Claude Design 직접 조율 결과 (2026-09-23)

- 사용자 요청으로 기존 Claude Design 프로젝트에서 두 차례 질의·회신. Claude는 R1~R7에 동의하고 파일 수정 없이 논의했다고 답했다. 이는 수정 완료 검수가 아니다.
- Claude는 TOP3 개수, 모바일 전환안, 새 문구 15건이 미승인임을 확인했다. “TOP3 한 화면” 주장을 철회했고, 모바일 전환 2안은 기존 완성 시안이 아닌 이번 신규 제안이라고 정정했다.
- 담당: Claude는 모바일 배치, 단일 후보 순서 표시, 상태별 예제 화면, 출처 표시, 문단 보존, 스크롤/초점, 별도 QA와 변경 위치 목록. Codex는 실제 조건 필터·정렬·AI·mode·resultSet·인용 연결 및 현행 소스에 선별 통합.
- 실제 citations에는 assetId/label/sourceName?/url?가 있음(lib/ai-search.ts 확인). assetId+url 관계를 보존하며 동일 URL의 다른 자산 참조를 제거하지 않는다. previousAssetIds 최대 18을 서버 검색 상한으로 오해한 회신을 정정했고 returnedCount는 matches.length임을 재확인했다.
