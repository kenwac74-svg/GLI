# P-010 다섯 유형: GPT Instant 웹과 OpenRouter 직접검색

## 결론

**양쪽 모두 다섯 유형을 실행했다. 직접검색은 후보와 근거를 제시하고 후속 문맥을 유지할 수 있었지만, GPT Instant 웹 수준의 전체 이용 경험과 속도를 충족했다고 결론 내릴 수는 없다.** API는 실제 요청 5회, 비용 보고값 합계 **$0.121162**, 총 **25,519토큰**이었다. 이번 승인 범위를 마친 뒤 추가 호출하지 않았다.

GPT Instant 웹은 사진·지도·비교표·선호도 선택·계산기를 표시해 사용자가 다음 판단을 하기 쉬웠다. 반면 API는 텍스트 위주이며, 원화 예산을 판정하지 못하고 단순 설명에도 검색했다. 다만 **Instant의 매물/수치가 정확성의 정답지는 아니다.** 1번에는 환산 가정과 표 금액이 10배 모순되는 문제가 실제로 보였다. 이번 검수는 출력/내부 계산/출처 연결의 관찰이며, 모든 외부 원문의 정확도나 매입·임차 가능성을 검증한 것은 아니다.

## 시험 조건

- 기준: **사용자가 지정한 ChatGPT 웹의 Instant 모드**. 로그인된 웹 UI에서 Instant 선택을 확인했고 매 대화에서도 표시를 확인했다. API 결과나 Gemini로 대체하지 않았다. 기반 모델의 내부 ID·계정 개인화 설정은 확인/변경하지 않았다.
- 대상: P-010의 `openai/gpt-6.1-sol`, OpenRouter `openrouter:web_search` / Exa fast. **기존 system 문구까지 유지**했다. `max_tool_calls=1`, `max_uses=1`, 결과 최대5, 각2,000자, 출력2,200토큰, low reasoning, 90초 제한, 공급자 fallback 없음.
- 모델·검색 설정은 도중 바꾸지 않았다. 원래 P-010 실제 요청 JSON과 대조해 일치함을 검증했다. 질문/이력만 다르며, 다섯 요청의 설정 지문은 모두 `a6578b06841b28228e7ad72be036d659ce5c1d2248bfb038ed50201b798eec90`이다.
- 양쪽 모두 실행 순서는 **1 → 2 → 5 → 3 → 4**. 1~4는 각각 새 대화였다. 5는 2 직후 같은 대화에서만 실행했다. 서비스 사이의 작업은 섞여 진행됐지만 각 서비스 내부에서 다른 질문을 끼워 넣지 않았다.
- 웹의 실제 두 번째 후보는 **Wyne by Sansiri**, API는 **Chambers On Nut Station, 6층**이었다. API 5번에는 2번의 실제 질문·답변·출처 annotations를 전달했다. 임의 후보나 다른 서비스의 결과를 전달하지 않았다.
- 실제 유료 API POST는 5회였다. 별도 회계 조회·모델 비교·재생성·재시도는 없다. 사용자의 이번 다섯 유형 지시가 이전 단일 요청 이후의 추가 시험 승인이다. 기존 검색 횟수 계측 불일치는 해결됐다고 간주하지 않고 고정 설정 그대로 관찰했다.
- 현재 GLI 상담·Gemini·DB·수집기·운영 서비스·배포·B안은 모두 제외했다. 웹에 추가 system 문구를 넣지 않아 제품 경험 비교이지, 동일 프롬프트/검색 코퍼스의 모델 성능 A/B는 아니다.

## 정확성에서 분리해서 볼 것

1. **웹 1번의 내부 환산 모순:** 본문에는 `1억 VND ≈ 55만 원`이라는 가정을 썼지만 표에는 `23억 VND ≈ 1억 2,650만 원`이라고 표시했다. 본문의 가정대로면 `23 × 55만 원 = 1,265만 원`으로 표와 10배 차이다. 실제 환율이 무엇인지는 이번에 확인하지 않았으며, 어느 쪽을 임의로 정답으로 고치지 않았다. `web-case-1.json`과 전사에 원문을 보존했다.
2. **수익률의 연결:** 웹의 지역 평균/가정 시뮬레이션은 개별 매물의 실제 임대료가 아니다. API의 Akari 수익률은 광고의 매매가/임대계약 주장에 따른 총수익률이지 순수익이나 실제 입금 검증이 아니다.
3. **자료의 수준:** 웹의 목록/프로젝트 페이지 링크, 단지 참고 이미지, API의 개별 광고 발췌는 서로 다른 수준이다. 링크·사진이 있다는 이유만으로 해당 호실의 최신 상태나 외국인 취득 가능성을 인정하지 않는다.
4. **웹 설명4의 4.1%:** 비용을 명시적인 가정으로 제시했고 `600-50-50-30-60=410만원`의 내부 계산은 일치했다. 실제 특정 자산의 수익률로 해석하지 않는다. API는 가상 비용을 만들지 않고 수익률의 정의와 차감 항목을 설명했다.

## 웹 시간 측정의 한계

웹 다섯 응답은 모두 **완료 상태와 Instant 표시**를 관찰했다. 그러나 브라우저 관찰 사이에 다른 검증이 진행됐고 2번의 대기 도구에 CDP 시간초과도 있었다. 따라서 **정확한 첫 본문/완료 시간 및 웹↔API 속도 우열은 판정 보류**다. Gemini/API로 대체하거나 관찰 상한을 실제 응답 시간으로 쓰지 않았다.

원시 웹 기록에는 관찰 상한과 측정 노트가 남아 있다. 1·4번은 본문 DOM을 읽기 전 probe 시간을 처음 본문 시간처럼 기록했던 것을 발견해 해당 값을 비교 지표에서 제외하고 정정 이유를 보존했다. 2번의 초기 paragraph locator도 입력창/기존 DOM을 잡을 수 있어 폐기했다. 불완전한 계측으로 “웹이 더 빠르다/느리다”는 수치를 만들지 않았다. 추후 정확한 속도 비교에는 별도 승인된 동일 관찰 방식이 필요하며 이번에 재실행하지 않았다.

## 원인 해석과 다음 검토 사항

- **모델 교체만으로 해결되지 않는다.** 현재 P-010 system은 모든 질문에 현재 웹 검색을 요구한다. 그대로 유지해 시험했으므로 4번의 불필요한 검색은 모델 자체의 한계로 단정할 수 없다. 다음 설계 검토에서는 일반 설명/앞선 정보 답변/신규 탐색을 구분하는 응답 정책을 검토할 수 있다. 이번에는 바꾸지 않았다.
- **원화 조건을 해결할 도구가 없다.** 이번 직접검색 경로에는 기존 GLI 환율 API/숫자 필터가 없었다. 그래서 검색은 성공해도 예산 판정이 멈췄다. 모델에게 환율을 만들어 내게 하는 해결은 채택하지 않는다.
- **유용한 근거와 고객 화면은 별개다.** API는 출처 annotations와 설명을 반환했지만 사진·지도·선호도 UI를 생성한 것은 아니다. 웹에 보이는 구성이 유용했다는 관찰과 GLI에 그 디자인을 승인했다는 판단은 구분한다. 표시된 웹 계산기/지도/버튼을 추가 조작해 기능 검수하지 않았다.
- **‘다음 질문 하나’와 답변 길이를 줄여야 한다.** 특히 API3 끝의4항목과 API4 긴 설명은 목표 UX와 어긋난다. 정확성을 버리기보다 지금 결론/가정/확인할 것/한 질문을 분리하는 정책을 다음 연구로 넘긴다.
- **비용 제어 계약 확인이 선행돼야 한다.** 고정 한도1과 사용량 보고4/5 불일치는 계속 미해결이다. 승인한5요청을 모두 기록했고 추가 탐색으로 원인을 추정하지 않았다. 운영 연결은 하지 않는다.
