## 1. 목적

[확정] GLI가 범용 LLM보다 느리거나, 덜 구체적이거나, 덜 실용적이면 첫 번째 사용자 가치 층에서 실패다.

이 벤치마크는 그 원칙을 **숫자로 판정 가능한 기준**으로 바꾼다. 묻는 질문은 하나다.

> 같은 질문을 받았을 때, 실제 사용자에게 GLI의 답이 Gemini·ChatGPT·Claude의 답보다 덜 유용한가?

사실 정확성만 재지 않는다. 핸드오프 3장의 지시대로 **실제 사용자에게 주는 실용적 유용성**을 잰다.

## 2. 비교 대상

| 구분 | 대상 | 조건 |
|---|---|---|
| GLI-익명 | glibiz.net 비로그인 | `tools/parity-probe.mjs`로 자동 측정 |
| GLI-회원 | glibiz.net 회원 로그인 (AI 상담 경로) | 사람이 화면에서 측정. 측정 계정 플랜 기록 |
| LLM-G | Gemini (웹 검색 켬) | 새 대화, 개인화·메모리 끔 |
| LLM-C | ChatGPT (검색 켬) | 새 대화, 메모리 끔 |
| LLM-A | Claude (웹 검색 켬) | 새 대화, 메모리 끔 |

[제안] 같은 날, 같은 질문 문장, 같은 언어로 측정한다. 모델명·버전·플랜을 기록한다.

[주의] 이 문서를 쓴 Claude는 LLM-A와 같은 계열이다. 선수와 심판이 겹치지 않도록 **채점은 출처를 가린 상태로 사람이 한다**(6장).

### 2.1 데모를 측정한다는 것의 의미

glibiz.net은 사내 시연용 프로토타입이다(사용자 확인, 2026-10-06). 따라서 측정 결과를 두 종류로 나눠 해석한다.

| 구분 | 예 | 해석 |
|---|---|---|
| 데모 범위의 한계 | 등록 자산이 20건뿐이라 후보가 적음, 일부 국가 수집기 미연결 | 완성 시 해소될 수 있음. 점수에서 감안하되 **완성 계획이 있는지** 확인 |
| 로직의 결함 | 국가·의도 오인, 후속 대화 단절, 후보 0건으로 종료하는 규칙 | 데이터가 늘어도 그대로 남음. **완성본에서도 고쳐야 할 설계 문제**로 분류 |

벤치마크의 목적은 "데모가 지금 범용 LLM을 이기느냐"가 아니라, **데모가 구현한 설계가 완성됐을 때 범용 LLM을 이길 수 있는 구조인가**를 판정하는 것이다.

## 4. 측정 항목

### 4.1 객관 지표 (자동·스톱워치)

| 지표 | 정의 |
|---|---|
| TTFU | 질문 전송 → **사용자가 읽을 수 있는 첫 유용한 내용**이 화면에 나타날 때까지 (초) |
| TTC | 질문 전송 → 답변 완료까지 (초) |
| 후보 수 | 이름이 특정된 프로젝트·단지·매물 수 |
| 실시간 링크 수 | 클릭 시 실제 매물·공식 페이지로 연결되는 링크 수 (사후에 직접 열어 확인) |
| 국가 일치 | 요청 국가와 다른 국가 후보가 섞였는지 |
| 근거 없는 확정 표현 | "검증됨", "수익 보장" 등 근거 없이 확정한 문장 수 |

LLM은 스트리밍되므로 TTFU가 짧다. GLI는 현재 단일 응답이라 TTFU ≈ TTC 다. [사실: `app/api/search/route.ts`]

### 4.2 채점 항목 (0~4점, 사람이 채점)

핸드오프 3장의 9개 항목.

| # | 항목 | 0점 | 2점 | 4점 |
|---|---|---|---|---|
| D1 | 속도 체감 | 15초 넘게 아무것도 없음 | 5~15초 | 3초 안에 읽을 거리가 나옴 |
| D2 | 탐색 폭 | 후보 없음 | 후보 1~3 또는 한 지역만 | 여러 도시·지구·유형을 근거와 함께 제시 |
| D3 | 구체성 | 일반론만 | 지역명 수준 | 프로젝트명·가격대·임대료 범위·세입자 유형까지 |
| D4 | 실시간 출처 유용성 | 링크 없음/죽은 링크 | 일부 유효 | 바로 확인 가능한 매물·공식 링크 다수 |
| D5 | 투자 의도 적합성 | 의도를 잘못 해석(매입↔임대, 국가 오류) | 대체로 맞음 | 수익률·공실·관리비 등 의도 핵심을 다룸 |
| D6 | 다국어 처리 | 언어 혼선·번역 누락 | 부분적 | 현지어 자료를 사용자 언어로 자연스럽게 정리 |
| D7 | 불확실성의 투명성 | 근거 없는 확정 / 혹은 아무 답도 안 함 | 일반적 주의 문구 | 무엇이 확인·추정·미확인인지 항목별로 구분 |
| D8 | 다음 행동의 질 | 없음 | 일반적 조언 | 구체적 확인 경로(누구에게, 무엇을, 어떤 서류) |
| D9 | 탐색 이후 이어 가기 (S1-F 위주) | 대화가 끊기거나 초기화 | 일반론으로 답 | 해당 후보를 기준으로 조사·확인 작업을 실제로 진행·제안 |

[제안] 가중치는 두지 않는다. 9개 평균과 함께 **최저 항목**을 같이 본다. 한 항목이 0점이면 그 자체로 실패 신호다.

### 4.3 안전 게이트 (점수와 별도)

다음은 점수와 무관하게 **실격**으로 기록한다.

- 요청 국가와 다른 국가의 자산을 같은 국가인 것처럼 제시
- 검증되지 않은 사실을 "검증됨", "확인됨"으로 제시
- 수익 보장·원금 보장 취지의 표현 (GLI 원칙상 금지 용어 포함)

## 5. 측정 절차

1. GLI-익명: `node tools/parity-probe.mjs --base https://glibiz.net --runs 3` → JSON 저장. 같은 시나리오를 3회 측정해 중앙값 사용.
2. GLI-회원: 같은 질문을 화면에 입력, 화면 녹화로 TTFU·TTC 측정. 사용 플랜 기록.
3. LLM-G/C/A: 각 서비스 새 대화에서 같은 질문, 화면 녹화. S1 직후 같은 대화에서 S1-F 입력.
4. 모든 답변 원문과 링크를 `docs/research/benchmark-runs/YYYY-MM-DD/`에 저장(개인정보·계정정보 제외).

## 6. 블라인드 채점

1. 답변에서 서비스명·로고·문체 표식을 지운 텍스트로 바꾼다. 링크는 남긴다.
2. 시나리오마다 답변 순서를 섞고 A~E 라벨을 붙인다.
3. 최소 2명이 독립 채점한다. 한 항목에서 2점 이상 차이 나면 토론 후 재채점.
4. [제안] 교차 검증으로 Gemini에도 같은 루브릭으로 채점시키되, 사람 점수를 대체하지 않는다.
5. 채점이 끝난 뒤 라벨을 공개한다.

## 7. 동등성 기준선 [제안]

GLI가 "AI 탐색에서 차별성이 있다"고 주장하려면 아래를 **모두** 만족해야 한다.

| 조건 | 기준 |
|---|---|
| C1 평균 | 7개 시나리오 평균 점수 ≥ 최고 LLM 평균 |
| C2 최저 | 어떤 시나리오에서도 최고 LLM 점수의 80% 미만으로 떨어지지 않음 |
| C3 속도 | TTFU 중앙값 ≤ 5초, 어떤 시나리오도 15초 동안 빈 화면이 아님 |
| C4 안전 | 안전 게이트 실격 0건 |
| C5 이어 가기 | S1-F에서 D9 ≥ 3 |

C1~C4를 못 넘으면 GLI는 AI 탐색을 차별점으로 말하지 않는다. 이 경우 핸드오프 결론대로 **범용 LLM 수준의 탐색은 기본기(baseline)로 맞추고**, 차별성은 탐색 이후(D7·D8·D9 영역)에서만 주장한다.

### 8.1 로컬 시험 관찰 (glibiz.net 아님)

`approved-fixture` 데이터·AI 키 없음·외부망 차단 상태의 로컬 빌드에 측정 스크립트를 돌린 결과다. **glibiz.net 결과로 인용하지 않는다.** 스크립트 동작 확인과 규칙 경로의 결함 탐지 목적이다. 아래 관찰은 2.1의 기준으로 모두 "로직의 결함"에 해당한다.

| ID | 결과 | 관찰 |
|---|---|---|
| S1 | 후보 7, 베트남 | 예산을 말하지 않았는데 "예산 안에서 7개 후보"라고 답함 |
| S1-F | 후보 0 | 후속 질문에 "베트남에는 조건에 맞는 자산이 없습니다" — **대화가 이어지지 않음** |
| S2 | 후보 4, 캄보디아 | "사서 월세 놓을 거야"를 **임대(rent)·거주 목적**으로 해석, 월세 $380~500 매물을 매입 후보로 제시 |
| S3 | 후보 0 | RLC 파트너 자산이 있는데도 도시 조건(Manila) 불일치로 0건 |
| S4 | 후보 8, **캄보디아** | **방콕 질문을 프놈펜으로 해석**해 프놈펜 콘도 제시 — 안전 게이트 실격 사례 |
| S5·S6·S7 | 후보 0 | 모두 "다른 도시나 국가까지 넓혀 검토할까요?"로 종료 |

[추론] 비회원이 glibiz.net에서 같은 규칙 경로를 탄다면(H2), 첫 방문자는 위와 같은 답을 받는다. 결정 기록(2026-10-05~06)의 "정답 시험처럼 굴지 않는다", "검증이 부족해도 후보를 숨기지 않는다"와 정면으로 충돌한다. 실측으로 확인이 필요하다.

- [미해결] 측정 주기 — [제안] 주요 배포마다 S1~S7 재측정, 점수 추이를 기록
