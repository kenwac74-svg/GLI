# P0-2A RUMAVI 정보의 수집 경로와 GLI의 정당한 확보 방안

상위 문서: `P0-2_CUSTOMER_DIFFERENTIATION.md` 부록 A를 이 문서로 대체한다.
표기: **[사실]** 공개 페이지·코드로 직접 확인 · **[추론]** 사실에서 끌어낸 판단 · **[미확인]** 외부에서 확인 못 함 · **[제안]**

## 0. 요약

1. RUMAVI는 정보를 **직접 만들지 않는다.** 시행사 판매 자료, 포털·중개사 광고, 공개 기업 정보를 **스크립트로 일괄 적재**하고, 그 위에 **자동 생성된 것으로 보이는 '전문가 분석'**을 얹는다. 사람이 하는 일은 작다.
2. 그래서 RUMAVI 정보를 "활용"하는 올바른 방법은 RUMAVI를 읽는 것이 아니라 **RUMAVI가 가져다 쓴 원천에 정당한 권리로 직접 붙는 것**이다. 원천은 1순위가 시행사, 2순위가 포털 그룹이다.
3. GLI는 이 중 필리핀에서 이미 시행사(RLC) 관계가 있고, 포털 피드를 받을 코드 경로(ADR-0002·0015·0018)도 만들어 두었다. **빠진 것은 기술이 아니라 '무엇을 달라고 할지'의 표준과 공급 계약이다.** 4장에 그 표준(프로젝트 자료 요청서)을 제안한다.
4. RUMAVI 데이터는 **오류가 많다.** 따라서 설령 합법적으로 받을 수 있어도 그대로 믿으면 안 된다. 오히려 GLI에게는 '원천을 직접 받아 출처와 기준일을 붙이고, 빈칸을 현장에서 채운다'는 정반대의 접근이 차별점이 된다.

### 1.3 RUMAVI 스스로 밝힌 정보원 [사실]

- "영문 **공개 채널**로는 확인되지 않는다", "영문 **리스팅**에서 확인되는 주요 프로젝트다", "조사 기준일 현재" — 영어 공개 자료·광고 사이트를 조사 대상으로 삼았다는 자기 진술.

- 이용약관 5A조: 매물은 파트너 중개사·시행사가 공급할 수 있고 소개·성사 수수료를 받을 수 있다.

### 1.4 사진의 출처는 [미확인]

RUMAVI가 사진을 어디서 가져왔는지는 외부에서 **확정하지 못했다.** 확인된 것은 (가) 시행사가 포털에 올린 사진과 RUMAVI 사진의 개수·파일명이 다르다, (나) RUMAVI는 파일명을 지우고 webp로 다시 저장한다는 점뿐이다. 같은 사진인지 가리려면 이미지 역검색이나 시행사 확인이 필요하다. 사람이 몇 장만 대조해 보면 된다.

## 2. 수집 경로 지도 [사실 + 추론]

```
① 시행사 판매 자료 ─ 가격·면적표, 평면도, 사진, 편의시설, 브로슈어  [원천]
        │
② 포털·중개사 광고 ─ realestate.com.kh, DotProperty 등            [재게시자]
        │           (시행사가 직접 올림. 소유권은 등록자에게 남는 구조)
③ 공개 기업 정보 ─ 상장사 공시·회사 소개(RLC: PSE 상장, JG Summit 계열, 1980년 설립)
        │
④ 영어 공개 웹 조사 ─ 자동 생성으로 보이는 분석문 (RUMAVI 자기 진술 ·'조사 기준일')
        │
⑤ RUMAVI 적재 스크립트 ─ 이미지 일괄 업로드(2026-03-12, 2026-06-09 확인)
        │                 + 6개 언어 번역 + 지역·국가별 SEO 페이지
        ▼
   RUMAVI 프로젝트 페이지 → 문의 → 소개·성사 수수료(시행사) 또는 정액 자문(구매자)
```

- ①이 진짜 원천이다. 사진·가격표·소개문은 **시행사의 것**이다.
- ②의 두 포털(realestate.com.kh, DotProperty)은 **같은 그룹(SEA Connect Ventures)** 소속이다. 이 그룹은 태국·인도네시아·필리핀·캄보디아에서 1위, 베트남·말레이시아에도 진출해 있다. (2차: b2b-cambodia.com)
- ③은 공개 정보라서 GLI도 같은 곳에서 직접 얻을 수 있다.
- ④⑤가 RUMAVI가 더한 부분인데, 위 1장의 오류가 이 단계에서 생긴다.

## 3. RUMAVI 정보를 쓸 수 있는가 [사실 + 제안]

| 방법 | 가능 여부 | 근거 |
|---|---|---|
| RUMAVI 페이지를 읽고 GLI 화면·DB에 옮기기 (번역 포함) | **불가** | RUMAVI 약관 12·14조: 서면 승인 없는 복제·재게시·번역·2차 저작물·상업적 이용 금지 |
| RUMAVI 자동 수집 | **불가로 본다** | 같은 조항 + 운영 방해 금지(4조). 법적 판단은 컴플라이언스 검토 |
| realestate.com.kh를 자동 수집해 GLI DB 구축 | **불가** | 해당 약관: 자동 접근·수집, 매물 DB 구축, 번역·2차 저작물, 경쟁 목적 이용 금지. **GLI의 ADR-0002도 같은 원칙**("공개 접근이 집계·재게시 허락을 뜻하지 않는다") |
| 사실 자체(프로젝트명, 시행사, 위치, 준공 연도)를 **원천에서 직접 확인**해 쓰기 | 가능 | RUMAVI의 문장·표현·사진이 아니라 사실만 쓰고, 출처는 원천으로 남김 |
| RUMAVI를 읽고 접촉할 시행사를 고르는 참고로 쓰기 | 통상 가능 | 연구·내부 참고 수준 |
| 서면 제휴·라이선스 | 가능 | 아래 4장 R4 |

**더 중요한 판단** [제안]: RUMAVI 데이터는 오류가 많아서(1장) **받아도 신뢰 자산이 아니다.** 같은 노력을 원천에 쓰는 편이 정확도도 높고 권리도 깨끗하다.

## 4. GLI가 쓸 수 있는 정당한 경로 [제안]

### 4.0 이미 있는 것과 빠진 것

- [사실] 필리핀 원천은 `COUNTRY-SOURCES.md`에 "RLC/Mantawi 파트너 자료 — **미연결**"로 적혀 있고, `DECISIONS` P25는 RLC를 "제공 자료 기준 등록"으로 정해 두었다. 관계는 있고 자료 연결이 없다.
- [사실] 가져오기 코드는 있다. 시행사·포털의 승인형 JSON 피드(ADR-0002), 관리자 수동 업로드(ADR-0015), CSV(ADR-0018). 원본 파일은 해시와 함께 보관하고, 가져온 매물은 운영자 검토 전까지 비공개(`REVIEW_PENDING`)다.
- [사실] 그런데 현재 가져오기 스키마(`LICENSED_JSON_REQUESTED_FIELDS`)는 **개별 매물 중심의 16개 필드**다: 국가·도시·구역·거래·유형·가격·통화·면적·침실·욕실·이미지·제목·요약·출처URL·관측시각 등.
- [추론] RUMAVI가 보여 주는 정보의 중심은 **프로젝트 단위**(세대 구성표, 준공 상태, 권리 유형, 외국인 쿼터, 시행사 이력, 이미지 사용권)다. GLI 스키마에는 이 필드들이 없다. 즉 **받을 준비는 됐지만, 프로젝트 정보를 받을 그릇이 비어 있다.**

### 4.2 프로젝트 자료 요청서 초안 (R1·R2 공통) [제안]

모든 항목에 **"누가·언제 기준으로 말했는가"**를 붙이도록 요청한다. 시행사가 준 값은 GLI에서 **'출처 주장'** 상태로만 올라간다(P-007·핸드오프 원칙).

### 4.3 GLI가 RUMAVI와 달라지는 지점 [제안]

RUMAVI는 같은 원천 자료를 이렇게 보여 준다: "완공됨, 건설 위험 없음".
GLI는 같은 원천을 이렇게 보여 줄 수 있다:

> 가격표 — 시행사 주장 · 2024-03 기준(2년 7개월 미갱신)

## 5. 같은 페이지에서 확인된 RUMAVI의 이해상충 표시 방식 [사실]

[추론] 앞의 두 문장은 자문 상품에 관한 것이고 세 번째는 매물 소개에 관한 것이라 모순은 아니다. 다만 **한 화면에서 '독립'과 '시행사 수수료 가능'이 함께 읽히고, 후자는 문의 단계에서야 나온다.** GLI의 P-007("상업 관계는 검증이 아니다")을 화면에 구현할 때 **시행사 제공 여부를 첫 화면에서 표시**하는 쪽이 RUMAVI보다 강한 방식이다.

## 6. 다음 확인 [제안]

1. **RLC 파일럿** — Radiance Manila Bay 한 프로젝트로 4.2 요청서를 보내고, 받은 값을 RUMAVI 페이지 값과 비교한다(세대수 1,068 vs 1,135, 준공 2019 vs 2021, 쿼터 잔여 등). 오류 표가 곧 'GLI 방식이 더 정확하다'는 증거가 된다. 개발은 거의 필요 없다(기존 수동 업로드 경로).
