# P0-2 검색 결과 화면 방향 결정 (기획자 검토 반영)

작성: 2026-10-07. 기준: 기획자가 결과 화면 시안(현재 vs 목표)을 검토해 남긴 의견.
범위: 사내 비공개 기술 데모. 법률·제휴·사업 논의는 다루지 않는다.
상태: **방향 결정.** 구현 전이며 세부 설계는 아래 "다음 설계 과제"에 남아 있다.

## 1. 확정된 방향

1. **바닥선은 일반 AI 수준의 답.** 몇 초 안에 읽기 시작할 수 있고, 한 덩어리 글이 아니라
   구역(한 줄 결론 / 지역 / 선택지 / 확인할 것 / GLI 확인 후보 / 이어서 묻기)으로 정리해 보여 준다.
   시안의 6개 구역 구성은 기획자가 모두 "좋음"으로 승인했다.
2. **GLI의 몫은 그 위에 얹는 것.** 일반 정보에는 "일반 정보" 표시, GLI가 확인한 후보에는
   "GLI 확인" 표시와 등급·출처 링크, 비교·저장·상담 연결 버튼을 붙인다.
3. **PC 화면을 먼저 확정하고 모바일로 최적화한다.** PC와 모바일은 설계를 따로 해야 할 수 있다.
   (이번 시안의 현재 화면 캡처는 모바일 기준이었다.)
4. **시각 정보 우선.** GLI 확인 후보 카드에는 썸네일을 넣고 텍스트보다 시각 정보를 보기 좋게 표시한다.
5. **썸네일은 일반 검색에서 보이는 미리보기 이미지로 한다.** 일반 AI에서는 링크를 한 번 더 눌러 웹페이지를 열어야
   보이는 대표 이미지를, GLI 서버가 출처 링크 페이지에서 미리 가져와 카드에 채운다. (기획자 결정, 2026-10-07)

## 2. 추가된 핵심 아이디어: 고객 질문이 GLI의 조사 지시가 된다

고객이 검색해서 나온 "일반 정보"(예: 어느 지역, 어떤 유형, 어느 예산대에 관심이 있는가)는
GLI가 앞으로 데이터베이스로 만들어야 할 물건을 알려 주는 중요한 근거다.

- 고객 검색 결과값을 GLI가 보관한다.
- 같은 지역·유형이 반복해서 나오는데 GLI 확인 후보가 없는 항목은 사람(조사 담당)에게 조사를 요청하는 프로세스를 둔다.
- 결과적으로 검색이 쌓일수록 GLI 재고가 고객 수요에 맞게 늘어난다. 일반 AI는 이 순환을 만들 수 없다.

## 3. 다음 설계 과제 (미결정)

| 과제 | 기획자 의견 | 정해야 할 것 |
|---|---|---|
| 버튼(칩) 클릭 동작 | 클릭하면 분기해서 다시 검색 결과를 보여 주거나, 다음 질문에 저장해 두는 설계를 자세히 | 어떤 칩이 즉시 재검색이고 어떤 칩이 "담기"인가, 선택한 조건을 어디에 보여 주고 어떻게 뺄 수 있는가 |
| 수요 기록 | 고객 검색 결과를 보관하고 중복 항목은 조사 요청 | 무엇을 저장하는가(질문 원문 vs 요약된 지역·조건), 몇 번 반복되면 조사 요청인가, 요청을 받는 화면 |
| 썸네일 | 일반 검색의 미리보기 이미지를 미리 가져오기로 결정 | 응답을 막지 않고 나중에 채우는 방식, 같은 링크는 저장해 재사용, 이미지가 없거나 주제와 어긋날 때의 대체 이미지, 가져오기에 실패했을 때의 표시 |
| PC 화면 | 먼저 확정 | PC 결과 화면의 배치(대화와 후보를 나란히 둘지 등) |

## 4. 시안

- 결과 화면 시안 v1(현재 vs 목표, 모바일 기준 캡처): 구역 6개 모두 기획자 승인.
- PC 결과 화면 시안 v2(대화형 답과 GLI 확인 후보를 나란히, 버튼 두 종류의 동작, 내 조건 줄, 조사 요청 화면): 기획자 검토 대기.
  버튼 동작 제안은 "이어서 물어보세요"는 바로 다시 찾기, "먼저 확인하세요"는 다음 질문에 담기이다. 확정 전이다.
