# P0-2 검색 결과 화면 방향 결정 (기획자 검토 반영)

작성: 2026-10-07. 기준: 기획자가 결과 화면 시안(현재 vs 목표)을 검토해 남긴 의견.
범위: 사내 비공개 기술 데모. 법률·제휴·사업 논의는 다루지 않는다.
상태: **방향 결정.** 구현 전이며 세부 설계는 아래 "다음 설계 과제"에 남아 있다.

## 1. 확정된 방향

1. **바닥선은 일반 AI 수준의 답.** 몇 초 안에 읽기 시작할 수 있고, 한 덩어리 글이 아니라
   구역(한 줄 결론 / 지역 / 선택지 / 확인할 것 / GLI 확인 후보 / 이어서 묻기)으로 정리해 보여 준다.
   시안의 6개 구역 구성은 기획자가 모두 "좋음"으로 승인했다.
2. **GLI의 몫은 그 위에 얹는 것.** 일반 정보에는 "일반 정보" 표시, GLI가 확인한 후보에는
   "GLI 확인" 표시와 등급·출처 링크, 비교·저장·상담 연결 버튼을 붙인다.
3. **PC 화면을 먼저 확정하고 모바일로 최적화한다.** PC와 모바일은 설계를 따로 해야 할 수 있다.
   (이번 시안의 현재 화면 캡처는 모바일 기준이었다.)
4. **시각 정보 우선.** GLI 확인 후보 카드에는 썸네일을 넣고 텍스트보다 시각 정보를 보기 좋게 표시한다.
5. **썸네일은 출처에 따라 세 가지로 나눈다.** (기획자 결정, 2026-10-07, 앞선 "미리보기 이미지를 미리 가져온다"를 대체)
   - GLI가 확인한 후보: GLI가 미리 입수해 DB에 둔 이미지를 쓴다.
   - 외부 사이트가 출처인 후보: 그 사이트에서 이미지를 가져온다.
   - 일반적인 도시 정보처럼 실제 건물·방이 없는 경우: 생성형 AI로 도시를 시각화한 대표 이미지를 쓴다. 정확한 건물 내부나 외형을
     보여 주는 이미지가 아니라 도시 분위기를 보여 주는 대표 이미지이며, 그렇게 표시한다.
6. **버튼은 사용자가 따로 배워야 하는 UI이면 안 된다.** "다음 질문과 함께 전달돼요" 같은 설명이 필요한 구조는 피한다.
   "먼저 확인하세요"에 어떤 정보를 띄울지는 아직 정해지지 않았다.
7. **"내 조건" 줄은 방향이 좋다.** 무엇을 여기에 보여 줄지를 정하는 것이 관건이다.
8. **조사 요청은 일반 사용자의 일이 아니라 시스템과 사람의 일이다.** 사용자 화면에 조사 요청 버튼을 두지 않는다.
   각 사용자의 검색 기록과 답변 기록을 보관해 계속 최적화한다.
9. **기존 UI의 큰 변경은 최소화한다.** 이번 시안은 구성 시안이며 그대로 적용하기는 어렵다. 이미지 시안은 Claude Design과
   상의해 기존 UI를 크게 바꾸지 않는 방안으로 뽑은 뒤에 판단한다.

## 2. 추가된 핵심 아이디어: 고객 질문이 GLI의 조사 지시가 된다

고객이 검색해서 나온 "일반 정보"(예: 어느 지역, 어떤 유형, 어느 예산대에 관심이 있는가)는
GLI가 앞으로 데이터베이스로 만들어야 할 물건을 알려 주는 중요한 근거다.

- 고객 검색 결과값을 GLI가 보관한다.
- 같은 지역·유형이 반복해서 나오는데 GLI 확인 후보가 없는 항목은 시스템이 집계해 사람(조사 담당)의 조사 대상으로 올린다. 이 과정은 사용자 화면에 드러나지 않는다.
- 결과적으로 검색이 쌓일수록 GLI 재고가 고객 수요에 맞게 늘어난다. 일반 AI는 이 순환을 만들 수 없다.

## 3. 다음 설계 과제 (미결정)

| 과제 | 기획자 의견 | 정해야 할 것 |
|---|---|---|
| 버튼 동작 | 의도는 좋으나 배워야 하는 UI는 안 됨 | 버튼 종류를 하나로 단순화할지, "먼저 확인하세요"에 무엇을 띄울지 |
| 내 조건 줄 | 방향 좋음, 무엇을 보여 줄지가 관건 | 시스템이 이해해 검색에 쓴 조건(국가·지역·예산·목적·거래 유형 등)만 보여 주는 안을 검토 |
| 썸네일 | 출처별 3가지 방식 확정 | 도시 대표 이미지를 어떻게 만들고 보관할지, 표시 문구, 이미지가 없을 때의 대체 |
| 검색·답변 기록 | 보관해서 계속 최적화 | 무엇을 남길지(질문, 이해한 조건, 답변, 보여 준 후보, 누른 것), 수요 집계와 조사 대상 목록 화면 |
| 화면 적용 | 기존 UI 변경 최소화, Claude Design과 상의 | PC 결과 화면의 이미지 시안, 기존 UI에 얹는 방법 |

## 4. 시안

- 결과 화면 시안 v1(현재 vs 목표, 모바일 기준 캡처): 구역 6개 모두 기획자 승인.
- PC 결과 화면 시안 v2(대화형 답과 GLI 확인 후보를 나란히, 버튼 두 종류의 동작, 내 조건 줄, 조사 요청 화면): 기획자 검토 완료.
  구성은 좋으나 버튼 설명 문구와 사용자용 조사 요청은 수정 대상이며, 이미지 시안으로 판단하기 위해 Claude Design 단계로 넘긴다.

## 5. 새 포크 시안 (기존 정책과 분리한 탐색)

기존 GLI 디자인 정책과 충돌하지 않도록, 이전 개발과 무관한 별도 탐색으로 PC 결과 화면을 그림 시안으로 그렸다
(디자인 캔버스, 2026-10-07). 기존 `design-handoff` 규칙과 GLI-052 지시서는 참조하지도 변경하지도 않았다.

- 시안 4장: A(대화와 후보를 나란히), B(한 줄기로 읽는 안), A의 처리 중, A의 후보가 없을 때.
- **기획자 선택: A안이 더 보기 편하다.** (2026-10-07)
- 이미지는 대체 일러스트이며 실제 이미지 스타일은 이미지 생성 도구로 따로 뽑아야 한다.
- 이 선택은 새 포크 탐색 안의 선택이며, 기존 UI에 어떻게 적용할지는 아직 정해지지 않았다.
