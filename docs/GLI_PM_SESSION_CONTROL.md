# GLI 총괄 PM·공동연구·세션 통합 운영

정리일: 2026-10-14
관리 저장소: `kenwac74-svg/GLI`
문서 성격: 사용자 역할 지정의 기록 + PM 운영 준비안 + 확인된 인계 현황
범위: 사업·상품기획, 최상위 UX 연구, 세션 간 인수인계. 앱 코드·배포·PR 병합은 이번 작업 범위가 아니다.

## 1. 이번 사용자 지시와 권한

사용자는 GLI 데모 개발·개선 중 **근본적인 사용자 경험 개선과 일반 LLM보다 더 효용성 있는 가치 제공**을 현재 GPT와 논의할 최상위 연구과제로 지정했다. 여러 세션의 역할을 정의하고, 정리할 세션을 정리하며, 현재 사업기획 대화의 GPT를 **총괄 사업기획자이자 PM**으로 두도록 지시했다.

확정된 것은 총괄 역할, 최상위 연구과제, 세션 정리 방향이다. 아래 역할별 운영·인계 방식은 이를 수행하기 위한 PM 준비안이다. 실제 세션에 지시가 전달됐거나 세션이 보관됐다는 뜻은 아니다.

- 최종 사업·상품 결정과 중요 변경 승인은 사용자에게 있다.
- GPT PM은 문제 정의, 우선순위, 과제 배분안, 기존 결정 대조, 결과 검토, 미해결 항목 관리와 문서 기록을 담당한다.
- 승인된 범위의 세부 정리까지 사용자에게 다시 결정시키지 않는다. 기존 합의를 바꾸는 선택만 쟁점과 대안을 정리해 올린다.
- 연구 담당자는 기존 설계와 PM의 가설에 반대할 수 있다. 결론과 기록은 통합하되 사고방식까지 하나로 묶지 않는다.
- PM 지정이나 인계 문서 커밋은 앱 코드 수정, 비용 발생, 계약, 병합, 배포의 포괄 승인이 아니다.

기존 `GLI_MASTER_BUSINESS_HANDOFF.md` §0, §1.1의 최상위 제품 원칙과 GPT–Claude 3회 반복 중단 규칙을 그대로 유지한다. 과거의 사업기획 전용 역할은 이번 사용자 지시로 총괄 PM까지 확장한다. 기존 제품 정책을 임의로 다시 쓰지는 않는다.

## 5. 최상위 연구과제 R-UX-01

### 질문

**GLI가 일반 LLM 수준의 즉각적이고 실질적인 도움을 제공하면서, 사용자가 GLI를 선택하고 다시 방문하고 비용을 지불할 만큼 나은 경험을 어떤 방식으로 제공할 것인가?**

이 과제는 단순 검색 속도 개선, 결과화면 미화, 시맨틱 검색엔진 도입 과제가 아니다. 기술은 고객 경험과 가치가 정의된 뒤 선택한다. 현지 검증·등급·출처·저장 기능이 있다는 것만으로 독점적 가치가 입증되었다고 보지 않는다.

담당: GPT PM + Claude 독립 공동연구. 사업·제품의 큰 선택은 사용자 승인. 이 문서를 기록했다고 Claude가 새 연구를 시작한 것은 아니다.

### 이미 합의된 출발점

일반 AI 수준의 답을 먼저 제공하고 GLI 확인 정보를 구분하여 얹는다. 외국어 원문을 고객이 직접 해독하는 부담을 줄인다. 데이터 부족을 답변 중단으로 바꾸지 않는다. 질문이 바뀌면 내용과 후보가 함께 바뀐다. 조사할 항목을 설계하는 것은 고객이 아니라 시스템과 운영자의 일이다.

Claude의 결과화면 기록에는 PC 먼저, 출처별 썸네일 세 갈래, 설명을 학습할 필요 없는 버튼, A안 선택, 주제 전환 시 이전 탐색 접기 등이 있다. A안 선택은 포크 시안 범위이며 기존 UI로의 전면 적용 승인은 아니다.

### 연구가 답해야 할 것

1. 첫 질문부터 후보 이해·비교·관심 좁히기까지 어떤 고객 장면을 만들 것인가.
2. 일반 AI와 같은 답 이후 GLI가 실제로 대신 끝내는 일이 무엇이며, 고객이 그 차이를 어디서 체감하는가.
3. 정보를 더 알아오는 과정과 결과 반환이 어떻게 재방문으로 이어지는가.
4. 무료 탐색, 기존 보고서 열람, 새 고비용 업무의 경계를 사용자가 쉽게 이해할 수 있는가.
5. 현재 Web2의 직접 매수·임대 관심층과 미래 소액투자 관심층에 각각 줄 가치가 무엇인가. Web3를 현재 이용가치의 대체 설명으로 쓰지 않는다.
6. 위 경험을 공급하는 비용과 유료전환이 성립하는가. 가격·전환율·손익 기준은 아직 수치로 확정하지 않는다.

### 연구 방식과 산출물

기존 승인 시안과 고객 장면을 출발점으로 삼는다. 새 점수표부터 만들거나 같은 문제를 또 설명하는 데 시간을 쓰지 않는다. 실제로 써보거나 눌러볼 수 있는 최소 시안과 관찰을 우선하고, 측정은 차이가 생겼는지 확인하는 보조 수단으로 쓴다.

산출물은 고객 장면, 일반 AI만 썼을 때와의 차이, 기존 합의, 새로 필요한 선택, 시안·관찰 근거, 가장 작은 검증, 비용·운영 부담을 포함한다. 결과물의 생성, 사용자 사용성 검증, 사업성 입증은 서로 다른 단계다.

특허와 Web3는 기존 미확정 연구 목록에 남긴다. 최상위 UX 과제를 피해 새로운 장기 구현을 시작하는 이유로 쓰지 않는다. 이미 존재하는 법률상 기한·외부 약속이 있다면 누락하지 말고 별도로 사용자에게 보고한다.

## 7. 인계와 세션 정리 절차

### 한 번의 인계에 필요한 것

- 사용자 문제와 세션의 담당 범위.
- 확정된 결정과 승인 근거, 적용 범위.
- 시도·실패·폐기안 및 중요한 판단 근거. 숨은 사고과정이 아니라 근거 중심의 결정 요약.
- 남은 일, 충돌, 막힌 이유와 다음 담당.
- 저장소·브랜치·기준 커밋·PR·파일 경로. 비공개 링크만 있는 시안의 접근 가능 여부.
- 구현/테스트/병합/배포/실사용 검증을 각각 구분한 상태.
- 이번 PM 기준과 다른 내용만 요약. Git에 이미 있는 내용을 대화 전체로 다시 복사하지 않음.
- 같은 미해결 문제에 국소 코드 처방을 반복한 횟수. 미확인이면 임의로 0으로 쓰지 않음.

### 정리 판정

`인계 필요 → 원문/근거 회수 → PM 대조 → 중복·충돌·남은 일 배정 → 정리 가능 → 사용자가 보관한 사실 확인`

필수 근거를 못 읽었거나, 미커밋 작업이 남았거나, 다른 담당이 이어갈 다음 행동을 모르면 정리 완료로 표시하지 않는다. 원문을 회수하지 못했다고 없던 결정으로 간주하지도 않는다.

세션 정리는 기록 보관을 뜻한다. 채팅·브랜치·커밋·시안을 삭제하거나 PR을 닫는 작업은 포함하지 않는다. 이 준비 작업에서 어느 세션도 자동 폐쇄하지 않았다.

## 8. 착수·검토·권한 경계

- 각 역할은 시작할 때 본 문서, 마스터 §0/§1.1, 자기 과제와 직접 관련된 최신 인계만 읽는다. 불필요하게 전체 저장소와 과거 대화를 매번 읽지 않는다.
- 문제를 다시 제기할 때 먼저 `이미 합의 / 적용 대기 / 검증 대기 / 실제 미정 / 원문 미회수` 중 어디인지 밝힌다.
- 연구 → 시안 → 사용자 방향 확인 → 개발팀 전달 제안 → 승인된 구현 → 관련 검증 → 별도 병합·배포 확인 → 사용자 효과 확인을 구분한다.
- 큰 틀 승인 후 사소한 다듬기마다 다시 묻지 않는다. 반대로 UI 전면 적용·상품 가격·사업 범위 변경은 작은 수정처럼 처리하지 않는다.
- 동일 미해결 문제에 코드 변경 수준 답변을 세 번 반복하면 마스터 §1.1에 따라 멈추고 Git에 인계하여 Claude 독립 검토를 받는다. PM이 총괄한다는 이유로 이 절차를 생략하지 않는다.
- GPT와 Claude의 의견이 달라도 실패가 아니다. 공통 근거, 이견, 반증 방법과 사용자 결정이 필요한 항목을 기록한다.
- 다른 세션으로의 실제 전달, Git 커밋, 상대의 수신 확인, 검토 완료를 각각 구분한다. 연결되지 않은 자동 실행이나 백그라운드 감시가 작동한다고 말하지 않는다.

## 9. 기존 세션에 전달할 공통 인계 요청문

> GLI 총괄 사업기획·PM은 현재 GPT 사업기획 대화로 통합한다. `kenwac74-svg/GLI`의 `docs/GLI_PM_SESSION_CONTROL.md`와 마스터 §0/§1.1을 읽고, 이 세션의 역할과 남은 작업을 확인하라. 새 작업을 확장하지 말고, 확정 결정·미해결 항목·시행착오·다음 행동·브랜치/커밋/PR을 기존 인계 문서에 정리하라. 이미 Git에 있는 내용은 경로로 참조하고 이 세션에만 남은 차이분을 우선 보존하라. 공개 저장소에 올릴 수 없는 내용은 별도로 표시하라. 코드·병합·배포·원본 삭제 없이 인계 경로와 남은 일을 보고하라. 전체 원문을 확인하지 않았거나 테스트하지 않은 항목을 완료로 쓰지 마라.

이 요청문은 준비된 전달용 문안이다. 모든 과거 세션에 전송했다는 뜻이 아니다.

## 10. 이번 준비 작업의 확인 범위와 보안
